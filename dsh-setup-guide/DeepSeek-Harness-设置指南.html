一、DSH 是什么

DeepSeek Harness（简称 dsh）是 DeepSeek AI 于 2026 年 8 月开源的 Agent Harness（智能体运行框架）。命令行名为 dsh，自带 Web 界面，底层由 Cordis 插件框架驱动。

它的核心设计哲学是 「一切皆插件」：官方只提供一个基础外壳，模型适配、文件编辑、命令执行、任务看板、知识库等能力全部以插件形式挂载，可自由替换。因此「设置 dsh」本质上就是三件事——装好运行时、接上模型、挂上插件。

三个必须先建立的概念

  • DSH_HOME：配置根目录，默认 ~/.dsh（Windows 为 C:\Users\<你>\.dsh），可用环境变量 DSH_HOME 覆盖。所有配置、凭据、插件、会话都在这。
  • Profile：一套独立的插件组合 + 依赖树。官方内置 web（浏览器界面）和 desktop（桌面客户端）两套，互不干扰。
  • 模型适配器：@deepseek-ai/dsh-llm-deepseek 只管 DeepSeek 官方 API；@deepseek-ai/dsh-llm-pi-ai 承载其他所有提供方（Anthropic / OpenAI / Azure / Ollama / 自建网关…）。两者可同时挂载。

二、安装与启动

前置环境

项目要求校验
Node.js^22.19.0 || >=24.0.0（硬性约束，写在 package.json 的 engines 里）node -v
包管理器npm（npx 方式）；源码构建需 pnpmnpm -v
网络国内建议先切镜像npm config set registry https://registry.npmmirror.com

Node 版本不够会直接启动报错（旧版 Node 16/18 一律不行）。用 nvm-windows 可多版本共存切换。

方式 A：npx 一键启动 最快

# 首次执行会自动拉取 dsh 依赖
npx @deepseek-ai/dsh web

# 启动成功后浏览器访问
http://127.0.0.1:3080

换端口加 --port。此方式包缓存在 npx 缓存里，升级/清理不够干净，适合快速试用。

方式 B：独立目录本地安装 Windows 推荐

不污染全局 npm（全局默认堆在 C 盘），在专用目录本地安装，删除即卸载。

# 1) 建目录并进入
mkdir D:\dsh-bin && cd /d D:\dsh-bin

# 2) 本地安装（关键：--allow-scripts 后的包名必须原样带全）
npm install @deepseek-ai/dsh --allow-scripts=...

# 3) 把 D:\dsh-bin\node_modules\.bin 加进用户环境变量 Path，重开终端
where dsh        # 应只返回一条，指向 D:\dsh-bin\node_modules\.bin\dsh
dsh --version

两个高频坑

  • 漏掉 --allow-scripts：安装看着成功，但 dsh 的终端与子进程能力会缺失，启动后大量功能不可用。必须重装并带全包名。
  • 满屏红字不是失败：安装过程会刷大量 npm warn / cleanup failed，只要最后一行有 added ... packages 就是成功的。

方式 C：源码构建 可改源码

git clone https://github.com/deepseek-ai/deepseek-harness.git
cd deepseek-harness
npm install -g pnpm
pnpm install
pnpm run build      # 不可省略，跳过会导致 Web 界面异常
pnpm dsh web        # 源码模式下命令前都要加 pnpm

国内克隆慢可在 git 链接前拼 https://gh-proxy.com/ 代理。

三、DSH_HOME 目录结构

理解这个目录 = 理解 dsh 的全部设置入口。以本机 C:\Users\Admin\.dsh 实测为例：

路径作用要不要手改
settings.yaml配置真源。模型 provider、路由、兼容开关都写在这（首次可能不存在，由界面操作自动生成）✅ 手动编辑（进阶）
.credentials.yaml凭据存储。Web UI 保存的 API Key / 登录 token 落在这里，只写不回显明文❌ 不要手改
profiles/web/Web 端 profile：package.json（插件依赖 + bundles 清单）、cordis.yml、cordis.patch.yml、node_modules/⚠️ 只改 cordis.patch.yml
profiles/desktop/桌面端 profile，结构同上，插件集合独立⚠️ 同上
.agent-presets/Agent 预设（标准 / Code / 极简 / 创作 + 自定义），含 preset.yml、prompt.md✅ 可放自定义预设
sessions/会话日志❌
skills/ · kb/ · knowledge-base/技能、知识库数据视插件而定
dsh-runtimes/dsh 自带的 node / pnpm / python 运行时❌
storages/插件持久化存储（如 better-sqlite3 数据库）❌

关于 cordis.yml —— 别改错文件

每个 profile 下的 cordis.yml 内容是一个空数组（注释里写明了原因）：插件树由 package.json 的 dsh.profile.bundles → cordis.patch.yml → --patch 覆盖层逐层叠加组合而成。

所以要覆盖配置、禁用某个插件、插入新条目，都写在 cordis.patch.yml 里，而不是 cordis.yml。例如本机 web profile 的 patch 文件：

- id: ui-theme
  name: "@deepseek-ai/dsh-client-ui-theme"
  config:
    preference: dark        # 强制深色主题
- id: skills-management
  disabled: true            # 禁用某个插件

四、Profile 机制

Profile 让「Web 端」和「桌面端」各用一套插件、各存一份依赖，互不污染。管理命令统一带 --profile 参数：

dsh plugin --profile web list       # 列出 web profile 已装插件
dsh plugin --profile desktop list   # 列出 desktop profile 已装插件

每个 profile 的 package.json 里有两块关键内容：dependencies（装了哪些插件包）和 dsh.profile.bundles（哪些插件实际被挂载进运行时）。装了但没进 bundles 的插件不会生效。

五、模型接入（核心设置）

dsh 不强制绑定 DeepSeek 自家模型，原生支持 OpenAI 兼容协议。接入分三条路径，由易到难：

路径 1：Web UI 添加「目录提供方」 新手首选

Anthropic、OpenAI、Google、Azure、Bedrock、Mistral、Groq、xAI、OpenRouter、Ollama 等 15+ 提供方已内置于 pi-ai 目录，端点/协议/模型列表都由目录提供，只需填 Key。

启动 dsh→ 设置 → 模型→ 添加提供方→ 选目标 + 填 API Key→ 保存，回会话页选中模型

例外：Bedrock / Vertex / Azure / Codex 走原生认证，只填 Key 不够（需 AWS 凭据+区域、ADC 项目、api-version、OAuth 登录流程）。

路径 2：Web UI 添加「自定义提供方」

公司网关、国内多模型平台、自建 vLLM / Ollama 都走这里。必填五项：

字段填什么注意
Provider ID小写连字符标识，如 my-gateway创建后永久不可改，会话记录/凭据引用都绑定它
显示名称选择器里的标签可随时改
基础 URL网关地址，如 https://xxx/v1可随时改
API 协议openai-completions / openai-responses / anthropic-messages源码只有这三种，每条路由只能选一种
凭据API Key存入凭据存储
模型至少一个模型 ID可点「获取可用模型」自动拉 GET /models，401 说明 Key 错

路径 3：直接写 settings.yaml 完整真源

Web UI 只是 settings.yaml 的子集。表单里没有的字段（图片模态、兼容开关、推理等级重命名）必须手写文件才能配。

两种写法的差别（很关键，别用错）：

写法效果适用
models: [...]整体替换路由的模型目录，未列出的模型消失把路由收窄到两三个模型，或加目录里没有的新模型
modelOverrides: {id:{...}}只改点名的模型，其余原样保留「修正一个，保留其余三十七个」

六、settings.yaml 全字段参考

模型配置的完整真源在 $DSH_HOME/settings.yaml 的 llm-pi-ai 分节。一条自定义路由的完整写法：

llm-pi-ai:
  providers:
    my-gateway:
      displayName: My Gateway
      apiKeyEnv: GATEWAY_API_KEY        # 引用环境变量，绝不写明文
      api: openai-completions
      baseURL: https://gateway.example/v1
      defaultContextWindow: 262144
      defaultMaxTokens: 32768
      compat:
        supportsDeveloperRole: false     # 系统提示不用 developer 角色
        maxTokensField: max_tokens          # 输出上限字段名
      models:
        - id: chat-model
          name: Chat Model
          contextWindow: 131072
        - id: vision-model
          input: [text, image]              # 显式声明视觉能力
        - id: reasoner
          compat:
            thinkingFormat: deepseek
          reasoningEfforts:
            off: low
            high: high

字段速查

字段默认值含义
apiKeyEnv无凭据引用（环境变量名）；省略则交给 pi-ai 环境发现
api目录协议协议格式，目录外路由必填
baseURL目录端点路由上所有模型共用
models已安装目录整体替换模型目录
modelOverrides无只改个别模型；不能与 models 并存
compat目录检测请求形状兼容开关
defaultContextWindow262144未声明容量模型回退值
defaultMaxTokens32768未声明输出上限回退值
defaultInput[text]未声明模态回退值
headers无附加请求头
retryPolicynormal，5 次重试策略

改完不用重启

配置文件按操作重新读取，全部在下一个请求生效。写错的分节会在写入处被拒绝并保留上一个有效值。注意：插件的增删需要重启，模型配置不需要。

网关拒绝请求？先加这两行

Key 和 URL 都对但请求全被拒，几乎都是「请求形状」问题——pi-ai 对认不出的地址一律按 OpenAI 本身处理，而多数兼容网关会拒绝 OpenAI 接受的某样东西：

compat:
  supportsDeveloperRole: false    # 大多数国产网关要设 false
  maxTokensField: max_tokens      # 只认 max_tokens 的服务端

其他常用开关：supportsReasoningEffort、thinkingFormat、chatTemplateKwargs、supportsUsageInStreaming、requiresToolResultName、cacheControlFormat。三条硬规则：开关归属协议（用错协议会被拒）、写了就要给值（冒号后留空会被拒）、模型级逐字段胜出路由级。

接入本地模型（Ollama / vLLM）

local-vllm:
  apiKeyEnv: LOCAL_PLACEHOLDER_KEY   # 无密钥服务也要给占位值
  api: openai-completions
  baseURL: http://127.0.0.1:8000/v1
  defaultContextWindow: 32768        # 本地小模型务必改小！
  compat:
    supportsDeveloperRole: false
    maxTokensField: max_tokens
  models:
    - id: <本地模型名>
      reasoningEfforts: false          # 非推理模型显式关掉

Ollama 在 pi-ai 目录内，可直接当目录提供方添加；vLLM 等自建服务按上面手工声明。无密钥服务需要占位凭据，否则 pi-ai 的 OpenAI 兼容实现会报错。

复用官方路由接第三方（有前提）

# 仅当第三方模型 ID 与 DeepSeek 官方命名完全一致时可用
export DEEPSEEK_API_KEY=sk-你的密钥
export DEEPSEEK_BASE_URL=https://服务商域名/v1
npx @deepseek-ai/dsh web

否则会报 UNKNOWN_MODEL，请改用路径 1/2/3。

七、插件管理

dsh 的功能扩展全靠插件。装插件 = 往 profile 里加依赖 + 重启。

# 从 npm 装
dsh plugin --profile web add <npm包名>

# 从 GitHub 装
dsh plugin --profile web add git+https://github.com/<作者>/<仓库>.git

# 从 tarball / 发布包装
dsh plugin --profile web add https://.../dsh-xxx-skin-0.1.4.tgz

# 查看已装
dsh plugin --profile web list

插件三坑

  • 必须重启 dsh web 并刷新页面才生效。
  • 包名含 # 时要用双引号包裹（如 "github:owner/repo#packages/xxx"），否则被 shell 截断。
  • 插件启动失败多半是上次异常退出留下的 .lock 锁文件，删掉 %USERPROFILE%\.dsh\**\*.lock 再启动。

官方插件市场：dshmarket.com（4000+ 插件），站内可查安装命令；对应插件 dshmarket 装上后可直接在界面内浏览安装。

八、Agent 预设与技能

~/.dsh/.agent-presets/ 存放 Agent 预设。官方内置四套：标准模式 / Code 模式 / 极简模式 / 创作模式。每个预设目录含 preset.yml（元数据）和 prompt.md（系统提示）。

Agent 预设类插件的安装方式和普通 Web 插件不同：要把插件目录完整复制到 %USERPROFILE%\.dsh\.agent-presets\，重启后生效——不能用 dsh plugin add。

主题已在 cordis.patch.yml 里强制 dark
Agent 预设custom + expert-team

给你的三条建议

  1. 想接第三方 / 本地模型：现在没有 settings.yaml，最省事的是在 Web UI「设置 → 模型」加自定义提供方；要配视觉模态或兼容开关，再手动建 ~/.dsh/settings.yaml 写 llm-pi-ai 分节。
  2. web 和 desktop 插件不同步：两套 profile 各自独立。如果桌面端缺 dsh-library、dsh-knowledge-base 等，需要在 desktop profile 下单独装一遍。
  3. 保持版本一致：where dsh 若返回多条，说明 npx 缓存里还有旧副本，清掉避免版本混乱。
