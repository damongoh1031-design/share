# ChatGPT 记忆 / IM 消息 / 定时发送消息

## TL;DR

| 问题 | 答案 |
|---|---|
| 有记忆 / 长期记忆吗？ | ✅ **有，而且比多数人以为的强**：改进版记忆 + 引用聊天记录 + 来源可追溯 + **仅限项目的记忆** |
| 能通过 MCP / 应用发 IM 消息吗？ | ⚠️ **部分可以**。Slack 官方应用具备 `chat:write` 等授权范围；官方"能力清单"明示的是加入频道 / 建提醒 / 传文件 / 改资料；自定义 MCP 服务器可做完整写入（限 Business·Enterprise·Edu） |
| 能定时发送消息吗？ | ✅ **能，但不是无人值守机器人**：写操作**可能需要批准 → 任务暂停**等你审核 |

---

## 1. 记忆 / 长期记忆（官方）

**入口**：设置 → **个性化** → **记忆**。

### 1.1 记忆能引用哪些来源

- 以往聊天
- 已保存的记忆
- 自定义指令
- **资料库中的文件**
- **来自已连接应用（如 Gmail）的内容**

→ 注意最后两条：**记忆和知识库是打通的**。挂了 Drive / Gmail 之后，记忆可引用其中的内容。

### 1.2 两套记忆体验（可切换）

| | 改进版记忆 | 旧版已保存记忆 |
|---|---|---|
| 形态 | 持续更新的**范围更广的上下文摘要** | 明确的**单项记忆列表** |
| 切换 | 设置 → 个性化 → 记忆 → 「试用改进版记忆」 | 同上 → 「已保存的记忆」 |
| 附带能力 | 摘要编辑、来源面板、优先级、版本历史（视套餐） | 搜索、排序 |

### 1.3 几个关键控制项

| 控制项 | 含义 |
|---|---|
| **记忆**（总开关） | 关掉**不删除**以往聊天；日后重开可能据聊天记录重新生成记忆 |
| **引用已保存的记忆** | 关掉会**同时**关掉「引用聊天记录」 |
| **引用聊天记录** | 开启后可用以往对话做个性化。**关掉后，从聊天记录记住的信息将在 30 天内从 OpenAI 系统删除**（原始聊天仍保留，除非你自己删） |
| **记忆摘要** | 概览，**不保证包含全部**细节；可编辑、可「不再提及此信息」、可「删除并关闭记忆」 |
| **来源（Sources）** | 回复下方可能显示，用来查是哪条信息影响了个性化；分享链接时**不含**来源 |
| **仅限项目的记忆** | 把记忆上下文限制在特定项目内：只能引用同项目内其他对话，项目内外互相不可见 |

- **已保存的记忆与聊天记录分开存储**：删聊天**不会**自动删已保存的记忆。
- **通过聊天记录引用的信息没有单独的存储上限**。
- **临时聊天**：开始前可选「非个性化」；临时聊天**不创建也不更新记忆**；保存后会转成普通聊天并遵循账号的个性化设置。
- 受监管工作空间（Enterprise / Healthcare）**改进版记忆默认关闭**，需管理员开放；不在 BAA 范围内。
- 隐私：个人账号开启「为所有人改进模型」时，**聊天内容与记住的信息可能被用于训练**；Business / Enterprise / Edu / Healthcare 默认不训练。

## 2. IM 消息（Slack 应用 / MCP）

### 2.1 Slack 官方应用

| 项 | 说明 |
|---|---|
| 类型 | **app with search and actions**（既能搜也能动手） |
| 可用位置 | **Chat、deep research、agent mode**（官方清单未列 Work；Work 侧走"事件触发定时任务"链路） |
| 能读取 | 你有权限访问的 Slack 会话、thread、频道、DM |
| 能执行 | 搜索/总结/按关键词或语义搜索；**在工作区管理员启用后，代表用户执行 Slack 动作**：加入频道、**创建提醒**、上传文件、更新 Slack 个人资料 |
| 请求的权限范围 | 含 **`chat:write`**（发消息）、`files:write`、`reminders:write`、`im:write`、`mpim:write`、`canvases:write`、多组 `search:read.*` 等 |
| 套餐 | 需要**付费 ChatGPT 计划**（Slack 侧不需要付费） |
| 限制 | 一次只能连**一个** Slack 工作区；deep research / Pro 模型 / agent mode 可能**耗尽每用户 Slack API 配额**；需管理员批准 scope 时，Slack 管理员可能要先批准或重装应用 |

> ⚠️ **注意口径差异**：权限范围里有 `chat:write`，但官方"能做什么"清单**没有逐条列出"发送消息"**，明示的是加入频道 / 创建提醒 / 上传文件 / 更新资料。→ **能发消息是合理推断，但未获官方逐条确认**。

### 2.2 自定义 MCP 服务器（要做完整写入用这条）

- **完整 MCP（含写入/修改）**：仅 **Business / Enterprise / Edu**，且**仅网页版**；**不需要开发者模式**。
- **Pro**：只能连**只读/抓取**权限的自定义 MCP 服务器。
- 路径：`Plugins → + → Add custom MCP server` → 填 HTTPS 端点或 Secure MCP Tunnel → 配认证 → 勾选风险确认 → Create as a plugin。
- 写操作**可能要求确认**；部分高风险动作**直接阻断**。
- MCP 服务器变更**不自动更新**，用冻结快照，需管理员 Refresh 后重新发布。

### 2.3 另一种玩法：在 Slack 里 @ChatGPT

`@ChatGPT in Slack / Microsoft Teams` 是**独立功能**，和"把 Slack 当作 ChatGPT 的连接源"不是一回事。要的是组织助理，走这条。

## 3. 定时发送消息

### 3.1 三种触发

| 触发方式 | 说明 |
|---|---|
| **按时间** | 一次性 / 周期性；付费档最高**每小时 1 次**并可指定精确时间 |
| **事件触发（webhook）** | **在 Work 模式中运行**；响应 **Gmail 新邮件 / Slack 频道新消息 / GitHub PR 活动** |
| **监控类** | 检查变化，有相关更新才通知；满足结束条件即停 |

### 3.2 关键限制：写操作可能被拦下

> 官方原文：*"发送消息或更改外部数据的操作可能需要批准。如果需要批准，任务将暂停，直至你完成审核。"*

所以**"定时无人值守往群里发消息"是不成立的**——除非该动作落在你已授予的权限内且不触发审批。

### 3.3 Slack 触发任务的硬条件

1. 先在 `设置 → 应用/插件` 连接 Slack
2. **在每个要监控的频道里加 `@ChatGPT`**（公开和私有频道都要）
3. 打开 **Work** 描述事件与要执行的动作
4. 检查 **Trigger / Condition / Prompt** 三项

**不触发**的情况：**DM、表情回应、消息编辑、消息删除**。只有应用**已加入的频道**的消息才触发。

### 3.4 限额

| 项 | 值 |
|---|---|
| 活动任务上限 | Free/Go 3｜Plus 5｜Business/Edu 10｜Pro/Enterprise 15 |
| 频率 | Free 每天 ≤1 次；付费最高每小时 1 次 |
| 事件触发合计 | **≤30 次/小时、≤720 次/天** |
| 不支持 | Free、Go、FedRAMP 不能创建事件触发任务；定时任务不支持语音聊天与 GPT |
| 管理员 | Enterprise / Edu / Healthcare 需管理员先开「允许事件触发的定时任务」 |
| 桌面 App | 可显示已有事件触发任务，但**创建/编辑触发条件要用网页版** |

### 3.5 分享任务

可分享任务链接（含标题、指令、执行计划、原始时区快照）；**不含**创建者姓名、聊天记录、历史结果、记忆、自定义指令、附件、已连接应用数据或凭据。接收者用自己的账号与权限运行独立副本。

## 4. 能力矩阵

| 能力 | Chat | Work | 备注 |
|---|---|---|---|
| 长期记忆 | ✅ | ✅ | 记忆来源含资料库文件与已连接应用 |
| 仅限项目的记忆 | ✅ | ✅ | 隔离项目上下文 |
| 读 IM（Slack） | ✅ | 事件触发链路 | 需付费 ChatGPT 计划 |

| 事件触发 | ❌ | ✅ | 仅 Gmail / Slack / GitHub |

## 可复用操作

**A. 开启并检查记忆**
`设置 → 个性化 → 记忆` → 打开「记忆」「引用已保存的记忆」「引用聊天记录」→ 查看「记忆摘要」→ 逐条纠正/删除 → 需要隔离时用项目的**仅限项目的记忆**

**B. 连接 Slack**
`设置 → 插件/应用 → Slack → Connect` → 完成 OAuth → 只能连一个工作区
管理员侧：管理控制台 → 工作区 → **插件** → 打开含 Slack 的插件 → 审 **Actions** → 禁用不想批准的 scope

**C. 建"Slack 有新消息就处理"的任务**
1. 连接 Slack
2. 在目标频道加 `@ChatGPT`
3. 打开 **Work** 描述事件与动作
4. 审 **Trigger / Condition / Prompt**
5. `已安排` 中查看/暂停/编辑

**D. 提示词：让记忆显式工作**
```
记住以下关于《书名》的设定，之后每次涉及该书都用它：
- 主角名 <X>，禁用称呼 <Y>
- 世界观：<一句话>
- 文风：<...>
```
（要真正持久，写进**项目指令**比依赖记忆更稳）

## 坑与反直觉

1. **关掉「记忆」不删聊天**；日后重开可能据聊天记录重新生成记忆。
2. **删聊天 ≠ 删已保存的记忆**——两者分开存储，必须分别处理。
3. **「引用聊天记录」关掉后是 30 天内删除**，不是立即；已保存的记忆不受影响。
4. **记忆摘要不等于全部记忆**，官方明确它可能省略细节；别把它当审计日志。
5. **分享链接不含记忆来源**，但任务分享链接会**明文包含任务指令**——别把敏感内容写进指令或标题。
6. **定时任务的写操作可能被拦下暂停**，不要设计成无人值守发消息的机器人。
7. **Slack DM / 表情回应 / 编辑 / 删除都不会触发任务**；且必须先把 `@ChatGPT` 加进频道。
8. **Slack 应用一次只能连一个工作区**。
9. **agent mode / deep research / Pro 模型跑 Slack 可能耗尽每用户 API 配额**，即使工作区总配额没满。
10. **在 Slack 里 @ChatGPT 和把 Slack 连进 ChatGPT 是两件事**，别混。
11. **定时任务不支持语音聊天与 GPT**；Free/Go 不能建事件触发任务。

## 未核实 / 存疑

1. **Slack 应用能否"发送消息"**：权限范围含 `chat:write`，但官方能力清单未逐条列出；**推断可行，未获明示确认**。
2. **Slack 应用在 Work 模式下的可用性**：官方标注可用位置为 Chat / deep research / agent mode，**未列 Work**；Work 侧目前确认的是"事件触发任务 + Slack"这条链路。
3. **Teams / 其他 IM 的写能力**：Microsoft Teams 有独立应用页，但本次未核实其 action 清单。
4. **定时任务审批的判定边界**：官方只说"可能需要批准"，**未给出哪些动作一定需要/不需要**。
5. **WorkBuddy 侧对照**：本工作台有定时/周期任务（automations）与内置邮件能力，IM 发送取决于已连接的 connector —— 未在本条目内核实，需要时单独确认。
