# MCP 工具回执协议（envelope）

> **TL;DR** 工具回执应该是一个**统一形状的结构化对象**，而不是一段自由文本。三条原则：
> ① 必回显"实际解析到的目标"和"实际跑的命令"；② 失败时**主动预取**诊断信息（替调用方
> 省一次往返）；③ 记账字段与模型可见字段**分离**（同一个对象，日志看完整版，模型看精简版）。

标签：`mcp-design` `protocol` · 证据等级：`A`（源码直读）

## 问题

MCP 工具最常见的回执形态是 `-> str`：一段给模型看的文本。这带来三个具体麻烦：

1. **隐含性** —— 工具自己"猜"了一个目标（默认路径、默认主机、默认分支），回执里不写，
   调用方以为它操作的是别的东西。
2. **往返浪费** —— 失败了只回一句 `permission denied`，模型必须再调一次才能拿到细节。
   每次往返都带上下文成本。
3. **无法度量** —— 没人知道这个工具到底省了多少上下文，也就无法证明它值得存在。

## 模式

### 原则 1：绝不隐含

回执里必须有两个字段：

| 字段 | 内容 |
|---|---|
| `resolved_target` | 实际解析到的目标（绝对路径、`repo#host`、索引名……） |
| `command` | 实际执行的命令（argv 数组，不是字符串） |

**判据**：把回执给一个没看过你代码的人，他能不能复现这次操作？不能就说明有隐含。

> 例子（`nix-agent`）：所有工具都回显 `resolved_target` 与 `command`。上游文档的原话是
> "nothing is silently implicit"。多命令工具会变成 `commands` 数组。

### 原则 2：失败时主动预取

不要在失败时只回退出码。**在工具内部就把它会需要的后续信息取好**：

| 字段 | 内容 | 替调用方省掉了 |
|---|---|---|
| `first_error` | 第一个像错误的行 | 自己 grep 日志 |
| `error_detail` | 结构化解析结果（`{message, file, line, column, trace}`） | 自己从长日志里抠位置 |
| `<domain>.log_tail` | 失败构件/进程的日志尾部 | 一次独立的 `nix log` / `docker logs` 调用 |

**判据**：失败后调用方**第一个想跑的命令**是什么？把它提前跑掉，结果放进回执。

### 原则 3：状态要能表达"部分成功"

`ok` / `failed` 两态不够。真实世界有第三种：**主操作成功，但副作用里出了问题**。

- `degraded` = 激活成功，但有服务新失败
- 回执同时给 `newly_failed` / `resolved` / `still_failed` 三段 diff

**判据**：把 `degraded` 折叠进 `ok`，调用方就会把"有服务挂了"当成成功。

### 原则 4：记账与可见分离

```
工具内部：response["raw_bytes"] = N; response["returned_bytes"] = M
    ↓
instrument 包装：返回给模型前 strip_accounting() 剥掉这两个字段
    ↓
模型看到的：没有记账字段
usage log：拿到完整对象（记账字段在）
```

**同一个对象，两个视图。** 好处：度量真实（工具自己报原始大小），上下文干净（模型看不到噪音）。

> 例子（`nix-agent`）：`runner.account()` 写入，`server.py::instrument()` 在
> `finally` 里 `strip_accounting()`。源码注释明说："the usage log reads them first"。

### 原则 5：早退状态要区分

有些失败是"命令跑了但结果不对"，有些是"**命令根本没跑**"。后者应该有自己的状态名，
让调用方知道**重试是没意义的，要改输入**。

| 类型 | 例 | 正确反应 |
|---|---|---|
| 执行失败 | 构建报错、sudo 认证失败 | 修问题后重试 |
| **早退** | 目标不存在 / 目标被锁定 / 拒绝远程引用 / 前置检查没过 | **改输入，不要重试** |

早退状态还应该**带上可用的替代值**（如"flake 里有这些主机名"），而不是只说"没找到"。

## 反面清单

- ❌ 回执是自由文本，没有稳定字段 → 调用方只能正则抠
- ❌ 成功时回全量日志 → 上下文成本无上界
- ❌ 失败时只回 `exit 1` → 强制往返
- ❌ 状态只有 ok/fail → 无法表达部分成功
- ❌ 记账字段出现在模型可见的回执里 → 噪音
- ❌ 早退和真失败混在一个状态里 → 调用方会无脑重试
