## 1. 输出格式（硬性）

每个源页面在章节文件里输出为**一个 `## ` 页面节**：

```markdown
## <中文页面标题>

> 原文：https://block.github.io/goose/docs/<路径，不含扩展名>

<正文>
```

- **必须**：`> 原文：` 后面**不加尖括号**，直接跟裸 URL，URL 后不留空格以外的内容。
- **必须**：章节文件第一行是 `# goose 官方文档中文手册：第 NN 章　<章名>`（NN 为两位章号）。
- 页面节之间用一个空行 + `---` + 空行分隔。

## 2. 标题层级映射

| 源 | 译文 |
|---|---|
| 文件 frontmatter 的 `title`（即页面标题） | `## ` 页面节标题 |
| 源 `##` | `### ` |
| 源 `###` | `#### ` |
| 源 `####` | `##### ` |
| 源 `#####` | `###### ` |

**不得跳级、不得合并、不得删除任何小节。** 源文件里的 `# ` 一级标题（少数文件有）按其语义并入页面节标题或降为 `###`。

源文件顶部的 YAML frontmatter（`---` 包围的 `title:` / `description:` / `sidebar_position:` 等）**不翻译、不输出**，只用来确定页面标题。

`import ... from '@theme/...'` / `import { X } from 'lucide-react'` 等 **MDX import 语句整行删除**（不属于文档内容）。

## 3. 代码与技术标识

**一律不翻译**：

- 代码块（``` 围栏内的一切，含注释）
- 行内代码 `` `...` `` 的内容
- 命令、子命令、参数名、环境变量名（`GOOSE_MAX_TURNS` 等）
- 文件路径、目录名、配置键名
- URL、JSON / YAML / TOML 片段
- 产品名、扩展名、模型名、provider 名（`goose` / `Developer` / `Playwright` / `claude-sonnet-4-5` 等）
- 代码围栏的语言标记（```bash 保持 ```bash）

代码围栏的**开闭必须成对**，且标记必须位于**第 0 列**（不得缩进）。

## 4. 图片与链接

- 图片：`/img/xxx.png`、`/assets/...` 等以 `/` 开头的路径 → 改写为 `https://block.github.io/goose/img/xxx.png`（绝对地址）。**一张都不能删。**
  - `data:image/png;base64,...` 内联图**原样保留**。
  - `![alt](/api/v1/...)` 这类 API 路径示例**原样保留**。
  - alt 文本译为中文。
- 站内链接：`[文字](/docs/guides/foo)` → `[文字](https://block.github.io/goose/docs/guides/foo)`，锚点 `#section` 保留。
- 外链原样保留。

## 5. 提示块（Docusaurus admonitions）

| 源 | 译文 |
|---|---|
| `:::note` | `:::note`（标题译为「说明」或省略） |
| `:::info` | `:::info`（「信息」） |
| `:::tip` | `:::tip`（「提示」） |
| `:::warning` | `:::warning`（「警告」） |
| `:::danger` | `:::danger`（「危险」） |
| `:::info Desktop Only` | `:::info 仅桌面版` |

**保留 `:::` 语法本身**（不要转成引用块），只翻译冒号后的标题文字。

## 6. JSX / MDX 组件

源文件里有 `<Tabs groupId="interface">` / `<TabItem value="ui" label="goose Desktop" default>` / `<GooseDesktopInstaller ... />` / `<CLICIExtensionInstructions ... />` 等 MDX 组件。

处理规则：

- **`<Tabs>` / `<TabItem>`：保留标签，只翻译 `label="..."` 属性值里的自然语言**。
  - `label="goose Desktop"` → 保持（产品名不译）
  - `label="ui"` → 保持（这是 value 标识，不译）
- **纯渲染型组件**（`<GooseDesktopInstaller ...>`、`<CLIExtensionInstructions ...>`、`<YouTubeShortEmbed ...>`、`<ImageCarousel ...>`、`<ContentCardCarousel ...>`、`<GooseBuiltinInstaller ...>` 等）：**整块保留原样**（含所有属性），因为它们是站点渲染指令，翻译会破坏渲染。但**其外层包裹的文字说明要翻译**。
- `<details>` / `<summary>`：保留标签，翻译 `<summary>` 内的文字与内部正文。
- 若某段 JSX 无法判断，**保守保留原文**，不要猜。

## 7. 表格

- 表头译中文；单元格里的技术标识不译。
- **保持列数与分隔行**（`|---|---|`）不变。
- 源里的 `<br></br>` / `<br/>` 保留。

## 8. 完整性判据（最关键，必须内化）

> 中文 UTF-8 单字 3 字节。**逐句完整翻译后，译文体积应与英文源基本持平（90%–130%）。**
> **禁止**用「中文应为英文的 40%–60%」当完整性判据 —— 那会导致为了凑指标而删内容。

**严禁**：
- 编造原文没有的内容
- 删减小节、合并小节、省略「重复」内容
- 加译者按语、总结段、「以上」式收尾
- 用「（此处略）」「详见原文」代替正文

**允许**：
- 按语义还原被抽取工具压成一行的多行内容（表格错位、代码块挤行）
- 调整语序以符合中文表达
- 把 `:::note` 之类的提示块标题译为中文

## 10. 写作风格

- 简体中文，技术文档语体，**第二人称「你」**（不用「您」）。
- 简洁直述，不添加原文没有的语气词。
- 英文与中文之间**不加空格**（如「使用 Developer 扩展」）。
- 中文标点用全角，代码与 URL 用半角。
- 列表符号沿用原文（`-` / `*` / 数字），不改成中文顿号。

## 11. 执行要求

- **必须用 Write 工具写文件**，禁止用 shell 的 `echo` / `cat <<EOF` 拼文件。
- **先完整读完本章所有源文件再动笔**；大文件分段读（`offset` + `limit`）。
- 若 `Read` 被内容审批门拦截（返回 `SENSITIVE_APPROVAL=TIMED_OUT`），把 `limit` 调到 3–8 行并**更换 `offset`** 逐步推进重试，不要放弃，也不要连续用同一 offset 重复重试（会触发循环守卫）。
- 章节输出超过约 6000 行时，分片写临时文件再合并。
- 全部写完后**自查**：
  1. 本章 `## ` 页面节数量 == 本章源文件数
  2. 每个页面节都有 `> 原文：` 行
  3. 无 `/img/` 相对图片残留、无 `](/docs/` 相对链接残留
  4. 代码围栏数为偶数
  5. 文件字节数 ≥ 源文件总字节数 × 0.9
- 汇报格式 ≤ 150 字：章号 / 页面数 / 输出字节数 / 自查五项是否通过 / 遇到的异常。
