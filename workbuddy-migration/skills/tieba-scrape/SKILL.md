# 百度贴吧帖子列表抓取

## 核心结论

**PC 版 `/f?kw=` 抓不到列表，必须用移动版端点。**

| 端点 | 结果 |
|------|------|
| `https://tieba.baidu.com/f?kw=<kw>&ie=utf-8` | PC 版，列表由 JS 渲染；直连普遍 403（WAF），即使 WebFetch 成功也只能拿到吧简介静态段 |
| `https://tieba.baidu.com/mo/q/m?kw=<kw>&pn=<N>` | **移动版，服务端渲染，可直接拿到帖子列表** ✅ |

## 抓取步骤

1. 用 **WebFetch**（服务端出口，不受本机代理/WAF 影响）请求：
   ```
   https://tieba.baidu.com/mo/q/m?kw=<吧名>&pn=0
   ```
2. prompt 写：`列出页面上所有帖子：标题、作者、显示的时间（原样保留，如 11:11 或 昨天 或 09-21）、回复数、链接。逐条完整列出。`
3. 翻页：`pn=0,50,100,150,...`，每页 30 条。
4. **停止条件**：时间列出现 `昨天`、`MM-DD` 形式即已跨天，该条及之后不属于今天。
5. 汇总输出（Markdown 表或 HTML 报告），并附上每条的 `https://tieba.baidu.com/p/<id>` 链接。

## 历史区间回溯（"最近 N 个月流行什么"类需求）

列表按最后回复时间倒序，深翻 `pn` 可回到过去。**先测速率，再定步长**：

1. 探测 `pn=1500 / 3000 / 6000` 各一页，读出对应日期，算出「每帖≈几天」。
   实测 rimworld 吧（2026-09）：`pn=0`→当天，`pn=100`→当天早晨，`pn=600`→3 天前，`pn=6000`→47 天前。
   ⇒ 约 **130~200 帖/天**，3 个月 ≈ `pn 0~11500`。
2. `pn` 无上限（测到 14000 仍正常）。但**逐页翻不可行**（3 个月 = 400 页）。
3. **用步长抽样**：`pn = 0, 400, 800, …`（步长 400 ≈ 覆盖 7.5%，32 页覆盖 3 个月）。
   每页 30 帖，总样本 ~960 帖，足够给关键词排名。
4. prompt 要求紧凑输出：`只输出纯文本行，每行格式：日期|标题|回复数。不要作者、链接、图片、置顶帖。`
   （否则 WebFetch 会带上 URL/图片 markdown，token 翻 3 倍）
5. 落盘成 `日期|标题|热度` 的文本，再用 Python 做**关键词组聚合**：
   - 定义 `{MOD名: [别名...]}`，含别名与子 MOD（如 鼠族 → 鼠鼠/地鼠大冒险/鼠洞/金鼠）
   - 统计三项：`提及帖数`（广度）、`热度合计`（深度）、`单帖最高`
   - 单字关键词（如 "鼠"）会误召回，别名表尽量用 2 字以上词
6. 报告必须声明口径：移动版时间是**最后回复时间**，所以「提及帖数」衡量的是**持续被讨论程度**，不是发布量。

## 关键坑

- **不要浪费时间在 curl / 公共 CORS 代理上**：贴吧对数据中心出口 IP 一律 403，`r.jina.ai`、`allorigins`、`codetabs` 均不可靠（返回空/500/522）。本机 `curl` 实测 HTTP 403（size 2507）。
- **单帖页 `curl` 会拿到「百度安全验证」空壳（约 2.5KB，`<title>百度安全验证</title>` + 一段 loadScript JS）**，同一 URL 用 **WebFetch 则能正常返回帖子正文**。⇒ **帖子正文一律用 WebFetch，不要用 curl**。判断方法：`grep -c "百度安全验证" /tmp/x.html`，命中就是被拦。
- **分页抓帖**：`https://tieba.baidu.com/p/<id>?pn=N`（N 从 1 起）。WebFetch 每次只返回**部分楼层**（本机实测 pn=1 只到 3 楼、pn=2 只到 17 楼、pn=3 只到 34 楼），**必须逐页翻**才能拿全；楼层号会在返回里标明，据此判断还剩多少页。
- ⚠️ **但 `?pn=N` 对部分帖完全无效**：本机实测 `p/8864562664` 的 `?pn=2` 返回与 `?pn=1` **一模一样的前 5 楼**。**判断方法**：比对两次返回的首尾楼层号，若相同说明该帖分页抓不动（可能被折叠/需登录/帖本身很短），**不要再重试，直接换帖或换源**。
- **`?see_lz=1`（只看楼主）会截断**，正文长帖建议用 `?pn=N` 逐页翻。
- **不要盲目装 agent-browser**：真实浏览器同样走本机代理，出口 IP 已被拦，大概率仍 403，且需下载数百 MB Chromium。WebFetch 是本场景最优解。
- **PC 版链接里的 `cid=` 参数**（分类）在移动版无对应项，可忽略，直接抓全吧列表。实测 `mo/q/m?kw=xx&cid=2` 与不带 cid 返回完全相同。
- **吧内搜索走不通**：
  - `f/search/res?ie=utf-8&kw=<吧>&qw=<词>` → 被「百度安全验证」拦截（WebFetch 返回验证码页）。
  - `mo/q/search?kw=<吧>&qw=<词>` / `&word=<词>` → 参数被忽略，退化成全吧列表；若只给 `word=` 会跳到**同名吧**（如搜 `mod` 跳到「mod吧」）。
  ⇒ 想做吧内话题统计，只能靠深翻 + 关键词聚合，没有搜索捷径。
- **时间语义**：移动版列表显示的是「最后回复时间」，排序也是按此倒序，不等于发帖时间。需要严格「今日新发主题」时须说明该口径差异。
- 列表中的数字为互动数（回复数），PC 版与移动版口径可能不同，报告中标注清楚。
- 部分行会显示**两个数字**（如 `\ 5 \ 25`），取后者作为热度；置顶帖带 `is_jingpost=1`，按需剔除。
- 列表里混有**跨月老帖**（最后回复在窗口内、发帖时间很早），做「新发布 MOD」清单时要靠标题里的「发布/预告/更新」字样单独筛，不能只看日期。

## 输出建议
