# 术语表构建与一致性维护流程

术语表是长文翻译质量的第一道保障：术语不统一，读者会把同一个概念误认为多个概念，整份文档的可信度随之下降。本文件规定术语表的构建流程、模板格式、一致性维护纪律和领域陷阱速查。

## 一、术语表构建流程（翻译前完成）

### 1. 提取候选术语

通读全文（不是抽读），抓取以下四类候选：

- 高频专业词：全文出现 2 次以上的领域概念
- 专有名称：产品名、功能模块名、机构名、项目代号
- 缩写与首字母词：SLA、KPI、ROI 及其定义关系
- 高危关键词：法律义务词、技术参数词、金额单位等错译代价高的词

不入表标准：普通通用词汇（"系统""公司""用户"）、只出现一次且无歧义的常规词，不进术语表——表格本身也要控制规模，超过两三百条反而失去查阅价值。

### 2. 确定译法（优先级从高到低）

1. **用户提供**：用户术语表、历史译文、指定译法，永远最优先，即使与词典不一致也沿用——术语所有权属于用户
2. **行业惯例**：该领域的标准译法，如"machine learning"=机器学习、"cloud native"=云原生
3. **权威词典与标准**：GB/T 术语标准、行业白皮书、官方双语文件、目标市场主流厂商文档用语
4. **以上皆无**：给出 1-2 个候选译法，标注推荐项及理由，交用户确认后再动笔

### 3. 歧义词标注

一词多义的术语必须入表并标注歧义，翻译时按语境取用：

- "应当"：合同语境 = shall（义务），说明书语境 = should（建议）
- "address"：名词 = 地址，动词 = 处理／应对
- "party"：法律 = 当事方，日常 = 派对（合同文档中按"方"处理）
- "solution"：技术 = 解决方案，化学 = 溶液

歧义处理原则：同一文档内若两种语境都出现，在备注列分场景写明各自译法，而非强行统一为一个。

## 二、术语表模板

| 原文术语 | 译法 | 词性 | 领域 | 备注 |
|---------|------|------|------|------|
| 负载均衡 | load balancing | 名词 | 网络/云计算 | 固定搭配，不可倒装为 balancing load |
| 应当 | shall | 情态动词 | 合同 | 义务性条款专用；非合同语境译 should |
| SLA | 服务等级协议 | 缩写 | IT 服务 | 首次出现写"全称（缩写）"，其后可直接用 |
| 对价 | consideration | 名词 | 合同 | 法律固定译法，不译"考虑" |

交付版术语表额外补"出现次数"列（高频术语排前面），方便用户优先审校最重要的译法。

## 三、一致性维护

- **分段翻译纪律**：长文档分段翻译时，每段开始前对照术语表，每段完成后快速回查本段术语用法是否与表一致。禁止凭上一段的记忆直接开翻。
- **新术语回填**：翻译中途发现原文未提取到的新术语，先定译法、立即回填术语表，再继续翻译。不要"先翻完再说"，否则后半文的译法无法追溯。
- **译法修订联动**：用户中途修改某术语译法时，全文检索旧译法并统一替换，替换后重跑一次术语一致性检查，并在翻译说明中记录该变更及涉及位置。
- **缩写规范**：首次出现用"全称（缩写）"，如"服务等级协议（SLA）"，之后可直接用缩写；英文原文中的缩写译成中文时同理反向处理。
- **英文专名不译**：产品名、商标、大小写敏感词（iOS、JavaScript、GitHub）保留原样，不译不改写大小写。

## 四、领域速查：常见术语陷阱

### 技术文档

- "library" = 库（不是"图书馆"）；"缓存 cache／高速缓存"全文统一一种
- "crash" 按语境译"崩溃／宕机"，入表标歧义；"memory" = 内存（不是"记忆"）
- 中文"数据"视语境译 data／dataset，参数表中的"参数"是 parameter 不是 argument（编程语境两者有分工）

### 商务文档

- 公司名原则上不译，除非有官方中文名；职务头衔按目标市场惯用层级对齐（Director = 总监／董事，视公司结构定）
- "proposal" 分"提案／投标书"语境；"offer"=录用通知／报价，须入表
- "亲，您好"类电商口吻不可直译进商务英文，按信函惯例改写为 "Dear Mr./Ms. X"

### 法律文档

- "应当 shall／可以 may／不得 shall not"：合同三态严格区分，混用会改变法律效力，这是法律翻译第一条铁律
- "party" = 方／当事方全文统一；"consideration" = 对价（不是"考虑"）
- 免责（limitation of liability）、赔偿（indemnification）、保证（warranty）、不可抗力（force majeure）为高危条款，逐条标注请专业人士复核后再定稿
