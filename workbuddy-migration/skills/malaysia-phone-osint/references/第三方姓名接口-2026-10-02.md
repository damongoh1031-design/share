# 第三方「号码 → 姓氏」方案（2026-10-02）

> 问题：DB1 / Truecaller 经常只返回名，不返回姓。有没有别的接口能补上真实姓氏？
> 结论：**缺姓是数据源结构，不是解析 bug。** 免费众包库补不出库里没有的姓。
> 唯一有文档支持的「号码 → `first_name` + `last_name`」方向是 B2B 职业库（PDL、RocketReach）。
> 这两家的**马来西亚手机号命中率尚未实测**，不得把营销覆盖率写成事实。

## 1. 为什么现有库没有姓

22 个已验证号码：有返回 18/22，token 全中（名+姓都对上）仅 2/22。
典型返回是 `Dato Dr Ricky`、`Mr Malvin`、`Prof Lee`、`Loh lawyer`。

这些库存的是「别人通讯录里的备注」，不是电讯商实名。多数人存联系人只存名。
同号重查 22/22 可复现，所以再查一次、换格式、换 UA，不会多出一个姓。

能提高的是交叉确认率，不是单库召回率：

1. 两库共有的 token 才是姓氏候选。只在一边出现的 `lawyer` / `PA` / `SURBANA` / `abe` 标成关系或组织，不拼进姓名。
2. 比对前剥称谓（`MR` `DR` `DATO` `PUAN` `ENCIK`），但不剥 `Tan` `Lim` `Ng` `Lee` `Yap` `Low`/`Loh`。
3. 中文备注先转拼音再比（`智辉` → `zhihui` ⊃ `hui`）。
4. 备注里已有组织名（`Lotus Power : Angie Ng`、`Loh lawyer`）时，改查该公司的公开董事/律师名录，不要继续堆号码库。
5. SSM e-Info 是「公司名 → 董事」，不是「号码 → 人」。没有公司名就不要付费查 SSM。

## 2. 方案分级

### A. 有机会返回结构化姓氏（先盲测，再考虑批量）

| 服务 | 端点 | 反查键 | 姓名字段 | 约束 |
|---|---|---|---|---|
| People Data Labs | `GET https://api.peopledatalabs.com/v5/person/enrich` | `phone` 单独即可，**必须以 `+` 国家码开头** | `full_name` `first_name` `last_name` | `min_likelihood` 默认 2（约 10–30% 是本人）。要姓氏准确率，设 `min_likelihood=6` 且 `required=last_name` |
| RocketReach | `GET https://api.rocketreach.co/api/v2/person/lookup` | `phone` + `lookup_type=phone` | 职业档案中的 name | 消耗 export credits。404 = 无档案。营销页 98% 是邮箱可达率，不是反查准确率 |

盲测集（已有 ground truth，见 SKILL §9）：

- `+60123355873` 期望姓 `leong`（名 roland）
- `+60122071768` 期望姓 `lim`（名 ricky）
- `+60123013006` 期望姓 `lim`（名 martin）
- `+60192385938` 期望姓 `lee`（名 marvin）

通过线：4 个里至少 2 个 `last_name` 与期望一致，且 PDL `likelihood≥6` 或 RocketReach `status=complete`。
达不到就停。随机消费者号码的预期命中率应低于 DB1 冷数据的 29%，因为职业库偏 LinkedIn 人群。

### B. 另一份通讯录备注（不能当姓氏来源）

| 服务 | 文档事实 | 处置 |
|---|---|---|
| GetContact | tag = 其他用户添加的 nickname/name，用户可自行管理。无官方反查 API | App 内手动交叉可以。不要接入 GitHub 上的非官方逆向库 |
| Whoscall / Gogolook Asi | 企业产品是防诈（号码/域名风险、诈骗网站）。页面未提供个人全名字段 | 可补「是不是诈骗」，不能补姓 |
| Truecaller for Business | Verified Business API 是商家登记自己的来电显示名 | 不能查任意个人号 |
| Eyecon / Sync.ME / CallApp / ViewCaller | 转售页声称返回 name + photo | 本仓库已实测 Sync.ME、Eyecon 失效。未重新实测前视为不可用 |

### C. 没有 name 字段（不要为姓氏去调）

| 服务 | 证据 |
|---|---|
| Telnyx CNAM | 官方文档：*Retrieve the registered caller name associated with a US number.* 单价 $0.003，与全球 carrier lookup（$0.0015）不是同一能力 |
| Twilio Lookup Caller Name | 仅美国 |
| numlookupapi validate | 字段是 carrier、line_type、location、e164。无 name |
| Vonage / HLR Lookups | 当前运营商 / MNP。无姓名 |
| Tellows | 接口 HTTP 200，马来西亚 5/5 空，含已知 329 次举报号 |
| whoseNo / numtrace / searqle | 垃圾来电热度，无反查 API |
| Kaspr / Apollo / Lusha | 方向是 LinkedIn URL → 电话，不是电话 → 人 |

## 3. 仍拿不到的东西

电讯商实名、身份证号、住址、通话记录，仍然只有：

- 报警：PDRM / NSRC **997**
- 法院：**Norwich Pharmacal order**

PDPA 2010（2024 修订）：非法交易个人数据最高 RM1,000,000 + 3 年监禁。
F 层只使用用户自己的商业 API key，只读、小样本、有 ground truth 再扩大。
