# 外呼 CRM · 对标成熟产品的优化建议

> 对标对象：Salesforce / HubSpot / 纷享销客 / 销售易（CRM 侧），Genesys / Five9 / 容联七陌 / 天润融通（外呼侧）
> 对象系统：本项目原型 v2.0（Go + SQLite 局域网部署，一层主管→坐席，XLSX 名单驱动）
> 日期：2026-10-20

## TL;DR — 四个判断

1. **你的系统里没有「通话」这件事。** 所有呼叫都是人工登记，没有 CDR、没有录音。结果：无法验证坐席是否真打了、真实接通率不可知、质检无从下手、AI 没有数据可用。这是最该补的一块，优先级高于任何界面优化。
2. **合规风险被低估了。** 2025 年工信部在推号码保护试点、多地通管局明确「严禁营销外呼」。现在只有一个客户级 `dnc` 标记，没有全局禁呼库、没有频次上限、没有外呼时段限制。这不是功能，是保命。
3. **只有「分配」，没有「回收」。** 成熟 CRM 的核心是客户资源**流转**：公海 / 私海 / 保护期 / 领取上限 / 到期自动回收。现在分下去就归坐席了，主管只能靠人肉发现谁在囤客户。
4. **AI 的正确切入点是「通话后」，不是「通话前」。** AI 首轮外呼在名单质量差、合规敏感的场景里风险大于收益；「录音转写 + 摘要 + 自动打标签 + 质检」是纯增益。

## 一、能力对照

| 能力 | 现状 | 成熟产品的做法 | 差距 |
|---|---|---|---|
| 客户主数据 / 去重合并 | ●●● | 手机号标准化唯一索引 + 合并保留主记录 + 变更历史 | 已达标 |
| 权限与数据范围 | ●●● | 角色 + 数据范围 + 字段级权限 + 记录共享 | 缺字段级（如隐藏成本价） |
| 审计留痕 | ●●● | append-only + 关键操作双人复核 | 可被前端清空，生产需服务端 |
| 导入导出 | ●●● | 模板校验 + 分批事务 + 失败行回执 | 已达标 |
| 任务与提醒 | ●●○ | 任务引擎 + 站内/短信/企微多通道 + 升级提醒 | 只有站内；提醒没人处理不会升级给主管 |
| 公海 / 私海流转 | ●○○ | 领取上限、保护期、到期自动回收、跨组流转审批 | **只有分配，没有回收** |
| 跟进节奏 / SLA | ●○○ | 按客户等级设不同跟进时限，超时预警并扣分 | 有周期重呼，但那是给未接通的 |
| 目标与过程管理 | ●●○ | 日/周/月目标 + 完成度 + 排行 + 异常预警 | 有结果报表，**没有目标** |
| 软电话 / 点击拨号 | ○○○ | WebRTC 软电话、点击拨号、自动弹屏、话后小结计时 | **完全缺失** |
| 通话记录 CDR | ○○○ | 主叫/被叫/振铃/接通/时长/挂断方/录音 URL | **完全缺失** |
| 录音与质检 | ○○○ | 100% 录音 + ASR 转写 + 违禁语命中 + 评分卡 | **完全缺失** |
| 号码保护（AXB 中间号） | ○○○ | 坐席看中间号，客户看公司号，双向隐藏真实号码 | **完全缺失**（工信部 2025 已开试点） |
| 合规闸门 | ●○○ | 全局 DNC + 频次上限 + 时段限制 + 主叫鉴权 | 只有单条客户 `dnc` |
| AI 能力 | ○○○ | 摘要、意向评分、话术推荐、质检、AI 外呼 | **完全缺失** |
| 企微 / 移动端 | ○○○ | 加微、会话存档、小程序 | 缺失（优先级低于上面） |

> ●●● 可上线　●●○ 能用但缺关键环节　●○○ 有雏形　○○○ 没有

**5 个 ○○○ 全部集中在「通话」相关** —— 这就是第 1 条判断的依据。

## 二、九个优化项

| # | 优化项 | 优先级 | 成本 | 市面做法 | 现状 | 建议 | 验收 |
|---|---|---|---|---|---|---|---|
| 1 | 合规闸门（DNC / 频次 / 时段） | **P0** | 3 人日 | 全局 DNC 按**号码**存；同一号码 7 天 ≤ 2 次；9:00–20:00 外呼；主叫鉴权备案 | `dnc` 挂客户记录，换条记录还能再打 | 建 `dnc_numbers`（号码唯一、全局、永久）；`call_gate()` 外呼前统一校验 | 同一号码 7 天内第 3 次被拦，主管能看拦截明细 |
| 2 | 公海回收 + 保护期 | **P0** | 4 人日 | 公海/私海；领取上限（如 200 条/人）；保护期 15 天无有效跟进自动退回 | 只有分配，分下去永久归坐席 | 加 `pool` 状态、`protectUntil`、`claimLimit`；定时任务扫描到期未跟进 → 退回并发通知 | 领 20 条 15 天不跟进，第 16 天自动回公海 |
| 3 | 客户分级 + 跟进 SLA | **P0** | 2 人日 | A/B/C 分级，A 类 24h、B 类 3 天、C 类 7 天；超时预警、连续超时降级 | 周期重呼只管「未接通」，不管「联系上了但没再跟」 | 加 `grade` + `slaHours`；`slaBreach()` 算超时，进主管异常预警区 | A 类 24h 无跟进，坐席与主管同时看到红色预警 |
| 4 | 目标管理 | **P0** | 2 人日 | 日/周/月目标（呼出、接通、有效通话、成交），实时完成度 + 排行 | 有结果报表，没有目标值 | 加 `targets` 表（人/组/周期/指标）；KPI 卡下加进度条与差额 | 设「每人每天 80 通」，工作台实时显示进度 |
| 5 | 未接通自动短信 | **P0** | 1.5 人日 | 未接通自动发短信（公司名 + 来电事由 + 回电方式），回复可回流 | 未接通就只是「未接通」 | 接短信网关，挂到「无人接听」结果上；同号码 24h 内只发一次 | 未接 10 秒内客户收到短信，系统记一条触达 |
| 6 | 软电话 + CDR | **P1** | 8–10 人日 | WebRTC 软电话点号即拨；通话结束回写 CDR；坐席不用手填「已接通」 | 系统外拨号，回来手工登记 | 不碰语音网关，接云通信 SIP 中继（阿里云/腾讯云/容联）；只做「发起呼叫 / 收 CDR 回调 / 用 CDR 生成记事草稿」 | 点号即通；挂断 5 秒内生成待确认记事 |
| 7 | 录音 + 关键词质检 | **P1** | 5 人日 | 100% 录音留存；违禁语实时命中；评分卡抽检（开场白/身份确认/需求挖掘/异议处理/结束语） | 没有录音，质检不存在 | 录音随 CDR 落地；先做关键词命中（规则引擎，可解释），命中标红推主管 | 每天自动筛出 5 通含违禁语的通话 |
| 8 | AI 通话摘要 + 自动标签 | **P1** | 5 人日 + 模型成本 | ASR 转写 → 3 行摘要 + 意向等级 + 关键异议 + 下一步建议，自动填记事，坐席确认 | 坐席手写，质量参差（有人只写「未接」） | 必须放在 CDR 之后（有录音才有转写）；只做摘要 + 标签，不做实时辅助 | 记事填写从 60 秒降到 10 秒，完整率提升 |
| 9 | 企微集成 | **P2** | 4 人日 | 一键加微、会话存档反哺画像、企微侧发资料 | 系统里只有电话号码 | 先做「一键加微 + 加微状态回写」，会话存档涉及合规评估放后面 | 客户详情显示已加微/未加微，主管能统计加微率 |

## 三、分三阶段落地

### 阶段一 · 机制补齐（2 周）
全局 DNC + 频次/时段闸门 · 公海回收 + 保护期 · 客户分级 + SLA · 目标管理 · 未接通自动短信

**产出**：客户不再沉淀，违规外呼被拦，主管第一次能看到「谁落后」。

### 阶段二 · 打通通话（1 个月）
SIP 中继 · WebRTC 软电话 · CDR 回调 + 记事草稿 · 录音留存 + 关键词质检 · AI 摘要 + 标签

**产出**：统计口径从「人工登记」变成「通话事实」，质检与 AI 有了数据基础。

### 阶段三 · 提效与扩展（1 季度）
号码保护（AXB）· 话术库 + 实时提示 · 企微集成 · 实时坐席看板 · 全量 AI 质检

**产出**：从「管得住」到「管得好」，坐席产能可对比、可复制。

## 四、明确不要做的六件事

| 不做 | 原因 |
|---|---|
| 预测式外呼 | 需要稳定名单量 + 接通率模型 + 足够坐席池，规模不够；空响本身就是投诉源 |
| AI 首轮外呼 | 名单来源不干净时，AI 只会更快地制造投诉，合规成本远高于省下的人力 |
| 自研语音网关 / 话机对接 | 用云通信 SIP 中继，别碰硬件和信令 |
| 复杂商机 / 报价 / 订单 / 合同 | 你做的是「名单 + 外呼 + 意向筛选」，不是 6 个月长周期销售 |
| 多级组织架构 | 一层主管→坐席够用；层级一多数据范围规则指数级复杂 |
| 原生移动 App | 坐席在工位用电脑，主管偶尔看数据，响应式网页够；真要移动端做小程序 |

## 五、先定指标，再谈优化

| 指标 | 公式 | 用法 |
|---|---|---|
| **北极星：有效通话时长 / 坐席 / 天** | Σ 接通且时长 ≥ 30s | 不用「呼出量」，因为它可以被空号刷高 |
| 接通率 | 接通数 / 外呼数 | < 15% 查名单质量；< 8% 先洗名单别加人 |
| 话后处理时长 ACW | 挂断到提交记事的秒数 | > 90 秒说明记事太麻烦，这是 AI 摘要最直接的价值点 |
| SLA 达成率 | 按时跟进数 / 应跟进数 | 比「今日登记数」更能反映坐席是否在挑客户 |
| 客户沉淀率 | 超保护期未跟进 / 在跟客户 | 公海上线后立刻暴露「谁在囤客户」 |
| 投诉率 / 退订率 | 投诉或退订号码 / 触达号码 | 行业经验 > 0.1% 就该停下来查名单来源 |

## 六、如果只能做三件事

1. **合规闸门（DNC + 频次 + 时段）** —— 3 人日。避免封号，是一切业务的前提。
2. **公海回收 + 保护期** —— 4 人日。让客户资源真正流转，主管第一次能管住「囤客户」。
3. **软电话 + CDR** —— 10 人日。把「人工登记」换成「通话事实」，之后所有统计、质检、AI 才有意义。

这三件事做完，系统才从「客户名单管理工具」变成「外呼作业系统」。其余优化都是锦上添花。
