# 外呼 CRM · 马来西亚场景优化建议（v2）

> 前提（2026-10-20 修正）：**不做通话集成**（无软电话 / CDR / 录音）、**不套用中国法规**、所有限制项**可调**。
> 对象系统：本项目原型 v3.0（Go + SQLite 局域网部署，一层主管→坐席，XLSX 名单驱动）
> 对标：纷享销客 / 销售易（公海与分配）、HubSpot / Salesforce（任务队列与 lead scoring）

## TL;DR

上一轮建议里最该做的四件事已经落地：**公海回收、联系频次闸门、角色化首页、马来西亚本地化**。
剩下的缺口只剩三个方向，而且都不依赖通话数据：

1. **客户分级 + 跟进 SLA** —— 公海管「不回来看」，SLA 管「回来了没跟上」。
2. **目标管理** —— KPI 有数没目标，坐席不知道今天该打多少。
3. **WhatsApp 触达** —— 马来西亚的主战场，不是短信也不是邮件。

## 二、本轮已实现（可在系统里验证）

| 能力 | 可调参数 | 默认值 | 验证方式 |
|---|---|---|---|
| **公海回收** | 启用开关 | 开 | 客户 → 公海页签可领取 |
| | 每人持有上限 | 200 位 | 达到上限后领取被拒，批量领取跳过并提示 |
| | 保护期 | 15 天 | 从「领取时间」或「最后跟进」取较晚者起算 |
| | 自动回收 | 开 | 超期且无待办回访才回收 |
| | 跨组流转审批 | 开 | 关掉后申请直接生效 |
| **联系频次闸门** | 总开关 | 开 | 关掉后完全不限制 |
| | 统计周期 | 7 天 | 按记事时间回溯 |
| | 周期内最多联系 | 2 次 | 记事登记 / 呼叫台保存 / 队列生成三处校验 |
| | 允许时段 | 09:00–20:00 | 不在时段内拦截 |
| **角色化首页** | — | — | 主管→KPI 看板；员工→我的日程 |
| **马来西亚本地化** | — | — | 号码 `012-*** 6789`、公司名 `Kuala Lumpur … Sdn Bhd` |

> 频次闸门是**打扰强度控制**，不是法规要求。马来西亚无中国式营销外呼禁令；
> 客户数据受 PDPA 2010 约束（告知目的、可要求更正/删除），属数据侧义务，与本闸门无关。

## 三、还该做什么

| # | 优化项 | 优先级 | 成本 | 做法 | 验收 |
|---|---|---|---|---|---|
| 1 | 客户分级 + 跟进 SLA | **P0** | 2 人日 | 每个 `category` 配 `slaHours`（A 24h / B 3d / C 7d）；`slaBreach()` 算超时，进主管预警 + 生成坐席待办 | A 类 24h 无跟进，双方同时看到红色预警 |
| 2 | 目标管理 | **P0** | 2 人日 | `targets` 表（人/组/周期/指标）；KPI 卡下加进度条与差额；员工首页显示「今日还差 12 通」 | 设「每人每天 60 通」，实时显示进度 |
| 3 | WhatsApp 触达 | **P0** | 3 人日 | WhatsApp Business API 或 wa.me 深链；未接通一键发模板；同号 24h 只发一次；发送记录写进记事 | 记事里出现「已发 WhatsApp」 |
| 4 | 号码体检 | P1 | 2 人日 | `my_prefixes` 表标运营商（012 Celcom / 016 Digi / 017 Maxis…）；连续 3 次未接自动标疑似空号 | 导入 500 条即看到「格式无效 12 / 疑似空号 8」 |
| 5 | 非通话类 AI | P1 | 4 人日 + 模型成本 | 记事自动打标签（预算/时间/竞品/决策人 + 情绪）；再做意向分排序 | 记事可按标签筛选，主管能看到「本月异议 Top 3」 |
| 6 | 移动端响应式 | P2 | 3 人日 | 只做「我的日程」「客户详情」两页；不做原生 App | 手机浏览器能看完今天的回访并写跟进 |

## 四、明确不要做

| 不做 | 原因 |
|---|---|
| 软电话 / CDR / 录音 / AI 质检 | 已确认不做通话集成，整条链路不成立 |
| 预测式外呼 | 需要通话链路与实时坐席状态，前提不存在 |
| AI 首轮外呼 | 名单不干净时只会更快制造投诉 |
| 中国式备案 / 主叫鉴权 / 号码保护（AXB） | 本地不适用；跨境拨打中国号码时再单独评估 |
| 复杂商机 / 报价 / 订单 / 合同 | 你做的是「名单 + 外呼 + 意向筛选」 |
| 多级组织架构 | 一层主管→坐席够用，层级一多数据范围规则会爆炸 |

## 五、指标口径（没有通话数据，就用登记事实）

| 指标 | 公式 | 用法 |
|---|---|---|
| **北极星：有效联系客户数 / 坐席 / 天** | 当日有「已接通」记事的**客户去重数** | 用客户数而非记事数，避免对同一客户刷次数 |
| 接通率 | 已接通记事数 / 全部记事数 | < 15% 先洗名单，别加人 |
| SLA 达成率 | 按时跟进客户数 / 应跟进客户数 | 做分级 SLA 之后才有 |
| 客户沉淀率 | 超保护期未跟进 / 在跟客户 | 公海已上线，现在就能算 |
| 回收再分配率 | 回收后被重新领取 / 回收总数 | 长期 < 50% 说明名单本身没价值 |
| 打扰投诉数 | 客户明确要求「不要再打」的条数 | 频次闸门的对照组，闸门收紧后应下降 |

## 六、如果只做两件事

1. **客户分级 + 跟进 SLA**（2 人日）—— 补齐「回来了没跟上」这一段。
2. **目标管理**（2 人日）—— 让 KPI 从「昨天发生了什么」变成「今天还差多少」。

合计 4 人日，不依赖任何外部服务。做完这两件，系统的管理闭环就成立了；
WhatsApp、号码体检、AI 标签都是放大器，可以排在其后。
