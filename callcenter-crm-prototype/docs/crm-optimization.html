外呼 CRM · 马来西亚场景优化建议v2 · 2026-10

前提已修正：不做通话集成（无软电话 / CDR / 录音）、不套用中国法规、限制项全部可调。
① 上一轮最该做的四件事，已经做完了
公海回收（领取上限 / 保护期 / 自动回收 / 跨组审批）、联系频次闸门、角色化首页（主管=KPI、员工=日程）、 马来西亚号码与公司名本地化。全部参数在「系统设置」里可调，不写死。
② 剩下的最大空洞：没有「该跟进而没跟」的度量
公海解决的是「客户被囤着不回来」；但客户回来了、也跟了一次、然后再也不跟，系统不管。 成熟 CRM 用 客户分级 + 跟进 SLA 管这件事，你现在只有「周期重呼」（那是给未接通的）。
③ 没有目标，KPI 只是「昨天发生了什么」
主管看板有 4 个指标，但没有目标值，也没有「距目标还差多少」。坐席不知道今天该打多少， 主管也不知道谁落后。目标管理是投入最小、见效最快的一项。
④ 马来西亚场景最该补的渠道：WhatsApp
马来西亚的商务沟通主战场是 WhatsApp，不是短信也不是邮件。未接通后发一条 WhatsApp 模板消息， 比打第二遍电话更有效，也不增加「打扰」成本。

2本轮已实现（可在系统里直接验证）

公海回收 已完成

客户不再沉淀在坐席名下。
可调启用开关 · 每人持有上限（默认 200）· 保护期（默认 15 天）· 自动回收开关 · 跨组审批开关
行为领取受上限约束；超期且无待办回访才回收；回收写审计；手动「立即执行回收」可随时跑
验证：客户 → 待回收 → 看到「超期 N 天」→ 立即执行回收 → 客户回到公海

联系频次闸门 已完成

控制打扰强度，不是法规要求。
可调总开关 · 统计周期（默认 7 天）· 周期内最多联系（默认 2 次）· 允许时段（默认 09:00–20:00）
行为记事登记、呼叫台保存、呼叫队列生成三处校验；被拦时给出具体原因
验证：客户详情显示「近 7 天已联系 2/2 次」→ 写跟进被拦

角色化首页 已完成

不同角色打开系统该看到不同的东西。

3还该做什么按性价比排序，都不依赖通话数据

客户分级 + 跟进 SLA P0

补齐「回来了但没跟上」这一段。
市面A/B/C 分级，各自跟进时限（A 类 24h、B 类 3 天、C 类 7 天）；超时进预警，连续超时降级或退回公海。
现状客户有 category 字段（A类/B类），但没有任何时限逻辑。
建议给每个等级配 slaHours；slaBreach() 算出超时客户，进主管 KPI 的「异常预警」，同时给坐席生成待办。
验收：A 类客户 24 小时无跟进，坐席与主管同时看到红色预警。约 2 人日

目标管理 P0

KPI 有数，但没人知道「够不够」。
市面日/周/月目标（有效联系数、新增意向、回访完成率），实时完成度 + 坐席排行 + 落后提醒。
现状KPI 卡只有实际值，没有目标值。
建议加 targets 表（人/组/周期/指标）；KPI 卡下加进度条与差额；员工日程顶部显示「今日还差 12 通」。
验收：设「每人每天 60 通」，员工首页实时显示进度。约 2 人日

WhatsApp 触达 P0

马来西亚的商务沟通就在 WhatsApp 里。
市面未接通自动发模板消息（公司名 + 来意 + 回电方式）；客户回复回流成线索；加微/加 WA 状态回写。
现状未接通就只是「未接通」，客户不知道你来过。
建议接 WhatsApp Business API（或先用 wa.me 深链 + 手工确认）；同号码 24h 内只发一次；发送记录写进记事。
验收：未接后一键发送模板消息，记事里出现「已发 WhatsApp」。约 3 人日

数据质量：号码体检 P1

名单质量决定接通率，而接通率决定一切。
市面导入时校验运营商前缀（012 Celcom / 016 Digi / 017 Maxis…）、批量去重、空号/停机标记。
现状只校验「是不是手机号格式」，不判断运营商，也不识别空号。
建议加一张 my_prefixes 表，导入时标注运营商与号段类型；「连续 3 次未接通」自动标为疑似空号进体检页。
验收：导入 500 条名单，立刻看到「无效格式 12 条 / 疑似空号 8 条」。约 2 人日

非通话类 AI：名单清洗 + 意向打分 P1

没有录音也能用 AI，只是不能用「通话质检」那套。
市面按历史跟进结果训练意向分（谁值得先打）；记事文本自动抽取标签（预算/时间/竞品/决策人）。
现状记事是自由文本，无法统计「客户都在顾虑什么」。
建议先做「记事自动打标签」（大模型抽取 3–5 个标签 + 情绪），再做「意向分排序」；不要做通话质检，因为没录音。
验收：记事页能按标签筛选，主管能看到「本月异议 Top 3」。约 4 人日 + 模型成本

移动端 / 离线补记 P2

坐席有时不在工位。
市面响应式网页 + 小程序；离线记事后同步。
现状桌面优先，窄屏只保证不横向溢出。
建议不做原生 App；把「我的日程」和「客户详情」两页做成响应式，够用。
验收：手机浏览器能看完今天的回访并写跟进。约 3 人日

4明确不要做

✕
软电话 / CDR / 录音 / AI 质检。已确认不做通话集成，这一整条链路都不成立。想做的话是另一个项目，不是加功能。
✕
预测式外呼。需要通话链路与实时坐席状态，前提就不存在。
✕
AI 首轮外呼。名单来源不干净时只会更快制造投诉；马来西亚虽然没有营销外呼禁令，但被投诉到 MCMC 一样麻烦。
✕
按中国法规做备案 / 主叫鉴权 / 号码保护（AXB）。本地不适用。若将来跨境拨打中国号码，再单独评估。
✕
复杂商机 / 报价 / 订单 / 合同。你做的是「名单 + 外呼 + 意向筛选」，不是 6 个月长周期销售。
✕
多级组织架构。一层主管→坐席够用；层级一多，数据范围规则会指数级复杂。

5指标：没有通话数据，就用「登记事实」口径必须写死，否则每个人算出来都不一样

北极星：有效联系客户数 / 坐席 / 天
= 当日有「已接通」记事的客户去重数
没有 CDR，只能用登记口径。用「客户去重数」而不是「记事条数」，避免对同一个客户刷次数。
接通率
= 已接通记事数 / 全部记事数
比「呼出量」诚实。低于 15% 说明名单或号码状态有问题，先洗名单，别加人。
SLA 达成率
= 按时跟进客户数 / 应跟进客户数
做分级 SLA 之后才有。它比「今日登记数」更能反映坐席是否在挑客户打。
客户沉淀率
= 超保护期未跟进 / 在跟客户
公海已上线，这个指标现在就能算。它直接暴露「谁在囤客户」。
回收再分配率
= 回收后被重新领取的客户 / 回收客户
衡量公海是否真的在流转。长期低于 50% 说明名单本身没价值，不是机制问题。
打扰投诉数
= 客户明确要求「不要再打」的条数
频次闸门的对照组。闸门收紧后这个数应该下降，不降说明闸门参数不对。

6如果只做两件事

1. 客户分级 + 跟进 SLA —— 2 人日。公海管「不回来看」，SLA 管「回来了没跟上」，两者合起来才是完整的客户资源管理。
2. 目标管理 —— 2 人日。让 KPI 从「昨天发生了什么」变成「今天还差多少」，这是主管每天打开系统最想看到的一句话。
这两件加起来 4 人日，都不依赖任何外部服务，做完之后系统的「管理闭环」就成立了。剩下的 WhatsApp、数据质量、AI 都是放大器，可以排在其后。
