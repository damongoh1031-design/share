# 外呼 CRM · 交互原型 v1.0

单文件可交互原型，用于在写 Go 后端之前验证产品形态、权限模型、客户资产保护与分配流程。
数据存浏览器 `localStorage`，刷新不丢，可一键重置。

- 入口：`prototype/crm-prototype.html`（双击即开，无需服务端）
- 技术：单文件 HTML + 原生 JS，无外部依赖、无 CDN、无网络请求
- 规模：约 3,300 行 / 152 KB；33 位客户、36 条记事、28 条回访、8 个账号

---

## 1. 本轮 7 条要求的落点

| 要求 | 实现位置 | 具体做法 |
|---|---|---|
| 必须有登录画面 | 登录页 | 账号 + 密码表单，错误提示，禁用账号拦截，会话写入 localStorage，退出即清 |
| 用户管理（管理员 / 主管可用） | 用户管理 | 管理员管全部；主管只看本人 + 直属下属，新建账号角色固定为员工、主管固定为自己 |
| 完整的权限管理 | 权限管理 | 18 个权限点 × 3 角色的矩阵，勾选即时生效；另有「个人额外授权」；数据范围按角色固定不可改 |
| 客户列表是重要资产 | 全局 | 手机号默认脱敏、查看完整号码需权限且限次留痕、导出分级（脱敏/明文）、明文仅管理员 |
| 主管分配客户给下属 | 客户列表 | 勾选多条 → 批量分配，可同步转移未完成回访，可给对方发提醒，全程审计 |
| 主管主要通过 XLSX 上传 | 客户列表 / 工作台 | 上传 → 解析预览（成功/重复/失败）→ 选择分配方式（统一 / 平均 / 暂不分配）→ 确认 |
| 客户列表管理：去重、无效号码、周期重呼 | 客户体检 | 三个页签：重复客户合并、无效与异常号码、周期重呼与待回收 |

## 2. 登录账号

| 账号 | 密码 | 角色 | 能做什么 |
|---|---|---|---|
| `admin` | `admin123` | 管理员 | 全部功能、全部客户、导出明文号码、配置权限 |
| `zhaomin` | `123456` | 主管（赵敏） | 团队客户、分配客户、上传名单、管自己的下属、看团队看板 |
| `wangxm` | `123456` | 员工（王小明） | 只看自己的客户，不能导出、不能分配、不能进体检/看板 |

## 3. 8 分钟体验路径

1. `wangxm / 123456` 登录 → 工作台：今日 3 条回访、2 条逾期。
2. 客户 → 手机号是 `138****4567`，点 👁 → 提示「已记录」，侧边栏次数 -1。
3. 客户 → 勾选客户 → 底部只出现「取消选择」（员工没有分配权）。
4. 退出 → `zhaomin / 123456` → 客户：25 位可见，出现「上传 XLSX」「导出」。
5. 勾选 3 位 → 批量分配 → 选下属 → 确认：客户转移 + 审计 + 对方收到提醒。
6. 上传 XLSX → 选「平均分配给下属」→ 确认：5 条自动分给 3 名坐席。
7. 客户体检 → 重复客户（2 组）→ 合并；无效号码（3 条）→ 标记停呼；周期重呼（待重呼 1 / 待回收 1）→ 一键排期。
8. 退出 → `admin / admin123` → 权限管理：把「导出客户」勾给员工 → 切回员工，导出按钮出现。

## 4. 权限模型

三层叠加，缺一不可：

1. **角色权限点**（18 个）：客户查看/新增/编辑/分配/导入/导出/明文导出/合并/标记无效、号码查看、记事、回访、团队统计、账号管理、权限配置、系统设置。
2. **数据范围**（按角色固定）：管理员=全部；主管=本人+直属下属；员工=本人。
3. **个人额外授权**：在角色基础上给某个人临时加权限，授权与撤销都进审计。

前端的按钮显隐只是表现，`can()` 与 `scopeIds()` 同时作用于列表、详情、日历、记事、统计、导出。
员工把 `state.custId` 改成别人的客户，页面直接显示「没有访问权限」。

## 5. 客户资产保护（5 道）

| 措施 | 说明 |
|---|---|
| 默认脱敏 | 列表与详情只显示 `138****4567`，中间四位不落到 DOM |
| 查看留痕 | 点 👁 才显示完整号码，写入 `audit_logs`，每人每日限次（默认 20） |
| 导出分级 | 脱敏导出 / 明文导出分开授权，明文仅管理员，单次上限 200 条，超限截断 |
| 导出留痕 | 记录操作人、时间、范围、条数、是否明文 |
| 越权拦截 | 数据范围校验在渲染前执行，不依赖按钮隐藏 |

## 6. 数据体检规则

| 页签 | 判定 | 可执行动作 |
|---|---|---|
| 重复客户 | 标准化手机号相同（去非数字、去 +86），或姓名 + 公司完全相同 | 选主记录合并：记事与未完成回访转移，重复记录隐藏但可追溯 |
| 无效 / 异常号码 | 人工标记（空号、停机）或格式不符合 `1[3-9]xxxxxxxxx` | 标记无效 → 自动停呼并取消待办；解除需填原因 |
| 周期重呼 | 最近一次结果为未接通/占线、当前无待办：未接次数 < 3 → 待重呼；≥ 3 → 待回收 | 按周期（默认 2 天）排下一次；待回收由主管决定继续或标记无效 |

## 7. 明确模拟、不要当成已实现

| 能力 | 原型状态 | 真实系统要做的事 |
|---|---|---|
| 密码校验 | 明文比对 `pwd` 字段 | bcrypt + 服务端会话 + Token 摘要 + HttpOnly/SameSite/CSRF |
| 数据存储 | localStorage | SQLite（WAL、foreign_keys、busy_timeout）+ 迁移 |
| XLSX 解析 | 固定 8 行预览 | Excelize 解析、体积/行数/解压限制、分批短事务 |
| 导出文件 | 只提示条数与脱敏方式 | 服务端生成 xlsx + 公式注入防护 + 导出审计 |
| 号码脱敏 | 前端截断 | 服务端不返回完整号码，查看时单独接口 + 授权 + 限流 |
| 周期重呼 | 手动点「按周期排期」 | 定时任务扫描未接通客户自动建任务 |
| 提醒 | 预置 5 条 | Go 定时器 30s 扫描 + notifications 表 + 去重键 |
| 备份 | 按钮 + 提示 | `VACUUM INTO` + 保留 14 份 + 恢复验证 |

## 8. 拿这个原型去问的问题

1. 员工看不到完整号码，实际怎么拨号？是走系统外呼，还是必须给查看权限？
2. 每日查看上限 20 次合理吗？按人、按团队还是按客户？
3. 主管需要「导出明文」吗？如果只能脱敏导出，名单怎么流转到别的系统？
4. 批量分配要不要「按数量平均」「按客户等级匹配坐席」这类规则？
5. 导入时重复号码：跳过 / 覆盖空字段 / 生成待确认任务，哪种更贴近实际？
6. 「周期重呼」的间隔应该按客户等级不同吗（A类 1 天，C类 5 天）？
7. 待回收客户由谁处理：主管回收重分，还是自动退回公共池？
8. 合并客户时，如果两条记录分属不同坐席，记事归谁？
9. 主管能创建主管吗？现在只有管理员能。
10. 权限矩阵里哪些点必须拆得更细（例如「改客户状态」单独授权）？

## 9. 与 Go 后端映射

| 原型模块 | 对应后端 |
|---|---|
| 登录 / 会话 | `internal/auth` + `users` / `sessions` 表 |
| 权限矩阵 | `internal/access`（权限点常量 + 角色表 + 数据范围） |
| 客户列表 / 详情 | `internal/customers` + `customers` 表（`phone_normalized` 唯一） |
| 号码查看 / 导出 | `internal/access` + `audit_logs` + 限流 |
| 批量分配 | `internal/customers` 批量服务 + `customer_assignment_logs` |
| 客户体检 | `internal/customers`（去重、无效、周期）+ 定时任务 |
| 导入导出 | `internal/excel` + `import_batches` |
| 记事 / 回访 / 提醒 | `internal/notes` / `internal/callbacks` / `internal/notifications` |
| 审计 | `internal/audit` + `audit_logs` |

`can()` / `scopeIds()` / `canSeeCustomer()` 就是后端数据权限组件的雏形，落地时整体搬到服务端，
每个查询强制拼上范围条件，前端只做展示裁剪。

## 10. 已知限制

- 单浏览器单会话，无并发与乐观锁冲突演示
- 分配与合并是同步内存操作，没有事务回滚
- 提醒为预置数据，不会到点真弹
- 权限矩阵的改动只影响前端渲染，没有服务端二次校验（真实系统必须两边都做）
- 移动端仅保证不横向溢出
