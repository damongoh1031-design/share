# 外呼 CRM · 交互原型 v3.0（马来西亚）

单文件可交互原型，用于在写 Go 后端之前验证产品形态、权限模型、客户池流转与作业流程。
数据存浏览器 `localStorage`，刷新不丢，可一键重置。

- 入口：`prototype/crm-prototype.html`（双击即开，无需服务端）
- 技术：单文件 HTML + 原生 JS，无外部依赖、无 CDN、无网络请求
- 规模：3,610 行 / 255 KB；33 位客户、36 条记事、28 条回访、8 个账号、2 个小组
- 自测：`_test/` 下两套 CDP 回归，**81 条断言全通过、0 页面异常**
- 场景：马来西亚本地外呼团队（号码、公司名、界面语言均已本地化）

---

## 1. v3.0 的六条设计决定

| # | 决定 | 落地方式 |
|---|---|---|
| 1 | **不做通话集成** | 没有软电话、没有 CDR、没有录音。坐席在系统外拨号，回到「呼叫台」登记结果与记事；系统只负责派单、记录、流转 |
| 2 | **不套用中国法规** | 不做号码备案、不做主叫鉴权、不做营销外呼限制。所有「限制」都是企业自设的**打扰强度控制**，可随时关掉 |
| 3 | **联系频次闸门可调** | 系统设置 → 统计周期（天）/ 周期内最多联系（次）/ 允许时段起止 / 总开关 |
| 4 | **公海回收可调** | 系统设置 → 启用公海池 / 每人持有上限 / 保护期天数 / 自动回收 / 跨组流转需审批 |
| 5 | **主管主页 = KPI** | 登录后直接进 KPI 看板：4 个核心指标 + 客户池预警 + 下属待办 + 团队动态 |
| 6 | **员工主页 = 日程** | 登录后直接进「我的日程」：4 个个人指标 + 回访日历 + 今日待回访 + 逾期未回访 |

> 第 1、2 条是这一轮最大的改动：删掉了通话与合规的假设，系统变成一台**纯名单作业机**——
> 名单进来 → 分配/领取 → 排回访 → 登记结果 → 超期回收 → 再分配。

## 2. 角色化首页

| 角色 | 首页 | 第一屏内容 |
|---|---|---|
| 主管 / 管理员 | **KPI 看板** | 今日待回访 / 逾期 / 今日已登记 / 可见客户；客户池（公海·待回收·待审批）；客户资产待处理；今日回访与逾期列表；最近记事 |
| 员工 | **我的日程** | 今日待回访 / 逾期 / 近 7 日已完成 / 我名下客户；月历（可切列表）；今日待回访列表；逾期列表 |

员工的导航里**没有** KPI 看板、客户体检、主管看板、用户管理——不是隐藏按钮，是菜单里就没有。
员工若手动把 `state.view` 改成 `dashboard`，`viewHtml()` 会把他送回日程。

## 3. 客户池：公海 / 私海 / 回收 / 跨组

```
公海(public)  ──领取──▶  私海(private, 有 ownerId, claimedAt)
     ▲                        │
     │                        │ 保护期内无有效跟进（且无待办回访）
     └────────自动回收────────┘

私海 ──申请跨组流转──▶ 待审批 ──同意──▶ 目标组长名下（保护期重新起算）
```

| 机制 | 默认值 | 可调位置 | 说明 |
|---|---|---|---|
| 启用公海 | 开 | 系统设置 | 关掉后客户只能由主管分配 |
| 每人持有上限 | 200 位 | 系统设置 | 达到上限后领取被拒，批量领取会跳过并提示 |
| 保护期 | 15 天 | 系统设置 | 从「领取时间」或「最后一次有效跟进」起算，取较晚者 |
| 自动回收 | 开 | 系统设置 | 超期且**没有待办回访**才回收，避免抽走正在推进的客户 |
| 跨组流转审批 | 开 | 系统设置 | 关掉后申请直接生效，不留审批单 |

**客户页三个页签**：客户（私海）· 公海（可领取）· 待回收（超期）。
行内操作：公海行有「领取」，待回收行有「超期 N 天 + 退回公海」；勾选后可批量领取 / 批量退回。

**审批页**（主管/管理员）：待审批列表 + 审批历史，同意后客户直接归到目标组长名下，未完成回访一并转过去。

## 4. 联系频次闸门

| 参数 | 默认 | 作用 |
|---|---|---|
| 总开关 | 开 | 关掉后完全不限制 |
| 统计周期 | 7 天 | 按记事时间回溯 |
| 周期内最多联系 | 2 次 | 达到上限即拦截 |
| 允许时段 | 09:00–20:00 | 不在时段内拦截 |

拦截点有三处：**记事登记**、**呼叫台保存**、**呼叫队列生成**（频次已满的客户不进队列）。
被拦时给出具体原因，例如「该号码 7 天内已联系 2 次，达到上限 2 次」。

> 这是**打扰强度控制**，不是法规要求。马来西亚没有类似中国的营销外呼禁令；
> 客户数据仍受 PDPA 2010 约束（告知目的、可要求更正/删除），这是数据侧的事，与本闸门无关。

## 6. 权限模型（21 个权限点）

三层叠加，缺一不可：

1. **角色权限点**：客户查看/新增/编辑/分配/导入/导出/明文导出/合并/标记无效/号码查看、记事、回访、团队统计、账号管理、权限配置、系统设置，外加本轮的**客户池三点**：领取公海客户 / 退回·回收 / 审批跨组流转。
2. **数据范围**：管理员=全部；主管=本人+直属下属；员工=本人。**公海对所有人开放**（这是它存在的意义）。
3. **个人额外授权**：临时给某个人加权限，授权与撤销都进审计。

| 角色 | 客户池权限 |
|---|---|
| 员工 | 领取公海客户 |
| 主管 | 领取 + 退回/回收 + 审批跨组 |
| 管理员 | 全部 |

## 8. 10 分钟体验路径

1. `wangxm / 123456` → 落在**我的日程**：今日 3 条待回访、2 条逾期，日历上标着时间。
2. 客户 → **公海（3）** → 点「领取」：客户进你名下，保护期 15 天开始算。
3. 客户 → **待回收（1）** → 看到「超期 10 天」→ 点「立即执行回收」：客户回到公海。
4. 客户详情 → 顶部显示「近 7 天已联系 2/2 次」→ 点「写跟进」会被拦下（频次已满）。
5. 系统设置 → 把「周期内最多联系」改成 99 → 回去再写一次，通过。
6. 退出 → `zhaomin / 123456` → 落在 **KPI 看板**：客户池三格（公海/待回收/待审批）可点。
7. 客户详情 → 「申请转组」→ 选华南二组 → 提交 → 侧栏「审批」出现 1 条待办。
8. 切到 `sunyue / 123456`（目标组组长）→ 审批 → 同意 → 客户转到孙悦名下。
9. 顶栏 `Aa` → 切浅色 / 特大字 / English：整站跟着变。
10. 系统设置 → 把「每人持有上限」改成 3 → 回客户页批量领取，会看到「因达到上限跳过」。

## 10. 明确模拟、不要当成已实现

| 能力 | 原型状态 | 真实系统要做的事 |
|---|---|---|
| 拨号 | 完全在系统外 | 若要接软电话，需要 SIP 中继；本轮明确不做 |
| 密码 | 明文比对 `pwd` | bcrypt + 服务端会话 + 强制改密服务端拦截 |
| 数据存储 | localStorage | SQLite（WAL）+ 迁移；多坐席并发写要单写队列 |
| 自动回收 | 进入页面时扫描 | 定时任务（cron/worker）每天跑一次，结果写审计 |
| 跨组审批 | 单级审批 | 可加多级、可加抄送；审批超时要能升级提醒 |
| 提醒 | 站内 + 生成时插入 | 定时器扫描 + 多通道（邮件/WhatsApp） |
| 备份 | 按钮 + 提示 | `VACUUM INTO` + 保留 14 份 + 异地副本 |
| 号码归属地 | 不判断 | 马来西亚可用运营商前缀表判断 Celcom/Digi/Maxis 等 |

## 11. 已知限制

- 单浏览器单会话，无并发与乐观锁冲突演示
- 公海是**全公司共享**，不按小组隔离；如果要按组隔离，需要给客户加 `poolScope`
- 保护期只按「最后一次记事」算，没有区分「有效跟进」和「无效尝试」
- 自动回收只在打开客户页/待回收页时触发，不是真正的定时任务
- 中英切换只覆盖界面文案，客户姓名与公司名保持原样
- 移动端仅保证不横向溢出

## 12. 下一步建议（详见 `docs/CRM-OPTIMIZATION.md`）

1. **客户分级 + 跟进 SLA**（A/B/C 不同时限）——公海解决「不回来看」，SLA 解决「回来了但没跟上」
2. **目标管理**（每人每天多少通）——现在 KPI 只有结果，没有目标
3. **WhatsApp 集成**——马来西亚 WhatsApp 是主渠道，比短信更实用
4. **数据质量**：导入时校验号码运营商前缀、批量去重、空号标记
