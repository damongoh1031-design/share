# 外呼 CRM · 交互原型 v2.0

单文件可交互原型，用于在写 Go 后端之前验证产品形态、权限模型、客户资产保护、分配流程与呼叫作业。
数据存浏览器 `localStorage`，刷新不丢，可一键重置。

- 入口：`prototype/crm-prototype.html`（双击即开，无需服务端）
- 技术：单文件 HTML + 原生 JS，无外部依赖、无 CDN、无网络请求
- 规模：3,194 行 / 228 KB；33 位客户、36 条记事、28 条回访、8 个账号、2 个小组、7 天登录日志
- 自测：`_test/` 下有 CDP 回归脚本，51 条断言全部通过、0 页面异常

| 2 | 字号：小 / 中 / 大 / 特大 | 顶栏 `Aa` → 字号 | `html[data-fs]` + `--fs` 系数（0.92 / 1 / 1.12 / 1.26），全站 300+ 处字号跟随 |

| 4 | 自定义密码 | 用户管理 → 修改我的密码 | 校验当前密码、长度 ≥ 6、两次一致、不得与原密码相同 |
| 5 | 员工能看电话，不能导出 | 客户列表 | 员工可见脱敏号码，可点 👁 查看完整号码（留痕 + 限次）；导出按钮置灰并说明原因 |
| 6 | 呼叫界面：资料 + 历史记事，登记后跳下一位 | 呼叫台 | 左栏客户资料 / 号码 / 累计呼叫 / 结果按钮 / 记事；右栏历史记事 + 队列预览 + 本次会话统计；保存即跳下一位，键盘 1–5 选结果、Enter 保存 |
| 7 | 主管可上传 + 下载客户资料 | 客户列表 | 「上传 XLSX」解析预览后导入；「导出」按脱敏/明文分级，单次上限 200 条 |

| 10 | 重设组员密码 | 用户管理 → 重设密码 | 主管只能重设本组员工；生成临时密码；被重设者下次登录强制改密，弹窗不可关闭 |
| 11 | 管理员可改全部人密码 | 用户管理 | 管理员对任意账号显示「重设密码」，含主管与管理员自己（自己走「修改我的密码」） |
| 12 | 管理员查看全部人日志 | 日志 | 登录日志 + 操作日志双页签，管理员全部账号，主管本人及下属 |
| 13 | 权限管理界面 + 转移主管的组员 | 权限管理 | 18 权限点 × 3 角色矩阵 + 个人额外授权 + 数据范围说明；顶部「小组管理」可改名、换组长、转移组员 |
| 14 | 设置小组名 | 权限管理 → 小组管理 | 新建/改名/换组长；小组名显示在用户管理、权限管理、侧边栏与登录后的身份区 |

## 3. 10 分钟体验路径

1. `wangxm / 123456` 登录 → 工作台：今日 3 条回访、2 条逾期。
2. 呼叫台 → 看到客户资料 + 历史记事 → 按 `1` 选「已接通」→ `Enter`：记事写入、回访完成、自动跳下一位。
3. 客户 → 手机号是 `138****4567`，点 👁 → 提示「已记录」，侧边栏剩余次数 -1；「导出」是灰的。
4. 顶栏 `Aa` → 切「浅色」「特大」「English」：整站变浅色、字变大、界面变英文。
5. 退出 → `zhaomin / 123456` → 客户：出现「上传 XLSX」「导出」「按数量分配」。
6. 按数量分配 → 来源「团队全部客户」→ 数量 50 → 随机 → 勾 3 名组员 → 开始分配：三人各拿到若干，审计有记录，每人收到提醒。
7. 用户管理 → 王小明一行点「重设密码」→ 拿到临时密码 `CrmXXXXXX` → 用它在登录页登录 → 被强制改密。
8. 日志 → 登录日志：只有赵敏自己 + 3 名下属的记录（王小明、李静、陈涛），孙悦组的人看不到。
9. 退出 → `admin / admin123` → 日志：8 个账号全量记录；权限管理：改名小组、把王小明转到华南二组。
10. 权限管理 → 把「导出客户」勾给员工 → 切回员工，导出按钮出现（权限点即时生效）。

## 4. 权限模型

三层叠加，缺一不可：

1. **角色权限点**（18 个）：客户查看/新增/编辑/分配/导入/导出/明文导出/合并/标记无效、号码查看、记事、回访、团队统计、账号管理、权限配置、系统设置。
2. **数据范围**（按角色固定）：管理员=全部；主管=本人+直属下属；员工=本人。
3. **个人额外授权**：在角色基础上给某个人临时加权限，授权与撤销都进审计。

前端的按钮显隐只是表现，`can()` 与 `scopeIds()` 同时作用于列表、详情、日历、记事、统计、导出、日志。
员工把 `state.custId` 改成别人的客户，页面直接显示「没有访问权限」。

密码相关的三条边界：

| 操作者 | 能改谁的密码 |
|---|---|
| 员工 | 只有自己（需验证当前密码） |
| 主管 | 自己 + 本组员工；不能改别的组、不能改主管/管理员 |
| 管理员 | 全部账号（改自己走「修改我的密码」） |

被他人重设后 `mustChange = true`：下次登录弹出强制改密窗口，无关闭按钮，只能改密或退出。

## 5. 客户资产保护（5 道）

| 措施 | 说明 |
|---|---|
| 默认脱敏 | 列表与详情只显示 `138****4567`，中间四位不落到 DOM |
| 查看留痕 | 点 👁 才显示完整号码，写入 `audit_logs`，每人每日限次（默认 20） |
| 导出分级 | 脱敏导出 / 明文导出分开授权，明文仅管理员，单次上限 200 条，超限截断 |
| 导出留痕 | 记录操作人、时间、范围、条数、是否明文 |
| 越权拦截 | 数据范围校验在渲染前执行，不依赖按钮隐藏 |

员工视角：能看号码、能拨号、能记事，但「导出」永远不可用，除非管理员在权限管理里单独授权。

## 6. 数据体检规则

| 页签 | 判定 | 可执行动作 |
|---|---|---|
| 重复客户 | 标准化手机号相同（去非数字、去 +86），或姓名 + 公司完全相同 | 选主记录合并：记事与未完成回访转移，重复记录隐藏但可追溯 |
| 无效 / 异常号码 | 人工标记（空号、停机）或格式不符合 `1[3-9]xxxxxxxxx` | 标记无效 → 自动停呼并取消待办；解除需填原因 |
| 周期重呼 | 最近一次结果为未接通/占线、当前无待办：未接次数 < 3 → 待重呼；≥ 3 → 待回收 | 按周期（默认 2 天）排下一次；待回收由主管决定继续或标记无效 |

呼叫台与周期重呼共用同一套规则：登记「无人接听 / 占线」后，若未接次数未到上限，系统自动排下一次回访，坐席不用手工建任务。

## 8. 明确模拟、不要当成已实现

| 能力 | 原型状态 | 真实系统要做的事 |
|---|---|---|
| 密码校验 | 明文比对 `pwd` 字段 | bcrypt + 服务端会话 + Token 摘要 + HttpOnly/SameSite/CSRF |
| 强制改密 | 前端弹窗拦截 | 服务端标记 `must_change_password`，未改密前所有接口返回 403 |
| 数据存储 | localStorage | SQLite（WAL、foreign_keys、busy_timeout）+ 迁移 |
| XLSX 解析 | 固定 8 行预览 | Excelize 解析、体积/行数/解压限制、分批短事务 |
| 导出文件 | 只提示条数与脱敏方式 | 服务端生成 xlsx + 公式注入防护 + 导出审计 |
| 号码脱敏 | 前端截断 | 服务端不返回完整号码，查看时单独接口 + 授权 + 限流 |
| 周期重呼 | 登记时按规则建任务 | 定时任务扫描未接通客户自动建任务 |
| 提醒 | 预置 5 条 + 分配时新增 | Go 定时器 30s 扫描 + notifications 表 + 去重键 |
| 登录日志 | 种子生成 7 天 | 每次登录/失败写 `login_logs`，按 IP 失败限速、锁定 |
| 备份 | 按钮 + 提示 | `VACUUM INTO` + 保留 14 份 + 恢复验证 |

## 9. 拿这个原型去问的问题

1. 员工看不到完整号码，实际怎么拨号？走系统外呼，还是必须给查看权限？
2. 每日查看上限 20 次合理吗？按人、按团队还是按客户？
3. 主管需要「导出明文」吗？如果只能脱敏导出，名单怎么流转到别的系统？
4. 按数量分配时，是**从公共池取新名单**，还是**在现有客户里重新分摊**？原型两种都留了口子。
5. 分配要不要「按客户等级匹配坐席」「按空闲度均摊」这类规则？
6. 组员转移后，他名下的客户跟着走还是留在原组？（原型：客户跟人走，组长只管可见范围）
7. 一个员工能属于多个小组吗？现在是一对一。
8. 主管能不能创建主管、能不能改别人的组员？现在只有管理员能。
9. 「周期重呼」的间隔应该按客户等级不同吗（A类 1 天，C类 5 天）？
10. 待回收客户由谁处理：主管回收重分，还是自动退回公共池？

## 10. 与 Go 后端映射

| 原型模块 | 对应后端 |
|---|---|
| 登录 / 会话 / 强制改密 | `internal/auth` + `users` / `sessions` 表（`must_change_password`） |
| 权限矩阵 | `internal/access`（权限点常量 + 角色表 + 数据范围） |
| 小组 | `teams` 表 + `users.team_id`，或直接沿用 `manager_id` 层级 |
| 客户列表 / 详情 | `internal/customers` + `customers` 表（`phone_normalized` 唯一） |
| 号码查看 / 导出 | `internal/access` + `audit_logs` + 限流 |
| 批量分配 / 按数量分配 | `internal/customers` 批量服务 + `customer_assignment_logs` |
| 呼叫台 | `internal/notes` 写入 + `callbacks` 完成 + 周期任务生成 |
| 客户体检 | `internal/customers`（去重、无效、周期）+ 定时任务 |
| 导入导出 | `internal/excel` + `import_batches` |
| 登录日志 | `login_logs`（时间、账号、结果、IP、设备、说明） |
| 审计 | `internal/audit` + `audit_logs` |

`can()` / `scopeIds()` / `canSeeCustomer()` 就是后端数据权限组件的雏形，落地时整体搬到服务端，
每个查询强制拼上范围条件，前端只做展示裁剪。

## 11. 回归自测

```bash
# 在 prototype/ 目录
node _test/cdp.mjs "$PWD/crm-prototype.html" ./suite.mjs   # 51 条断言
node _test/cdp.mjs "$PWD/crm-prototype.html" ./shots.mjs   # 重出 14 张截图
```

脚本用 headless Chrome + CDP 驱动，覆盖：登录、11 个页面渲染、4 套主题、4 档字号、中英切换、
呼叫台登记跳转、员工导出禁用、按数量分配、重设密码与强制改密、日志数据范围、小组改名与组员转移、自定义密码。
断言失败或出现 `Runtime.exceptionThrown` 会直接打印。

## 12. 已知限制

- 单浏览器单会话，无并发与乐观锁冲突演示
- 分配与合并是同步内存操作，没有事务回滚
- 提醒为预置数据，不会到点真弹
- 权限矩阵的改动只影响前端渲染，没有服务端二次校验（真实系统必须两边都做）
- 中英切换只覆盖界面文案，业务数据保持原语言
- 移动端仅保证不横向溢出
