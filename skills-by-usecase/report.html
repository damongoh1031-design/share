① 一个用途只装一个

重叠的 skill 会让 agent 重复劳动、浪费 context，还会互相干扰——比如两个 TDD skill 都要求「先写测试」，agent 会不知道该听谁的。

② 先看用途，再看安装量

安装量高只说明流行，不代表适合你的用途。find-skills（3.8M）是入口，但它在「写测试」这个用途上毫无用处。

③ 装之前必看安全审计

实测 50 条审计记录：Gen Agent Trust Hub 有 3 个 Med Risk、Snyk 有 8 个 Med Risk + 1 个 High Risk。详见第五章。

一个必须注意的「隐性重复」

这两个不是重复，是配合关系——要一起装
  • codebase-design = 词汇与纪律（module / interface / depth / seam / adapter / leverage / locality）
  • improve-codebase-architecture = 执行体检，且它明确要求先调用 codebase-design 拿词汇

原文："Call the Skill tool with 'codebase-design' for the architecture vocabulary... Use these terms exactly in every suggestion, and don't drift into 'component,' 'service,' 'API,' or 'boundary.'"

同理，这三组也是「互补非重复」
  • grill-me（对齐需求）↔ grill-with-docs（对齐需求 + 建 GLOSSARY.md/ADR）
  • frontend-design（创造好看的设计）↔ web-design-guidelines（审查是否符合规范）
  • impeccable/critique（批评）↔ impeccable/polish（打磨）

四4 个值得单独说的 skill

4.1 caveman —— 唯一有第三方学术验证的省钱 skill

来源结果
Adobe Research（CAVEWOMAN 论文引用本仓库）每模型成本降 1.4-2.4 倍，最高 3 倍
Elasticsearch Labs响应 token 少 63.6%，"Zero information loss"
JetBrains（86 个真实编码任务配对 A/B）无质量损失（p = 0.82），输出 token 少 8.5%

六个可独立开关的组件：Say less（63→20 token）、Read less（input token 少 33.2%）、Auto（比 Opus xhigh 便宜 54%）、Blocks（397→76 token）、Waste fixes、Browse（页面小 129.8 倍）

一条重要设计边界

"Adobe: cavemanning your prompt makes answers worse, so caveman never touches your prompt." —— 它只压缩输出和工具返回，从不改你的输入。

4.2 ui-ux-pro-max —— 设计参考的数据量最大

50+ 设计风格 · 161 调色板 · 57 字体配对 · 99 UX 指南 · 10 技术栈（React / Next.js / Vue / Svelte / SwiftUI / RN / Flutter / Tailwind / shadcn / HTML）· 25 种图表 · 161 种产品类型模式

覆盖：网站 / 落地页 / 仪表盘 / 管理后台 / 电商 / SaaS / 作品集 / 博客 / 移动应用，含组件库（按钮、模态、表单、表格、卡片、图表）

它和 frontend-design 的区别：frontend-design 教 agent「怎么做出有品味的选择」，ui-ux-pro-max 给 agent「一个可查询的设计数据库」。两者可共存。

命令用途

5.3 一条实用的安全原则

「Med Risk」在 skills.sh 上几乎等同于「这个 skill 会做有副作用的操作」

纯文本指令型 skill（如 grill-me、tdd）基本都是 Safe/Low Risk；凡是 Med Risk 的，通常意味着它会：执行 shell 命令、调用外部 API、往第三方平台写数据、或安装其他 skill。

这不是坏事——agent-browser 如果装成 Safe 反而说明它没在做它该做的事。关键是自己知道它要什么权限。
