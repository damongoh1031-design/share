### 1. Graphify-Labs/graphify —— 代码上下文押注显式图谱，而不是向量库

**事件**：Python 语言榜 daily 第 1，+626，总 128,443，forks 12,379，Apache-2.0，建于 2026-04-03，最新 v0.9.92（2026-10-16）。**仓库已从个人账号 `safishamsi/graphify` 转到组织 `Graphify-Labs/graphify`（301 已实测）**，但 README 徽章仍指向旧路径。

**核心内容**
- 定位：把代码库连同文档、SQL schema、配置、PDF、截图，编成一张可查询的知识图谱；形态是 **Claude Code 的 `/graphify` 技能**，同时提供 Cursor / Codex / Gemini CLI 的技能与 MCP stdio 入口。
- 抽取分两条路：代码走 **tree-sitter AST + 调用图**（py/ts/js/go/rs/java/c/cpp/rb/cs/kt/scala/php）；文档/图片走模型抽取（Claude vision）。
- 技术栈：NetworkX + Leiden（graspologic）+ tree-sitter + vis.js，**本地跑，不需要 Neo4j、不需要服务器、没有向量库**。
- 每条边打标签：`EXTRACTED` / `INFERRED` / `AMBIGUOUS`——"哪些是抽出来的，哪些是猜的"是显式字段。
- 产出：`graph.html`（交互图）、`obsidian/`（可直接当 vault）、`wiki/`（每个社区一篇文章，给 agent 按文件爬）、`GRAPH_REPORT.md`、`graph.json`、`cache/`（SHA256，只重算改动文件）。
- 增量机制：`--watch` 下代码保存触发纯 AST 重建（不调模型），文档/图片变更只提示跑 `--update`；`graphify hook install` 装 post-commit 钩子，每次提交重建。
- 自报压缩比（附 worked example 可复跑）：52 文件混合语料 **71.5x**、4 文件 5.4x、6 文件 ~1x。

**为什么值得关注**
- 代码 RAG 的真实失败点是"检索到片段但不知道边"：谁调用谁、哪个配置项绑到哪个 schema。显式图 + 边置信度标签把"不可见的检索"变成可审计对象。
- 它自己承认小仓库无收益（6 文件 ~1x）——图的价值在**结构**不在压缩，这比"一律 70 倍"的宣传可信。
- 分发形态值得记一笔：不是 SDK，而是给 4 个 harness 各写一份技能。上下文基础设施正在以 skill 为单位落地。

**注意**：v0.9.x，三天内两次 bump AST cache schema（0.9.91 / 0.9.92），升级后首次构建全量重抽；PyPI 包名仍是占位 `graphifyy`，因为 `graphify` 名字在回收中——**装包时别装错同名包**。

### 2. NVlabs/ASPIRE —— 把"训练"换成"技能精炼"

**事件**：Python 榜 daily +94，总 554，Apache-2.0，建于 2026-07-08，论文 arXiv 2607.00272。README 公告 **ASPIRE v1.0（2026-10）**：能解魔方，LIBERO-Pro 的 80 个 Goal/Object/Spatial/Long 任务达 **99%** 成功率。

**核心内容**
- 三个重新定义：训练 = 技能精炼（不是梯度下降）；"训练好的模型" = 一个传感器运动技能仓库（不是浮点权重）；"分布式训练" = 一组各练一个技能的 agent（不是切分 minibatch）。
- 数据：10 个 LIBERO-Pro 任务上，成功率随底座模型从 **15%（GPT-6 Luna）→ 99%（Claude Opus 5.5）**；跨 LIBERO-Pro / Robosuite / BEHAVIOR-1K，Opus 5.5 每个任务 97–100%。作者强调最强模型不是最贵的，给了 cost/success 前沿线。
- 真机：YAM 站，跨本体 sim-to-real 收桌、在线真机学习解魔方、叠杯、拧瓶盖倒水、装药丸拧瓶盖。
- **复现流程本身就是 agent 技能**：`.claude/skills/`（iterative-debugging、evosearch）与 `.codex/skills/` 两套；真机走 `AGENTS.md` + System 2 操作手册，仿真跑不需要。
- 明确要求 agent 在执行前先报告：需要几张 GPU、凭证、gated 权重（SAM3）、服务、预计时长、seed 划分、输出路径，**等确认再跑**。

**为什么值得关注**
- 这是"技能"作为能力载体的最强证据：产物不是权重而是可读、可 diff、可复用的技能文件；连论文复现都以技能形式交付。
- 对做 agent 的人来说，`iterative-debugging` 这类技能是可直接借用的范式——把"跑→读失败→改→再跑"写成技能，而不是写进 prompt。
- README 自带安全声明：**会执行模型生成的 Python（完整 import 权限），trial 进程与 watchdog 不是安全沙箱**；仿真 agent 绝不能碰真机。

**注意**：真机那三条 recipe 是"从演示会话蒸馏"的，不是新一轮真机验证；benchmark 数字为作者自报。

### 3. TauricResearch/TradingAgents v0.7.0 —— 订阅账号变成 provider

**事件**：Python 榜 daily +222，总 111,922，forks 21,618。v0.7.0 发布于 **2026-10-16 21:38 UTC**。

**核心内容**
- 新增 `chatgpt` provider：**用 ChatGPT Plus / Pro 订阅跑，不用 API key**，走 OpenAI 给开源应用的登录流程。CLI 里选 "Subscription"；无人值守用 `llm_provider="chatgpt"`，先 `tradingagents login chatgpt` 登录一次，`logout chatgpt` 撤销授权。
- 回测口径改了：**从每次决策之后的第一个收盘价开始计分**，消除前视偏差——这是量化框架里最容易糊弄过去的一处。
- CLI 启动时提示有更新版本，并给出与安装方式匹配的升级命令；每个 GitHub release 附 wheel。

**为什么值得关注**
- 成本模型从"按 token 付费"变成"按月订阅"，对高频跑多 agent 的场景是数量级差异。框架层开始假设"用户可能没有 API key，但有订阅"。
- 这也是 ToS 灰区：把消费级订阅接进自动化框架，平台侧态度随时可能变。个人用可以，别当生产依赖。
- "回测从决策后第一个收盘价计分"这个细节，比多接一家 provider 更有价值——它决定了回测数字能不能信。

- 这两个项目都有 WebUI、多语言、`check-models` 批测脚本——不再是脚本，是产品。
- 风险落在使用者身上：ToS 违约、账号封禁、上游随时改协议。只适合个人折腾，不进生产。

### 8. thesysdev/openui —— 生成式 UI 的竞争下沉到"输出语言"

**为什么值得关注**

**注意**：`lang-core` 已 1.0，但各框架 runtime 还在 0.4.x，版本矩阵不齐；跨框架行为一致性要自己测。

**核心内容**
- **多集群 Kubernetes 不再需要 Enterprise license**（原本是商业版功能下放）。
- Fleet 卡片：集群健康、k8s 版本、Node/Pod ready、告警、问题、快照状态；可跳转单集群 dashboard、切换集群、分享直达链接。
- **一个集群不可达时，其他集群照常可用**，故障集群单独显示状态 + Retry。
- 调查按集群定向：web chat 与 CLI 里选集群，用**只读** k8s 工具做对比；引用能跳回正确 dashboard。
- 审批门控的动作**绑定目标集群**，且 action 凭证与 reader 凭证分离。
- 实时 Pod 日志跟随所选集群/Pod/容器。

**为什么值得关注**
- AI SRE 的定位在退：从"自动修"退到"帮你取证、把动作关在门里"。这是能落地的形态——事故现场最缺的是证据链，不是自动执行。
- reader / action 凭证分离 + 动作绑定集群，是多集群下最容易被忽略的正确细节。
- 商业策略信号：原本 Enterprise 的功能下放到开源版。
