### 1. stablyai/orca —— 今日全站第二增幅，把"多 Agent 并行"做成桌面工作台

**事件**：`main:daily` 今日 **+25,115**（总 97,067），今日 05:52 UTC 刚发 **v1.4.230**。上午一期只在速览里给了一行"按日发版"，实际它是今天主榜第二大增幅。

**核心内容**
- 定位一句话：*"Run Codex, ClaudeCode, OpenCode or Pi side-by-side — each in its own worktree, tracked in one place."*
- **支持 33 家 CLI Agent**（README 逐个列 logo）：Claude Code / Codex / Grok / Cursor / GitHub Copilot / Muse / DeepSeek Harness / ZCode / OpenCode / MiMo Code / Amp / OpenClaude / Antigravity / Pi / oh-my-pi / Hermes / Devin / Goose / Auggie / Charm / Cline / **CodeBuddy** / Codebuff / Kimi / Kiro / Mistral Vibe / Qwen Code / Rovo Dev … 结尾一句 *"if it runs in a terminal, it runs in Orca"*。
- **Parallel Worktrees**：一个 prompt 扇出到 5 个 Agent，各自独立 git worktree，比完再合并赢家。
- **Mobile Companion**（iOS App Store + Android APK）：Agent 跑完推通知，手机上直接回一句继续。
- **Design Mode / 标注 AI diff / 拖文件给 Agent / 终端分屏 / SSH worktree**。
- **Account switcher + usage tracking**：看 Claude、Codex 的额度和限流重置时间，**热切换账号不用重新登录**。
- **Orca CLI**：`orca worktree create`、`snapshot`、`click`、`fill`——Agent 也能反过来驱动 Orca。
- MIT，macOS / Windows / Linux，Homebrew + AUR，**签名构建**单独一节。

**值得关注的原因**
- 这是「多 harness 统一控制面」这条线**第一次从 CLI/代理层升到完整桌面工作台**。对照：cc-switch（10-12 期）管 10 个 CLI 的 endpoint 切换，Orca 管 33 个 CLI 的**并行执行 + 结果比较**。控制面从"配置"上移到"调度"。
- "一个 prompt 扇出 5 个 worktree 再择优合并"把**多 Agent 从架构问题降级成操作问题**——不需要写编排代码，人肉选赢家。这和 10-13 期 Game Studios 的负面实证（多 Agent 编排的双盲评排在最后）形成互补：Orca 不解决"哪个 Agent 更好"，只解决"让你同时看到 5 个"。
- 额度热切换是**订阅额度工程化的第四种形态**（前三种：TradingAgents 把订阅接成 provider、OmniRoute 调度免费额度、opencode2api 指纹伪装）。它把"多个账号"变成一等的 UI 功能。

### 2. github/gh-aw —— GitHub 官方把 Agent 编进 Actions，并主动撤回有漏洞的版本

**事件**：`langM:go` 本月 **+302**（总 5,419，596 forks，MIT），最新 **v0.92.0（10-15）**。README 顶部一条 NOTE 直接写明安全事件。

**核心内容**
- **形态**：`gh` CLI 扩展（`gh extension install github/gh-aw`）。一个 agentic workflow = **YAML frontmatter（触发器/权限/工具/引擎）+ Markdown 正文（让 Agent 干什么）**，`gh aw compile` 校验后生成标准 `.lock.yml` 交给 GitHub Actions 跑。
- **官方立场写得很清楚**：确定性的构建/测试/lint/部署**继续用传统 Actions**；只有需要"推理或解释"的任务（issue 分诊、PR 评审、CI 失败归因、文档维护、依赖分析、仓库报表）才加 Agent。*"complements existing CI/CD; it does not replace it."*
- **内置 5 个引擎**：GitHub Copilot、Claude Code、OpenAI Codex、Google Gemini、Pi。
- **安全模型三件套**：Agent job **默认只读 + 沙箱**；写操作不直接执行，先缓冲进 **safe-outputs**，校验后在**单独 job 里用受限权限**落地；作者仍需自查权限、工具、网络、产物。
- **安全公告**：`>= 0.83.3, < 0.85.4` 的版本因漏洞**被整批撤回**（GHSA-8h78-hpm7-29gg）。当前 v0.92.0 已越过该区间。
- 面向 Agent 的入口做全了：`llms.txt`、`llms-full.txt`、`ai/summary.json`。

**值得关注的原因**
- **平台方第一次给 Agent 定"能写什么"的边界，而不是给能力**。safe-outputs 的本质是"把写操作从 Agent 进程里拿出来，换一个受限身份的 job 去执行"——这与 mxc 的策略面、agent-sandbox 的编排面、litebox 的内核面是同一条思路的第 4 层：**权限面**。
- **"确定性归 Actions，推理归 Agent"是迄今最清楚的分工表述**，可直接抄进团队规范。前几期看到的都是"Agent 什么都干"，这里是官方明确划线。
- 撤回 0.83.3–0.85.4 是**诚实披露的新等级**：不是修完发版，而是把整段版本标记为不可用。这条比任何 changelog 都更能说明 Agent 工作流的攻击面有多实在。

### 3. microsoft/playwright-cli —— 微软官方下场说：编码 Agent 该用 CLI，不该用 MCP

**事件**：`langM:javascript` 本月 **+1,006**（总 14,355，822 forks，Apache-2.0），最新 v0.1.22（09-28）。同门还有 `microsoft/playwright-mcp`，官方在两个项目之间做了明确取舍。

**核心内容**
- README 第一节就是 **Playwright CLI vs Playwright MCP** 的对比，结论直给：
  - **CLI + Skills 适合编码 Agent**：CLI 调用**更省 token**——不把庞大的工具 schema 和冗长的无障碍树塞进上下文，Agent 通过少量专用命令行动。
  - **MCP 仍适合专门场景**：需要持久状态、丰富内省、对页面结构反复推理的循环（探索式自动化、自愈测试、长跑自主流程），此时"维持连续浏览器上下文"值这个 token 成本。
- 安装：`npm i -g @playwright/cli@latest` → `playwright-cli install --skills`。Claude Code / Copilot 直接用本地已装的 skills。
- **可以不用 skill**：把 CLI 丢给 Agent，它自己读 `playwright-cli --help` 就会用。
- 相关 release 细节：`run-code` 脚本可用 timers / fetch / URL / Buffer / crypto / AbortController / TextEncoder，但 **`require` 与 `process` 保持不可用**（权限边界）；`video-start --fps=60`、`--cursor` 动画光标、`--point-style/--highlight-style/--title-style` 控制标记样式。

**值得关注的原因**
- 这是**厂商第一次公开否定自己另一条产品线的主流用法**。过去半年 MCP 被当成"Agent 接工具"的唯一正确答案，官方现在说：高频编码场景里 MCP 的 schema 开销是负担，CLI 才是对的。
- 与本期 gh-aw、orca 的取向完全一致：**Agent 的接口在从"结构化工具协议"往"命令行 + 技能文档"回摆**。判断可复用：*有状态、要反复内省的用 MCP；一次性的、可脚本化的用 CLI。*
- `require`/`process` 不可用而 timers/fetch 可用，是"给能力但按白名单给"的样板——比"沙箱里什么都能跑"更容易审计。

### 4. BuilderIO/agent-native —— Agent 不点 UI，它和 UI 走同一层 action

**事件**：`langM:typescript` 本月 **+2,676**（总 7,433，今日仍在推代码）。仓库创建于 2026-03-12，**无 LICENSE 文件**（README 只说"你建的东西归你"）。

**核心内容**
- 定位：**TypeScript 的 agentic 应用框架**——"把每个能力定义成一次 action，Agent 拿它当 tool，UI 从代码里调它"。
- 三条共享：
  - **共享 action**：一个 `defineAction` 同时暴露给 UI、Agent、HTTP、**MCP**、**A2A**、CLI，走同一套校验与权限。
  - **共享数据**：Agent 干的活出现在 UI 里，UI 干的活 Agent 能看到。
  - **共享应用状态**：Agent 收到当前页面、选中记录、当前视图。
- **关键设计句**：*"The agent does not click through the UI. It works through the same action layer as the UI."* —— 不做 computer-use 式的点屏幕。
- 脚手架：`npx --yes @agent-native/core@latest create my-agent --standalone --template chat`。
- 自带：Agent chat、认证与权限、skills 与 memory、定时/事件触发、Agent teams、**PostgreSQL 生产 / PGlite 本地**。
- 彩蛋：Claude Code 里 `/visual-edit` —— 在 canvas 上改运行中的 app（多断点对比），改完让 Claude 把改动写回源码。

**值得关注的原因**
- 它给出了**"Agent 原生应用"的第三条路**：不是给现有 SaaS 加个聊天框（第一条），也不是让 Agent 点屏幕（第二条，CUA/Windows-MCP 那一路），而是**让 action 层成为唯一入口**。这样权限、审计、校验天然只有一处。
- 和 gh-aw 的 safe-outputs 是同一个抽象的两端：一个在 CI 里把写操作抽出来，一个在应用里把能力抽出来。**"能力层统一"正在成为 Agent 工程的标准答案**。
- 反面提醒：**无 LICENSE**。Builder.io 是商业公司，`@agent-native/core` 的 npm 授权要单独看，不能默认当开源用。

### 5. mobile-next/mobile-mcp v1.0.12 —— 移动端也走"读结构不读像素"，且默认不喂视觉模型

**事件**：`langM:typescript` 本月 **+3,026**（总 9,748，866 forks，Apache-2.0），**v1.0.12（10-18）**。

**核心内容**
- 一套 MCP 工具同时打 **iOS 模拟器 / iOS 真机 / Android 模拟器 / Android 真机**，不需要 XCUITest、不需要 Espresso。
- **accessibility-first**：从原生无障碍树驱动应用，**不用视觉模型、不消耗图像 token**；只有必要时才退回截图 + 坐标。官方原话：*"fast and cheap"*。
- 工具面（30+）：`mobile_list_available_devices`、`mobile_get_foreground_app`、`mobile_list_elements_on_screen`、`mobile_click_on_screen_at_coordinates`、`mobile_type_keys`、`mobile_press_button`、`mobile_open_url`、`mobile_start_screen_recording`、`mobile_get_device_logs`、`mobile_list_crashes`、`mobile_batch_commands`（一次调用串多步）。
- 冷门但实用的：`mobile_fold_device`（折叠屏）、`mobile_set_location`（改 GPS）、`mobile_clipboard`。
- **v1.0.11 的两个安全修复值得单列**：输出路径**逐级解析 symlink 后**再校验白名单（此前符号链接可把截图/日志/录像重定向到白名单外）；symlink 成环或层数过多**直接拒绝**。v1.0.12 修大 UI dump 触发 `ENOBUFS`。
- Claude Code + Ghostty/kitty 有 `/mobile-mirror`：终端侧栏直接看设备实时画面，能点能打字。

**值得关注的原因**
- **"读结构 vs 看屏幕"的分野从桌面扩到移动端**（10-09 期 Windows-MCP 走 UI Automation，10-15 期 agent-browser 走浏览器协议）。mobile-mcp 的取舍更硬：默认完全不用视觉模型。这意味着移动自动化的成本从"每步一张截图"降到"每步一个元素列表"。
- symlink 逐级解析这条修复，是**文件边界类漏洞的通用模式**：只校验字面路径等于没校验。同类问题在过去几期的 claude-mem（读取绑定根内已校验的确切文件）、gods-eye-view（凭据服务端代理）都出现过——**"路径先解析再判权"应写进 checklist**。

### 6. devaccuracy/ledgerforge v1.0.0 —— 给 AI Agent 发一张有额度的卡，账在服务端

**事件**：`langW:go` 本周 **+207**（总仅 411，42 forks，Apache-2.0），**v1.0.0（10-10）** 首个正式版。

**核心内容**
- 开源**复式记账本**：钱包转账、payout、计费、预留、退款，全部**整数单位**记账，带**可验证审计链**。
- 三种用法：HTTP API、Go 库、**本地 MCP server**（`ledgerforge-mcp`）。
- **Agent 护栏是核心卖点**：每个 API key 独立配置**币种与精度上限、余额与账本白名单、每日预算、审批挂起**，**由服务端强制，不是客户端自觉**；派生 key **继承限制并共享祖先预算**；MCP 必须绑到某个 API key，**审批人凭据要放在 Agent 权限之外**。
- 会计保证写死：整数记账（`1250` + `precision: 100` = `12.50`）、借贷必平、分录不可改（更正/退款生成新交易）、**幂等靠 reference**（超时后用同一个 reference 重试，重复 reference 直接拒绝）。
- `ledgerforge verify` 只读重放会计证据；`audit verify --anchor` 对独立保存的根做锚定。
- 边界写得很克制：**它只记账，接支付通道和定义会计模型仍是你的事**。
- 供应链：Linux/macOS/Windows 二进制 + 多平台镜像 + checksums + **SPDX SBOM** + 镜像 attestation，**测试/漏洞/模糊测试门禁通过才发版**。
- 商业化**没有功能门控**：开源版就是 Cloud 版同一份核心，*"no license keys or feature gates"*。

**值得关注的原因**
- **"Agent 花钱"从概念变成可部署的组件**。10-15 期 apify-mcp-server 接了 agentic payments（AGI token / x402 / Skyfire）——那是"怎么付"；ledgerforge 是"**付多少、谁批、怎么查**"。两块拼起来才是完整闭环。
- 它的设计原则可复用：**额度、白名单、日预算必须服务端强制，且审批凭据不能和 Agent 在同一权限域**。任何"Agent 调支付 API"的方案，缺这一条等于没护栏。
- 411 star 说明这类项目还没被注意——但**基础设施类项目的价值不看 star**，看它是否被别的东西依赖。

### 10. claude-mem v14.0.0 —— 从"记忆检索"跳到"我让你干的事现在到哪了"

**事件**：已推送仓库重大新版本。**v14.0.0（10-17 15:50 UTC）+ v14.0.1（10-17 16:25 UTC）**，版本号从 13.39 直接跳到 14。当前 101,661 stars / 8,933 forks / Apache-2.0。

**核心内容**
- **My Work（新的默认首页）**：本地、人类可读的"你给 Agent 下过的请求"视图。
  - 三种视图：**Cards**（全宽请求卡：标题、白话摘要、谁做的、属于哪个项目）、**List**（可排序）、**Agents**（按 Agent 分组）。
  - **"Attention first" 排序**：需要你处理的排最前。
  - **白话摘要**由你已配置的模型生成，**新摘要写出来之前旧的好摘要继续显示**；没有可用 provider 就显示原始记录措辞。
  - **状态机**：In progress / Needs you / No recent update / Ready to check / Checked，**刷新时页面不跳动**。
  - **Review**：只有人能把结果标成"已检查"。原文一句关键设计：*"so an agent reporting 'done' is never mistaken for a person confirming it."*
  - 可下钻：workstreams、记录的 evidence、原始请求。
- **TeamBrain（可选，商业层）**：团队选择共享的工作、上下文与交接进入同一个视图，**私人工作不会被广播**。自助开通，**$50 / 席 / 月**（cmem.ai/teambrain）。
- 其他：Codex 跳过 next-message suggestion 与 rollout-consolidation 的辅助 prompt；Windows 测试改为直接拉起运行中的 Bun。
- 升级：`npx claude-mem@latest install`。

**值得关注的原因**
- **记忆层的问题定义变了**：13.x 解决的是"Agent 能不能查到过去的上下文"（三步有界披露、游标、hook 让路），14.0 解决的是"**人能不能查到 Agent 干了什么**"。从检索转向**工作台账**。
- 那句"Agent 报 done ≠ 人确认完成"是本期的核心判断，也是**人机责任边界第一次被写成 UI 约束**。对照 10-13 期 Game Studios 的"解析通过≠跑过"、10-15 期 Soup 的"配置被接受≠生效"——三者是同一族问题：**系统状态不能自我认证**。
- 商业化路径值得记：**开源部分（My Work）免费 + 团队协作收费 $50/席/月**，且明确"私人工作不广播"。这比"企业版解锁负载均衡"（bifrost）温和得多，也更符合记忆类产品的信任门槛。

## 五、当日判断

1. **Agent 的接口正在从 MCP 回摆到 CLI + Skills。** 微软自己在 playwright-cli README 里写了取舍标准（高频编码 → CLI 省 token；需要持久状态 → MCP），HKUDS/CLI-Anything 同一天 +5,051 也是同一方向。**判断可复用：一次性、可脚本化 → CLI；有状态、要反复内省 → MCP。**
2. **"权限面"成为 Agent 工程的第四层。** 已有三层是策略面（mxc）、编排面（agent-sandbox）、内核面（litebox），今天 GitHub 补上**权限面**：safe-outputs 把写操作从 Agent 进程里拿出来，交给单独 job 用受限身份执行。同一个抽象在应用层由 agent-native 实现（action 层是唯一入口）。
3. **控制面从"配置"上移到"调度"。** cc-switch（10-12）管 10 个 CLI 的 endpoint，Orca 管 33 个 CLI 的并行 worktree 执行 + 结果择优，Coder 管"Agent 循环跑在控制平面、工作区里没有 key"。**三种形态，同一条线：Agent 不该住在工作区里。**
4. **"Agent 花钱"闭环补齐。** 10-15 期 apify 解决"怎么付"（x402 / AGI token / Skyfire），本期 ledgerforge 解决"付多少、谁批、怎么查"（服务端强制额度 + 审批凭据与 Agent 权限分离 + 可锚定审计链）。**缺后者等于没护栏。**
5. **记忆层的问题定义从"Agent 查得到"变成"人查得到"。** claude-mem 14.0 的 My Work 是工作台账，不是检索器。核心约束：**Agent 报 done ≠ 人确认完成**——与"解析通过≠跑过""配置被接受≠生效"同族，都是"系统状态不能自我认证"。
6. **厂商官方插件开始跨 harness 分发。** Unity 官方插件同时上 Claude Code / Codex / **Grok**；Orca 的支持列表里出现 CodeBuddy、DeepSeek Harness、Kimi、Qwen Code、MiMo Code。**单押 Claude Code 的时代结束了。**
7. **移动端自动化定型为"读结构不读像素"。** mobile-mcp 默认不用视觉模型，Android 官方也发了 `android/skills`。成本从"每步一张截图"降到"每步一个元素列表"。
8. **诚实披露继续细分到"数据新鲜度"。** OpenStock 把报价延迟明码标价（社区每小时 / Cloud $5 月 15 秒 / 自托管自选），比"实时行情"四个字有用。
9. **今日最大增幅（VoiceStudio +42,036）没有产品事件。** 停更 26 天、无新 release。**star 尖峰 ≠ 趋势**，这条要写进筛选口径。
