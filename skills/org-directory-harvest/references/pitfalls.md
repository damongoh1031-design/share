## 1. Facebook 登出态拿不到大图，改 URL 参数也没用

**现象**：不登录访问主页，`img` 的 `naturalWidth` 最大只有 590。
把 CDN URL 里的 `stp=dst-jpg_s590x590` 改成 `s2048x2048`，返回 **22 字节**的内容，
日志报 `URL signature mismatch`。

**原因**：FB 的 CDN 签名覆盖了尺寸参数，改了就失效。

**修法**：必须用登录 cookie（`c_user` / `xs` / `datr` / `fr` / `sb`）。
登录后同一张图在 DOM 里直接给到 `naturalWidth=2048`，不用改 URL。
判断是否真登录：页面 `document.cookie` 里有 `c_user`，且标题不是「Facebook」。

**顺带**：图片在页面上会以多种尺寸重复出现，按 URL 里的图片 ID
`/(\d{6,})_(\d+)_(\d+)_[a-z]\.(jpg|png|webp)/` 归并，取面积最大的一张，
否则 2444 张里有一半是同一张图的缩略副本。

## 2. 中文关键词在 FB 搜索里污染极重

**现象**：搜「基督教会」「青年团契」，返回结果里台湾、香港、新加坡、巴黎、美国的页面占一半。
搜「佛堂」返回一堆素食餐厅和殡葬服务。

**修法**：三层闸门，缺一不可。

1. **搜索层 `exclude`**：`巴黎|Paris|纽约|New York|NYC|多伦多|Toronto|温哥华|Vancouver|伦敦|London|悉尼|Sydney|USA|Texas|Fort Worth|秘鲁|Peru|仰光|芥菜種|布農|都蘭`
2. **名称层 `MY_PLACE`**：名字里带马来西亚地名（`新山|槟城|怡保|马六甲|芙蓉|古晋|亚庇|…`）即通过
3. **正文层 `MY_BODY`**：正文含 `Malaysia|马来西亚|雪兰莪|柔佛|槟城|…` 即通过

**关键 bug**：闸门一开始写成 `MY_BODY.test(pg['title'])`，而 `pg['title']` 是
`"(9) Facebook"` 这种字符串——所有页面都过不了，L3 层只剩 12 条。
正确做法是**先解析出 `nm`**（title → 正文首行 → slug），再对 `nm` 做闸门判断。

## 3. 块状名录的「块尾」会串到下一条机构

**现象**：佛总 288 个会员团体的 `网站` 字段 100% 是垃圾，填的都是下一家机构的名字。

**原因**：页面 `innerText` 长这样：

```
A001 | 某某佛教会
地址：...
联络电话：...
电子邮箱：...
网站：
B002 | 另一家佛教会        <-- 这一行被当成上一条的「网站」
地址：...
```

标签定位法把「下一个标签出现之前的所有行」都归给当前字段，最后一行必然是下一条的名字。

**修法**：切块时若当前块一直延伸到列表末尾，说明尾巴属于下一条，回退一行：

```python
if nxt == e and bi + 1 < len(starts):
    nxt = e - 1
```

修完 `网站` 从 288 条垃圾降到 11 条真实。

## 4. 理事名单页：正文从导航之后才开始

**现象**：14 个州联委会页面全部返回同一个电邮、0 个电话。

**原因**：页面真实内容是「职位 / 姓名」两列表格，后面接
`通讯处 / 联络人 / 电子邮箱 / 面子书`。直接全文正则匹配会先撞上页脚的联系方式。

**修法**：先剥导航，从第一个职位词开始切，再按 `标签: 值` 取值：

```python
ROLE = re.compile(r'^(主席|副主席|秘书|副秘书|财政|副财政|理事|查账|稽查|顾问|团长|副团长|'
                  r'主任|副主任|组长|副组长|队长|副队长|协调员|州代表|委员)')
```

修完 13/13 主席 + 193 位理事全部拿到。

**衍生 bug**：切出来一个叫「卸任主席」的假人。
二次过滤，姓名候选里含
`主席|理事|秘书|财政|查账|稽查|顾问|委员|主任|团长|队长|组长|卸任|前任|名誉|代表`
一律丢弃。209 → 193。

## 5. 支会编号前缀不是固定的

**现象**：青运（YMM）只解析出 42 个支会，全在雪兰莪。

**原因**：正则写死 `^B\d{3}`。实际前缀按州变：霹雳 `A`、雪兰莪 `B`、柔佛 `C`……

**修法**：`^([A-Z]\d{3})\s*\|\s*(.+)$`。42 → 280。

**教训**：任何「编号 + 名称」的列表，先 `head` 看 30 行确认前缀分布，别按第一行写正则。

## 6. 分类正则的包含关系陷阱

| 错误分类 | 原因 | 修法 |
|---|---|---|
| 柔佛 → 佛教 | `柔佛` 里有「佛」 | `(?<!柔)佛` 否定后行断言 |
| 布道处 → 道教 | 裸 `道` 命中 | 去掉裸 `道`/`tao`，改用 `道教\|道家\|道观\|道壇\|德教\|老君\|九皇\|大伯公\|法主公\|茅山\|天后宫\|关帝\|紫阁\|玄天上帝\|三清` |
| 狮子会 → 文化 | 裸 `lion` 命中（Lions Club ≠ 舞狮） | 去掉 `lion`，用 `龙狮\|舞狮\|醒狮\|狮团\|dragon dance\|wushu\|武术` |
| 紫系团体 → 其他 | 裸 `紫` 太宽 | 用 `紫阁\|紫閣\|紫系` |

**原则**：宁可漏分类到「其他」，也不要错分类——错分会让下游按类别统计全部失真。

## 7. 同一 FB 主页被重复写入

**现象**：`kuansengmalaysia` 在结果里出现两次，第二次覆盖了第一次的电话。

**修法**：用 `seen_slug` 字典，命中已存在时**合并**而不是覆盖：

```python
if slug in seen_slug:
    old = seen_slug[slug]
    for k in ('tel', 'mobile', 'email'):
        old[k] = ' / '.join(filter(None, {old.get(k, ''), r[k]}))
    continue
```

```python
EVENT_NAME = re.compile(r'第\s*\d+\s*[届屆]|20[0-2]\d\s*年|19\d\d\s*年'
                        r'|(?:^|\s)(?:19|20)\d\d(?:\s|$)|[‘’\']\s*第', re.I)
```

## 9. 邮编推断州属：「最后一个」不是「第一个」

**现象**：`78000 Tampin, Negeri Sembilan` 被判成马六甲。

**原因**：Tampin 镇的邮局在马六甲境内编码，但地址写的是森美兰；反过来也有
`地址写 Selangor 但邮编是吉隆坡` 的情况。

**修法**：严格三级顺序，前一级命中就不看后一级。

1. 地址里出现的英文州名（`Negeri Sembilan|Selangor|Johor|…`）
2. 城市/地名提示表（`Klang→雪兰莪`、`Tampin→森美兰`、`Kota Kinabalu→沙巴`）
3. **最后一个** 5 位邮编（取最后一个，因为 `No.9, Jalan SS25/24, 47301 Petaling Jaya` 前面可能有别的数字）

**注意**：写 `PC_RANGE` 时别写成 `05000`——Python 会把前导零当八进制报
`SyntaxError: leading zeros in decimal integer literals`，写 `5000`。

**非标准州名映射**：`雪隆 → 雪兰莪`、`沙闽 → 沙巴`、`登嘉楼州 → 登嘉楼`。

## 10. `shutil.rmtree` 在沙箱里会失败

**现象**：`OSError: [WinError 0x2] SHFileOperationW` —— 删除被重定向到回收站。

**修法**：手动自底向上删：

```python
for root, dirs, files in os.walk(p, topdown=False):
    for f in files: os.remove(os.path.join(root, f))
    for d in dirs:  os.rmdir(os.path.join(root, d))
os.rmdir(p)
```

## 11. github-sync 的目录模式会静默删远端文件

**这是最危险的一条。**

- 逐文件模式 `--src a.xlsx --dest dir/a.xlsx` 用 `shutil.copy2`，**安全**。
- **目录模式 `--src dir --dest dir` 会先 `shutil.rmtree(dest)` 再 `copytree`**：
  远端目录里本地没有的文件被删掉，旧版本被本地旧版本覆盖，全程无提示。
  仓库是跨会话共享的，别人（或上一轮的自己）传过的东西会凭空消失。

**修法**：

1. 只用逐文件模式，一个文件一条命令。
2. 执行前先 `--dry-run`，确认输出里 `deletions=0`、`new` 数量符合预期。
3. 传完用 `md5` 校验本地与远端一致，并检查仓库总文件数没有减少。

## 12. 增量 OCR 的缓存键与目录约定

- 缓存键用 **sha1**（文件内容），不要用路径——同一张图换个名字/目录不该重跑。
- `org_slug` 取相对路径第一段，所以**图片必须按 `<slug>/<img>.jpg` 组织**，
  否则无法回溯到机构。
- 采集还在跑的时候就先跑一遍 OCR，跑完再跑一遍；增量缓存会自动补齐，
  不会重复计算。第一批只覆盖 380 张是正常的，不是 bug。
- OCR 常把 `012-345 6789` 粘成 `0123456789`，补一次切分：
  `re.sub(r'(?<=[0-9])(?=[+0])', ' ', txt)`。

## 14. JS 异步加载的表格抓不到

**现象**：武术总会的「属会资料」页，`innerText` 里一个属会都没有。

**原因**：数据由 XHR 拉 JSON 后渲染。

## 16. 「搜索词别名」会污染合并 —— 最贵的一次错

**现象**：用 `马来西亚中华总商会` 这类宽泛关键词搜到的 300 个 FB 页面，
凡是被该关键词命中的，全部被合并进 ACCCIM 总会这一条记录，
笨珍、古来、麻坡、关丹、民都鲁、浮罗交怡等地方中华商会**整条消失**，
数据被写进总会名下，成了错的联络方式。

**根因**：把「搜索用的关键词」当成「页面的真实身份」。
`qmap[slug] = idx[query]` 这种写法，等于宣布「凡是我用 A 搜出来的页面都是 A」。

**修法**：搜索词只能用来**发现**页面，绝不能用来**判定身份**。
身份判定只用页面自己写的名字，规则要严格：

```python
def similar(a, b):
    if jac(a, b) >= 0.7:              # 有效 token 的 Jaccard
        return True
    fa, fb = flat_cjk(a), flat_cjk(b)  # 去掉非中文字符
    if len(fa) >= 5 and len(fb) >= 5 and (fa in fb or fb in fa):
        return min(len(fa), len(fb)) / max(len(fa), len(fb)) >= 0.75
    return False
```

`0.75` 这个长度比阈值是关键：没有它，`北霹雳中华总商会` 会被
`霹雳中华总商会` 吞掉（7/8 = 0.875 也过不了 0.95，但过得了 0.8）。

## 17. 「中华总商会」里含「华总」二字

分类正则按顺序匹配时，若 `华总` 排在 `中华总商会` 前面，
所有 `XX中华总商会` 都会被归到「华总体系」——因为字符串里确实有「华总」。
**商会类判定必须排在华总之前**。同理 `中华大会堂` 与 `大会堂` 要一起写。

## 18. 缩写撞车：吉打和吉兰丹都叫 KCCCI

`Kedah Chinese Chamber of Commerce and Industry` 与
`Kelantan Chinese Chamber of Commerce and Industry` 缩写完全相同。
仅凭「缩写相同」判同一机构，会把两个州的中总合并。

**修法**：缩写相同时还要看中文主体——
一侧无中文（纯英文名）才认缩写；两侧都有中文则要求中文完全一致。

## 19. 母会与分会绝不能按「包含关系」合并

`REHDA` 有 12 个州分会，`FMM` 有 9 个，名字形如
`REHDA 马来西亚房地产发展商会 Johor分会`。按中文包含关系判定，
12 条会全部塌成第一条（因为中文部分完全相同）。

**修法**：带 `分会|属会|支部|联委会|青商团|青年团|妇女组` 的记录一律独立成条；
两边都是分支时，只认「字面几乎完全一致 + 英文地名部分也相同」。

## 20. 母会与属会要按地名归并（反向问题）

官网写 `柔佛州中华总商会 笨珍属会`，FB 上却叫 `笨珍中华总商会`，
两者是同一机构，但字面毫无包含关系，会变成两条记录。

**修法**：从 `^(.{4,}?(?:中华总商会|中华商会|商会))\s*(\S{2,6}?)(属会|分会|支会)$`
里抽出地名（`笨珍`），凡是名字含该地名且带「商会」二字的记录，归并进母会，
并在 note 里记 `亦称 笨珍中华总商会`，保留两种叫法。

## 21. FB 页名解析：`1.1 万位粉丝` 的「万」字

`FANS = re.compile(r'[\d,\.]+\s*(?:位粉丝|followers)')` 匹配不到
`1.1 万位粉丝`（数字和「位粉丝」之间夹了个「万」），
于是回退到「找第一行像机构名的中文」，抓到 `发消息`、`联系我们`、`详细了解`。

**修法**：

```python
FANS = re.compile(r'[\d,\.]+\s*万?\s*(?:位粉丝|followers)', re.I)
UI_JUNK = re.compile(r'^(发消息|关注|搜索|社群|联系我们|详细了解|在线状态'
                     r'|未读通知数量|个未读聊天|注册|WhatsApp|\d+)$')
```

往前找名字时跳过 `UI_JUNK`，也跳过含 `位粉丝|followers|赞|次点评` 的行。

## 22. 境外同名机构会大量混入

`Chinese Chamber of Commerce of Guam / Mauritius / Tampa Bay / Greater Cincinnati`、
`Swiss-Chinese Chamber of Commerce`、`Silicon Valley Chinese Engineer Association`
——这些名字的 token 与马来西亚机构高度重合，Jaccard 能到 0.6。

**修法**：三层过滤，缺一不可。

1. **中文国名/地名**：`华盛顿|关岛|毛里求斯|北欧|马耳他|秘鲁|乌克兰|柬埔寨|刚果|西班牙|欧盟|俄罗斯|爱尔兰|株式会社`
2. **邮箱/官网 TLD**：`.tw .hk .mo .cn .jp .kr .id .th .vn .ph .in .au .uk .us .ca .de .fr .bd .ch .sg` 一律丢
3. **英文地名**：`Guam|Mauritius|Maltese|Nordic|Washington|WNY|Tampa|Cincinnati|Columbus`

判断依据用**邮箱域名和官网域名**比用名字可靠得多——名字可以起得很像，域名不会。

## 23. 繁体字必须先转简体再分类

马来西亚社团大量使用繁体（`馬來西亞華商經貿總會`、`山打根中華商會`、`馬來西亞茶業商會`），
分类正则写的是简体，这些全部落进「待分类」。

**修法**：分类、相似度比对、去重之前统一走一遍 `simp()`（约 100 字的繁简映射表），
显示名也用简体，保持全表一致。

## 24. 中英文重复条目要「中文名优先」

同一机构常有两个页面：`Malaysia Tea Trade Association` 与
`Malaysia Tea Association 馬來西亞茶業商會`；`Federation of Malaysian Manufacturing - FMM`
与 `马来西亚厂商联合会 FMM`。

**修法**：
- 名称收敛：英文为主、中文为辅的页名，若中文总长 ≥ 4 字，直接取中文作主名
  （`BCCCI 民都鲁中华总商会` → `民都鲁中华总商会`）。
- 去重时若目标名无中文而来源名有中文，采用来源名。
- 跨语言对（`茶业商会` ↔ `tea trade association`）靠 `MANUAL_PAIRS` 手工补，
  自动规则永远覆盖不到，不要指望。

# 五、理事名表解析（2026-10-30 第二轮）

采「人名」比采「机构联络」难一个量级：名表是**无结构的多行文本流**，
同一个站的不同页面都可能换版式。以下 9 条是按真实页面踩出来的。

## 25. 两字职务会被人名校验吃掉

`主席`、`财政`、`董事`、`顾问`、`查账`、`会长` 都只有两个字，
而「中文姓名 2–6 字」的校验正好放行它们。

**症状**：整份名表解析出一堆叫「主席」「财政」的人，真正的人名一个没有；或行数正常但职务全空。

**修法**：职务判定**必须排在姓名判定之前**，且不要给职务加 `not CJK_NAME.match(s)` 这种
「排除人名」的反向条件——那会把所有两字职务一起排除掉。

```python
def is_role(s):
    return bool(s) and len(s) <= 40 and bool(ROLE.search(s))
```

## 26. 职务行的全角冒号有两种写法

- `顾问：` —— 冒号在职务后面，姓名在下一行
- `主任     ： 蔡常辉` —— 冒号和姓名挤在同一行
- `副主任` / `：` / `甲、乙、丙` —— 冒号自己占一行

**修法**：先 `re.sub(r'[\s:：]+$', '', s)` 剥尾部冒号；再判 `'：' in s` 时按冒号切分，
前半段是职务就把后半段当姓名列表；单字符标点行（`：`、`、`）一律跳过。

## 27. 区域起始标记会撞上 `<title>`

用 `名誉会长` 作区域起点，会先命中 `<title>名誉会长、名誉董事名录 – 峇株巴轄中華總商會</title>`，
于是整段导航被纳入区域，导航里的 `青商团` 被当成分组名，最终每个人的职务都变成
`青商团 永久名誉会长`。

**修法**：`region(L, start, end, occ=N)` 取第 N 次出现（正文标题通常是第 2 次）；
或改用更长、只在正文出现的标记。

## 28. 分组前缀只给小组职务

`会务规划与策略委员会 主任` 正确；`青商团 永久名誉会长` 荒谬。

**修法**：只有当职务以 `主任 / 委员 / 组长` 结尾时才拼接分组名，
且判断重复用 `not group.endswith(s)`（`委员` 是 `…委员会` 的后缀，用 `s not in group` 会误判）。

## 29. 结束标记可能出现在起始标记之前

导航里 `其他委员会` 在前、`历届理事会` 也在前，用后者作结束标记，
`next(i for i in range(a+1, ...) if end in L[i])` 找不到就退化为 `len(L)`——
但如果 `end` 恰好又出现在 `a` 之前的位置，区域会算成空。

**修法**：区域长度 < 3 行时直接报错或退化为「到文件末尾」，不要静默产出 0 条。

## 30. 英文名里的弯引号不是 ASCII

`Dato’` 用的是 U+2019，`Dato'` 才是 U+0027。字符类 `[A-Za-z'\.\s\-]` 漏掉弯引号，
吉打中总 42 人里 23 人的英文名会被判成「不是人名」，掉进 `company_en` 字段。

**修法**：字符类里补 `\u2019\u2018`；凡是从网页抓的英文人名，先做
`unicodedata.normalize('NFKC', s)` 或直接补这两个码位。

## 31. 勋衔代码必须和姓名分开

`拿督陈明恩 DIMP`、`黄卿兴 JMN, AMN县议员`、`颜旺栗 PIS`——
尾部的大写勋衔代码会让「纯中文 2–6 字」校验失败。

**修法**：
```python
HONOR_CODE = re.compile(r'\s+(?:[A-Z]{2,6}\s*,?\s*)+$|\s*[A-Z]{2,6}\s*$|县议员$|州议员$|上议员$')
```
先剥代码，再剥中文勋衔（`拿督斯里|拿督威拉|拿督|丹斯里|敦|准拿督|太平局绅`），最后剥学位/称谓
（`先生|女士|小姐|博士|硕士|律师|工程师|会计师|局绅`）。

## 32. 同一个人在同一机构有多个职务

`蔡常辉` 既是 `副会长` 又是 `商贸组主任`；`陈友信` 既是 `主席` 又是 `会务规划与策略委员会 主任`。

**修法**：去重键用 `(机构, 规范化姓名)`，命中时把职务用 `；` 合并，其余字段取第一个非空值。
不要按 `(机构, 姓名, 职务)` 去重——那样同一个人会出现好几行，看表的人无法判断该打哪个电话。

## 33. 中英双语姓名：找「同一份列表的两个语言版本」

这是给马来西亚华人建人名库的**最高性价比动作**。中总（ACCCIM）的做法值得照抄：

- 英文：`acccim.org.my/en/pic-member/<slug>/`
- 中文：`acccim.org.my/pic-member/<中文名>/`
- 两份列表**顺序一致**，按序号 zip 即得中英对照。

```python
en = get(base_en + '/wp-json/wp/v2/pic-member?per_page=100&_fields=id,title,link')
zh = get(base_zh + '/wp-json/wp/v2/pic-member?per_page=100&_fields=id,title,link')
pairs = [(a['title'], b['title']) for a, b in zip(en, zh)]
```

**为什么重要**：马来西亚华人普遍不用完整中文名，报章与 Facebook 一律用英文名
（`拿督洪锡倡` = `Dato' Ang Saik Cheong`）。只有中文名的人，检索命中率接近零。

**发现双语页的办法**：`/wp-json/wp/v2/types` 列出所有自定义 post type，
人名类通常是 `pic-member`、`honorary-president`、`past-presidents`、`team`、`people` 这类。

## 34. 「用姓名全网搜手机号」基本不成立（实测结论）

2026-10-30 实测，12 人样本：

| 引擎 | 结果 |
|---|---|
| DuckDuckGo HTML | 命中 0；几十次请求后被限流，返回无结果页 |
| Bing HTML 直取 | 能拿到 10 条 `b_algo`，但查询被泛化（`Ang Saik Cheong Kedah` 返回所有姓 Ang 的网站），`site:` 查询直接为空 |
| Bing 摘要文本 | 不含电话号码，只有一句简介 |

**结论**：搜索引擎不索引社团领袖的**个人手机**。个人手机只出现在两处——
① 商会自己印的**名表**（带 `Mobile:` 栏）；② Facebook 贴文里的**名片/海报照片**。

**该做的**：
1. 优先找带 `Mobile / Office Tel / Home Tel / Fax / Email` 栏的名表页（吉打中总那种，42 人 42 个手机）；
2. 有公司名的，抓公司官网 Contact / Management 页拿办公室电话；
3. FB 相册 OCR 兜底（需登录态，成本高）。

**不该做的**：拿人名去搜索引擎逐个查，再指望摘要里出现号码。
