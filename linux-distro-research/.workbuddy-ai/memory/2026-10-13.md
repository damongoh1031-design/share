## Arch 防滚挂指南（第十一份专题 · 预警 / 提醒 / 检查 / Agent 一站式）

- **交付物**：`reports/arch-anti-breakage-guide-2026-10.md`
- **知识沉淀**：`kb/arch-anti-breakage-guide.md`（v1.0.0，已登记 kb/README.md）
- **本轮新增产出（不只是报告，是可运行件）**：**`skills/arch-update-guard/`** —— Arch 更新前检查闸门 skill
  - `scripts/arch_update_guard.py`：零第三方依赖（纯标准库），10 项检查，退出码语义化（0 正常 / 1 WARN / 2 BLOCK / 3 环境错误）
  - 子命令：`check` / `json` / `news` / `snapshot --yes` / `selftest`
  - **本机实测**：语法检查通过；**13 项 selftest 全通过**；`news` 真实抓到 **6 条需人工介入公告**（含 2026-09-22 mkinitcpio）；`check` 在 Windows 上正确降级为 BLOCK 且其余检查仍跑
- **方法**：2 个并行子代理（预警工具链 / 提醒+自动化）+ 主调研员对全部工具做 AUR RPC / 官方仓库 API / GitHub API / PyPI 实测
- **本轮关键修正**：
  - **`informant` 已从 AUR 下架**（AUR RPC 实测 `NOT_IN_AUR`）—— 但 GitHub 仓库还在（429★，2025-06 停更），导致**网上大量教程"看起来有效"**。推荐改用 **`arch-manwarn`**（Rust，25★，2026-08，只拦 manual intervention，误报率低）
  - **`arch-mcp` 存在**（`nihalxkumar/arch-mcp`，59★，PyPI `arch-ops-server` v3.4.0）—— **推翻前序"Arch AI 生态基本为零"的结论**。它自带 `safe_system_update` Prompt（检查关键新闻→验证磁盘→列更新→查服务→建议），正是用户要的"一站式"
  - **`snap-pac` 在官方 extra 仓库**（3.0.1-3），不在 AUR
  - **`arch-audit` 数据源已死**（依赖 2025-06 停发的 Arch ASA）
- **实测确认**：Arch News **有 RSS/Atom**（`archlinux.org/feeds/news/`，HTTP 200，16KB）；`checkupdates` 退出码 **0=有更新 / 2=无更新**；`snapper`(extra) / `timeshift`(extra) / `linux-lts`(core 6.18.56-1) / `archlinux-contrib`(extra) / `rebuild-detector`(extra) 全部在官方仓库；`arch-update` AUR v4.4.3-1（74 votes，GitHub 460★，**2026-10-12 更新**）
- **核心结论**：Arch 官方**不提供也不推荐**无人值守自动更新 —— 因为 manual intervention 公告需人判断。正确目标是「自动化检查 + 人工确认执行」。三件套：News RSS + `arch-manwarn` + `snap-pac`
- **未解决**：`arch-update` 确切 unit 文件名（GitHub 直连被拦）；`arch-mcp` 12 个工具当前是否全部可用（需 Arch 环境实测）；`informant` AUR 下架的确切原因与时间
