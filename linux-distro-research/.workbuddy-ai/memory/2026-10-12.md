## 游戏性能优化深度比较（同一组发行版，第二份调研）

- **交付物**：`reports/linux-gaming-perf-2026-10.md`
- **知识沉淀**：`kb/linux-gaming-perf-rolling-distros.md`（v1.0.0，已登记 kb/README.md）
- **方法**：3 个并行子代理（每发行版 1 个）+ 主调研员核实跨发行版通用层（scx_lavd / NTSYNC / Wayland HDR）
- **核实到的关键事实**：
  - 图形栈：Arch Mesa 26.2.4 = TW 26.2.x；**NixOS stable 停在 25.2.6，落后约一年**
  - 调度器：`scx_lavd`（Igalia 为 Steam Deck 开发、原为游戏场景）三发行版都可用；NixOS 用 `services.scx` 一行声明式启用最优雅；Arch `scx-scheds` 1.1.3 最新，TW `scx` 1.0.16 落后
  - NTSYNC：Linux 6.14 主线，Fedora 44 首个默认启用；三发行版内核都 ≥6.14，差异只在是否默认加载
  - **Tumbleweed NVIDIA 是 KMP 内核模块包，内核升级会导致驱动损坏**（6.18 事件）
  - **Tumbleweed 的 AMD 32 位 Vulkan 默认不装**，需手动 `zypper in libvulkan_radeon-32bit`
  - **NixOS `hardware.graphics.enable32Bit` 默认 false**，漏设导致 Proton 黑屏
  - CachyOS 收益：Phoronix 实测**个位数百分比**，非营销所说的翻倍
  - **三发行版无任何公开游戏帧率对比数据**
- **RimWorld 特化结论**（用户为 RimWorld 1.6 玩家）：RimWorld 是 Unity/Mono 单线程瓶颈，第 1 层（内核/调度器/governor/taskset）远比第 2 层（图形栈）重要；Performance Fish 模组是最大单一提升手段
- **未解决**：Arch 内核是否默认 `CONFIG_SCHED_CLASS_EXT=y`；linux-zen 的 HZ/PREEMPT 具体值；CachyOS 2026 独立量化数据缺失

## 配置漂移与残余文件（第七份调研）

- **交付物**：`reports/config-drift-rolling-update-2026-10.md`
- **知识沉淀**：`kb/config-drift-and-residual-files.md`（v1.0.0，已登记 kb/README.md）
- **方法**：3 个并行子代理（命令式合并机制 / 声明式与不可变架构 / 残余文件与孤儿包）+ 主调研员用 **GitHub API 读 nixpkgs 源码** + **Arch 官方包库 API** + **rpmfind 文件列表**做二次核实
- **核心框架**：把「配置漂移」拆成四类 —— A 文件级冲突（可检测不可自动判定）/ B 语义漂移（只有 NixOS 能硬拦截）/ C 孤儿包（可全自动）/ D 残余文件（可检测需人工判断）
- **最重要的前提（易被误解）**：**只有被声明为「配置文件」的文件才有保护**。Arch `backup=()` 数组 / RPM `%config` / Debian `DEBIAN/conffiles` —— 没声明的文件升级时**直接覆盖，连 `.pacnew` 都不留**
- **本轮硬核实到的关键事实**：
  - **`mkRemovedOptionModule` 是 `throw` 而非 warning** —— 从 nixpkgs `lib/modules.nix` 第 1863 行源码确认（官方文档写 "warning"，**文档与实现不一致**）；第三方佐证 mobile-nixos issue #731
  - **openSUSE rpm 包自带 `/usr/lib/systemd/system/rpmconfigcheck.service`**（rpmfind 对 `rpm-4.20.1-11.1` 文件列表确认），但**没有 `.timer`** → 不会自动运行，需手动或自建 timer
  - **`lostfiles` 5.1-1 已在 Arch 官方 `extra` 仓库**（2026-07-19）；`etckeeper` 1.18.23-3 也在 extra（2026-04-14）；`pacman-contrib` 1.13.1-1（2025-12-13）
  - **`cruft` 已从 Debian testing 移除**，继任 `cruft-ng`（现由 pkg-security-team 维护在 **salsa.debian.org**，2026-10-10 活跃，GitHub 只是镜像）
  - **`ostree admin config-diff`** 打印当前 /etc 与默认 /usr/etc 的差异（A/M/D 前缀）= 内置漂移检测器；升级时 /etc 走**三方合并**，不用 `.rpmnew`
  - **`xsuchy/rpmconf` 48★，GitHub 最后推送 2025-07-08**，但 Fedora 包为 1.1.12-7.fc45（小矛盾，开发可能已转 Fedora dist-git）；**不支持三方合并，仅两方**
  - Arch `pacdiff -3` 是唯一可做**三方合并**的命令行工具（需缓存里有 base 包）
  - Debian dpkg 是**唯一默认强制用户表态**的机制；`ucf` 支持 diff3
  - **`needrestart` 与配置漂移无关**（只管库升级后的服务重启）—— 常见混淆
  - **Fedora/openSUSE 的 "orphan" ≠ Debian/Arch 的 "orphan"**（前者=仓库里没有，后者=无依赖）
  - Arch VLC 拆包 2025-08-12（`vlc` → `vlc` + `vlc-plugin-*` + `vlc-gui-*`），**拆包不能靠 `replaces` 自动解决**
  - Fedora/RHEL/openSUSE **都没有官方工具**找「不属于任何包的文件」；Arch 有 `lostfiles`，Debian 有 `cruft-ng`
- **结论**：① 通用首选 `etckeeper`（把 /etc 变 git，跨发行版，装完当天见效）② 结构解法选 NixOS / Fedora Atomic / MicroOS ③ 语义漂移除 NixOS 外无自动拦截手段
- **未解决**：`rpmconfigcheck.service` 内容（OBS 有 PoW 反爬）；MicroOS `transactional-update` 处理 /etc 冲突的原文；通用 `rpm-ostree reset` 语义；`.rpmorig` 精确触发条件（仅二手）

  - **Arch 没有「Arch Council」这一机构**（最高是 Project Leader，很多二手资料写错）

  - **Arch 有 ASA 安全公告机制**（9 人志愿团队 + arch-security 列表），但 **tracker 当前停更**（ArchWiki 明确警告）
