一句话结论

NixOS 是六者中"证据最弱、定位最不同"的一个——它从不在性能上竞争，卖点是声明式配置与原子回滚。但它有个反直觉的发现：sched-ext 调度器与 NVIDIA 驱动都是官方 nixpkgs 原生支持（比 Fedora 省事），唯一真正做不到的是"全仓库 v3 重编译"——虽然 nixpkgs 在配置上支持 x86_64-v3-linux，但那意味着几乎全部包都要本地编译。

3. 差异的原因

3.1 编译层 —— CachyOS 的最大优势，也是 NixOS 的最大结构性劣势

项NixOS 26.05CachyOS影响
指令集基线通用 x86_64-linux（v1）v3/v4/znver4CPU 密集 2–8%
LTO部分包全栈 ThinLTO1–3%

关键机制：nixpkgs 原生支持 x86_64-v1-linux / x86_64-v2-linux / x86_64-v3-linux 作为 system type，所以配置层面你可以启用 v3。但官方二进制缓存只提供通用 x86_64-linux 构建——一旦改成 v3，几乎全部包都要在本地重新编译（可能数小时到数天），且无法再从官方缓存下载。

这就是 NixOS 与 CachyOS 的本质差异：CachyOS 提供现成的 v3/v4 二进制仓库，NixOS 提供"能编译 v3 的能力"但不提供现成产物。

4. 差异"没突出"的原因

  1. NixOS 根本不以性能为卖点：它的核心价值是声明式、可复现、原子回滚——性能不在它的竞争清单上。这是"差异不突出"的最根本原因。
  2. 内核可自由切换：boot.kernelPackages = pkgs.linuxPackages_latest 一行就能拿到与 CachyOS 同代的内核——"内核红利"可自取。
  3. scx 官方可用：NixOS 在调度器实验这一层不落后（比 Fedora、Ubuntu 都强）。
  4. NVIDIA 无需第三方仓库：比 Fedora（需 RPM Fusion）省事，接近 Arch/CachyOS 的体验。
  5. 官方缓存是通用构建：这是 NixOS 唯一"结构性吃亏"的点，但它是可复现性的代价——为了"同一份配置在所有机器上得到同一个系统"，必须用通用二进制。
  6. 瓶颈不在 CPU（Amdahl 定律）：4K 游戏 GPU 受限、桌面受 IO/网络限制。
  7. 测量噪声同量级：run-to-run 方差常有 1–3%。
  8. 部分"优化"是取舍：激进电源档是用功耗/续航换响应。

5. 纯官方 NixOS 26.05 能复现哪些优化策略？

前提界定："第三方仓库"指第三方 Flake / Cachix 缓存 / 外部 overlay等。nixpkgs 官方仓库 + cache.nixos.org 视为官方。

2LTO / PGO / BOLT 预编译包无系统性优化构建本地重编译

⚠️ 关于第 1 条的重要澄清：nixpkgs 在配置层面原生支持 x86_64-v3-linux（nix-env 会列出 Additional system types: ... x86_64-v3-linux），你可以通过 nixpkgs.hostPlatform 与 gcc.arch = "x86-64-v3" 启用。但官方缓存不提供 v3 产物——一旦启用，几乎全部包都要本地编译，代价是数小时到数天的构建时间 + 磁盘空间。
所以准确表述是：NixOS "能编译 v3"，但不"提供现成的 v3 二进制"。这与 CachyOS 的现成 v3/v4 仓库是工程便利性上的本质差别。

5.3 直接回答你的问题

NixOS 26.05 在"没有第三方仓库"的前提下，能复现 CachyOS 约 13 项优化——而且几乎每一项都是 configuration.nix 里的一行声明，可版本控制、可复现、可原子回滚。

其中三项是 NixOS 的相对优势：

  1. sched-ext 调度器（services.scx.enable）——官方 nixpkgs 原生支持（比 Fedora 的 COPR、Ubuntu 的源码编译都省事）
  2. NVIDIA 驱动（videoDrivers = ["nvidia"]）——官方 nixpkgs，无需第三方仓库
  3. generations 原子回滚——比 CachyOS 的 Btrfs 快照更彻底

唯一真正做不到的是"全仓库 v3/v4 重编译"：nixpkgs 配置上支持 x86_64-v3-linux，但官方缓存只提供通用构建，启用 v3 意味着几乎全部包都要本地编译。加上 BORE / BMQ 内核必须自建——这两项是 CachyOS 在 NixOS 上无法"官方即用"地复现的部分。
