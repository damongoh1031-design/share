1. 项目背景

  • 基于 Arch Linux 的滚动发行版，主打 性能（而非外观或 AI 概念）。项目约于 2021–2022 年起步（不同来源说法不一），创始 / 主导者为 Peter Jung（GitHub: ptr1337）。
  • 官方站点 cachyos.org ｜ 包索引 packages.cachyos.org ｜ Wiki wiki.cachyos.org。
  • 2024 年全年发布 13 个版本；2025–2026 年改为 每年约 5 次 ISO 更新（2026 年 8 月的 2608 镜像为当年第 5 版）。
  • 2025–2026 年长期位居 DistroWatch 人气榜第一；Steam 硬件调查中占比一度约 4.21%，接近 Ubuntu 24.04 二手来源，谨慎引用。

2. 做了什么优化（技术拆解）

2.1 软件仓库：全栈重编译

  • 维护独立软件仓库，不直接复用 Arch 官方二进制，而是把 Arch 的 PKGBUILD 按现代 CPU 指令集重新编译：
    • x86-64-v3（Haswell / Excavator 及更新）
    • x86-64-v4（需 AVX-512，Skylake-X / Zen4 等）
    • znver4（AMD Zen 4 / Zen 5 专属；2024 年 7 月起新装系统对 Zen4/5 自动启用）
  • 编译优化叠加：LTO 为基线；核心包额外启用 PGO + BOLT；内核另有 AutoFDO + Propeller（linux-cachyos-lto 变体）。

2.2 内核：linux-cachyos 系列 + 调度器可选

  • 基于上游 Linux，叠加 CachyOS 自有 patch set（含未主线化 / 未进 stable 的补丁），官方称先内部测试再发布。
  • 提供多种内核变体：linux-cachyos（默认，对 EEVDF 做响应性调参）、-bore、-eevdf、-bmq、-rt-bore（实时）、-lts、-hardened、-server、手持设备变体等。
  • sched-ext（SCX）：支持用户态可插拔调度器（BPF 实现），由 scx_loader 管理、可运行时切换。SCX 与 BMQ 内核变体不兼容

2.4 安装体验

  • 两套安装器：Calamares 图形安装器 + CLI 安装器（New-Cli-Installer，C++）。
  • 支持 17+ 桌面环境 / 窗口管理器（KDE Plasma、GNOME、COSMIC、Hyprland、Sway、Niri、i3、XFCE…）。
  • 默认 Btrfs + 快照回滚；支持 LUKS2 加密、Plymouth、bcachefs、T2 MacBook、手持设备游戏模式；2026 年起默认启用 Wayland。

2.5 性能成色：证据与反证

正面证据

  • Phoronix 在 Razer Blade 18 上做 Windows 11 vs Ubuntu 26.04 LTS vs CachyOS 的 99 项测试（2026-07-15），CachyOS 赢下 51 项；几何平均分 76.19 vs Windows 11 的 76.12（差 0.07），Ubuntu 明显落后。
  • 社区实测（i7-13700KF + RTX 5090）中 CS2 的 1% low 帧比 Windows 11 高约 20%。
  • RX 5700 XT 上 11 款游戏实测，Linux 侧平均帧率比 Win11 高约 6.4%。

反证与局限

  • 99 项里赢的是"项数"不是"51%"，且多为小分差，测试混合编译 / 渲染 / 模拟负载，并非全是游戏。
  • 提升集中在低帧与 CPU 敏感的高帧竞技游戏；GPU 吃满的 3A 差距小得多。
  • 社区共识：Linux 游戏收益大头来自 Proton / 驱动 / 内核，任何发行版都能吃到；CachyOS 独有的是编译优化 + 调度器调校那一层。
  • 现有测试多为单样本、高端硬件，缺少多机型对照。同机本地 AI 推理测试中 Windows 11 反而大幅领先。

4.3 决策模式与治理风险

  1. 关键人物依赖（bus factor 低）：公开核心成员仅 9 人，方向与发布高度依赖创始人。
  2. 无正式治理章程 / 基金会：没有公开的选举、决策委员会或路线图治理机制。
  3. 资金来源单一：以个人捐赠 + 单一硬件厂商赞助为主，抗风险能力弱。
  4. 与上游关系：深度依赖 Arch 上游包与 PKGBUILD，属"寄生式创新"，上游策略变化会直接传导。

5. 打包质量

5.1 打包流程

  • 来源：以 Arch 官方 PKGBUILD 为基础，修改编译参数（_processor_opt 等）后重建，产出独立仓库。
  • 构建基础设施：Docker 构建镜像（如 pttrr/docker-makepkg-znver4）+ makepkg；脚本 script.sh / script-v3-v4.sh 支持多架构批量构建；repo-manage-util 更新仓库索引。
  • 多仓库矩阵：x86_64 / x86_64_v3 / x86_64_v4 / znver4。
  • 签名：仓库包由 CachyOS 签名密钥签名（pacman-key --recv-keys F3B607488DB35A47）。
  • AUR 衍生仓库：cachyos-aur-derived 托管部分 AUR 衍生包。
  • 索引与镜像：packages.cachyos.org 包检索；官方 mirrorlist API + cachyos-rate-mirrors 自动测速换源。

5.2 质量保障

  • 内核补丁先内部测试再发布；发行前 ISO 快照做 sha256 + GPG 双签名校验。
  • 工具链持续现代化：Shelly 重写为 Zig、Cachy-Updater 基于 Arch-Update 4.x + Rust 重写、安装器代码重构并修了一批 bug。

5.3 打包质量风险点

  1. 与 Arch 官方仓库混装：优化包与官方包混用可能造成版本 / ABI 漂移，建议整仓切换而非混装。
  2. 同步延迟：独立仓库相对 Arch 官方存在滞后，上游紧急安全更新需等重建后才进入。
  3. AUR 供应链：AUR / AUR 衍生包存在恶意包风险（2025-06 AUR 恶意包事件）；新版 Shelly 增加 PKGBUILD 预览作为缓解。
  4. keyring / 镜像运维：常见问题为 keyring 过期、镜像不同步、磁盘空间不足导致更新中断（建议更新前预留 ≥10GB 并备份 /var/lib/pacman/local 与 /etc/pacman.conf）。
小结：打包工程质量在同类 Arch 衍生项目中属上游水平——自动化、多架构、签名、索引齐备；但"独立仓库 + 重编译"模式天然带来同步与混装两类风险。

6. Bug 风险

6.1 结构性与固有风险

  • 滚动发行固有风险：上游更新随时可能引入回归，需自备快照回滚（默认 Btrfs + 快照，但需用户安装时主动选择并实测恢复流程）。
  • 前沿特性风险：sched-ext / BORE / BMQ / 实时内核、AutoFDO / Propeller 属"尝鲜级"，稳定性与主线内核有差距。
  • 硬件门槛：不支持无 SSE4.2 的 CPU；v3/v4 仓库要求较新 CPU（v4 需 AVX-512）。

6.2 已观察到的具体问题

类别具体问题
调度器sched-ext / scx 在登录前加载时报 warning（源自 CachyOS 社区报告，scx issue #1160）；SCX 与 BMQ 内核变体不兼容

6.3 争议与需存疑的说法

  • "性能提升"的宣传口径：收益主要在低帧与 CPU 敏感场景，部分"Linux 游戏更强"结论被归因于 Proton / 驱动而非发行版；测试样本偏少。
  • 部分二手来源需谨慎：如"2026 年 1 月版本率先支持 FSR 4.0 AI 补帧"来自百科 / 聚合站，未在官方渠道一致确认。
  • 中文技术博客（CSDN 等）多为 SEO 聚合内容，技术细节可参考但不宜作权威依据。

7. 结论与建议

适合安装

  • 显卡为 AMD 或较新 NVIDIA，游戏库以 Steam 单机 + Proton 兼容网游为主。
  • 掌机用户（官方支持 ROG Ally、Steam Deck OLED/LCD、Legion Go / Go S）。
  • 想要 Arch 的滚动更新与 AUR，但不想手动装系统的"不想折腾的 Arch"用户。
  • 国内用户友好：官方 ISO 下载列表含清华 TUNA 源，可自动换源。

不建议安装

  • 主力是强反作弊网游（内核级反作弊基本无解）。
  • GTX 10 系及更老的 Pascal 卡（需 legacy 驱动，维护成本高）。
  • 完全不想折腾、且必须使用特定专业软件的用户。

落地建议（四条安全路线）

  1. 别直接抹盘，先双系统或装到第二块盘，日用一周再决定。
  2. 安装时选 Btrfs 方案，装完亲手测一次快照恢复。
  3. AUR 装包先看 PKGBUILD（Shelly 已支持预览），别盲装。
  4. 滚动更新前备份 pacman 数据库与配置、预留磁盘空间。

后续值得关注的三个信号

  1. 服务器版（Server Edition） 何时从实验性转正（2026 年 8 月已出现在 CLI 安装器中）。
  2. 掌机支持名单是否继续扩大。
  3. NVIDIA legacy 驱动支持是否继续收缩。
