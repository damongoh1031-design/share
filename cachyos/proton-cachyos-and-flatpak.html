CachyOS 深度调研 · 第十一轮

只用 proton-cachyos 能拿多少优化？Flatpak 下又损失多少？

2026-10-16  |  承接第十轮（Proton 游戏优化收益排序）

① proton-cachyos 能带走「翻译层那一半」优化，而且不需要装 CachyOS —— 官方直接发布 x86_64_v3 变体的独立 tarball，任何发行版丢进 compatibilitytools.d 即可。带不走的是内核、Mesa/glibc、CachyOS-Settings。

② Flatpak 的代价不在「沙箱开销」（可忽略），而在「图形栈被 runtime 替换」 —— Flatpak Steam 用 runtime 自带的 Mesa 与 glibc，不是宿主的。所以在 CachyOS 上用 Flatpak Steam 会丢掉 CachyOS 对 Mesa/glibc 的 v3/v4 优化；但 /dev/ntsync 可用（manifest 含 --device=all），且可以把 v3 版 proton-cachyos 放进 Flatpak 的 compat tools 目录，把翻译层优化找回来。

一、问题 ①：proton-cachyos 拿到了什么

决定性证据：官方发布 v3 变体的独立 tarball

GitHub release cachyos-11.0-20261005-slr 的资产列表（本次直接抓取 Releases API）：

资产说明
...-x86_64.tar.xz通用基线（x86-64 v1）
...-x86_64_v3.tar.xzx86-64-v3 优化构建（AVX2 等）
...-arm64.tar.xzARM64

README 明确：把 redistributable build 放进 ~/.steam/root/compatibilitytools.d/。

关键推论：不需要装 CachyOS 就能拿到 v3 优化的翻译层。官方只发 v3 变体（不发 v4）——v4 要求 AVX-512，覆盖面太窄。

收益保留度

优化项只装 proton-cachyos 后说明
翻译层（Wine / DXVK / vkd3d-proton 的 v3 优化构建）✅ 保留官方 _v3 tarball 自带
Proton-CachyOS 补丁（FSR4 / Reflex / OptiScaler / 着色器缓存 / UMU）✅ 保留都在这个包里
CachyOS 内核（BORE / EEVDF 调参 / 1000Hz / 补丁集）❌ 拿不到需装 linux-cachyos 内核
Mesa / RADV 的 v3/v4 优化构建❌ 拿不到Proton 不打包 Mesa，用宿主发行版的 Mesa
NTSync⚠️ 取决于宿主需内核 ≥ 6.14 且加载 ntsync 模块
CachyOS-Settings（sysctl / IO / ZRAM / THP / 电源档）❌ 拿不到发行版层
优化过的 glibc 等系统库❌ 拿不到宿主提供

结论：大约拿到一半——「翻译层」那一半（也正是 Proton 场景的冠军项），拿不到「系统层」那一半。

二、问题 ②：Flatpak 下损失多少

先破除一个误解：沙箱本身的开销很小

Flatpak 用 bubblewrap 命名空间隔离，不拦截系统调用（只有 seccomp 过滤器，开销极小）。所以"沙箱导致掉帧"在机制上不成立。

⚠️ 诚实标注：没有找到 Flatpak vs 原生 Steam 的公开对照基准。"沙箱开销可忽略"是机制推断，不是实测结论。

真正的代价：图形/系统栈被换成了 runtime 版本

Flatpak 应用的依赖来自 runtime（org.freedesktop.Platform），不是宿主。实测清单可见：

Mesa  org.freedesktop.Platform.GL.default  25.1.7  24.08  system

也就是说 Flatpak Steam 里的 Mesa 来自 org.freedesktop.Platform.GL.default 扩展，而不是宿主的 Mesa；glibc 同理来自 org.freedesktop.Platform。

维度Flatpak Steam 下影响
Mesa / RADV❌ runtime 版本在 CachyOS 上会丢掉 v3/v4 优化构建；滚动发行版上还可能比宿主旧
glibc❌ runtime 版本丢掉宿主的 v3/v4 优化
NVIDIA 专有驱动✅ 宿主提供GL extension 挂载宿主 nvidia 驱动 → N 卡受影响较小
内核（调度 / 内存 / NTSync 驱动）✅ 宿主内核CachyOS 内核收益保留
沙箱开销可忽略—

/dev/ntsync 在 Flatpak 下可用吗？——可用

Flatpak 对新设备类型的默认策略是：「我们允许它们通过 --device=all，否则不允许」（flatpak issue #6199，维护者原话）。而 Flatpak Steam 的 manifest 里就有 --device=all（本次实测 com.valvesoftware.Steam.yml 第 45 行）：

41:  - --filesystem=/run/udev:ro
45:  - --device=all
46:  - --allow=multiarch      # Wine/Proton 跑 32 位代码所需
47:  - --allow=devel          # ptrace，pressure-vessel 需要

→ /dev/ntsync 应当可见（前提仍是宿主内核 ≥ 6.14）。建议本地验证：

flatpak run --command=sh com.valvesoftware.Steam -c 'uname -r; ls -l /dev/ntsync'

顺带纠正一条 NTSync 的性能口径（一手、权威）

flatpak 维护者在 issue #6199 里给出了比媒体更准确的表述：

  • "ntsync is around the same speed as fsync" —— 平均帧与 fsync 同级。
  • 它带来的是 "better game/app compatibility ... and better 1% lows since it's more efficient (less CPU overhead and less RAM usage) than the hacky fsync solution."
  • "If you have a fast CPU it would typically already handle fsync without much issues. People who are very CPU-bottlenecked would probably still see a big performance improvement with ntsync though."
  • "the performance will not change as much as some people have been misled to believe based on benchmarks that compared vanilla wine (no esync/fsync hacks) vs ntsync."
  • 实测例：3600X + 5700XT 平台上，部分游戏 1% low 帧率翻了约三倍。
  • 机制：esync/fsync 完全忽略 waitstate 调用；NTSync 在内核里真正实现，"which is why CPU bound situations under Linux punished frame rates"。

一句话：翻译层优化可以"打包带走"，系统层优化不能。 Flatpak 额外削掉的是"宿主图形栈"，但换回了干净的依赖隔离。

四、可复用操作

# A) 任何发行版：装 v3 版 proton-cachyos（无需装 CachyOS）
TAG="cachyos-11.0-20261005-slr"      # 用前先查最新 tag
mkdir -p ~/.steam/root/compatibilitytools.d
curl -LO "https://github.com/CachyOS/proton-cachyos/releases/download/$TAG/proton-cachyos-11.0-20261005-slr-x86_64_v3.tar.xz"
tar -xf proton-cachyos-11.0-20261005-slr-x86_64_v3.tar.xz -C ~/.steam/root/compatibilitytools.d/
# 重启 Steam → 游戏属性 → 兼容性 → 强制使用指定兼容工具 → 选 proton-cachyos

# B) Flatpak Steam：同一份 tarball，换个目录
mkdir -p ~/.var/app/com.valvesoftware.Steam/data/Steam/compatibilitytools.d
tar -xf proton-cachyos-11.0-20261005-slr-x86_64_v3.tar.xz \
    -C ~/.var/app/com.valvesoftware.Steam/data/Steam/compatibilitytools.d/

# C) 确认沙箱里的内核与 NTSync
flatpak run --command=sh com.valvesoftware.Steam -c 'uname -r; ls -l /dev/ntsync'

# D) 想让 Flatpak 用宿主图形栈？做不到——这正是 Flatpak 的设计

五、坑与反直觉

  • "Flatpak 更慢" —— 沙箱开销可忽略；真正的代价是图形栈被换成 runtime 版本。
  • "在 CachyOS 上用 Flatpak Steam" —— 相当于自废武功：把宿主优化过的 Mesa/glibc 换成 runtime 通用版本，还要再手动装 v3 Proton 才补回翻译层。
  • "从 AUR 装 proton-cachyos 就是 CachyOS 构建" —— ❌ 自行编译时 flag 取决于你的机器与 PKGBUILD，不一定是官方 v3 构建。要 v3 就用官方 _v3 tarball。
  • v3 变体的硬件要求 —— 需要 CPU 支持 AVX2（Intel Haswell 2013+ / AMD Excavator+）。老 CPU 用 x86_64 基线版。
  • Flatpak runtime 的 Mesa 可能比宿主旧 —— 滚动发行版（CachyOS / Arch / Tumbleweed）尤其明显。
  • NTSync 不是"免费提速" —— 平均帧 ≈ fsync；收益在 1% low 与 CPU 受限场景。CPU 强 → 提升 ≈ 0。
  • N 卡在 Flatpak 下受影响较小 —— 专有驱动由宿主挂载；AMD / Intel 走 runtime Mesa，受影响较大。

六、未核实 / 存疑

  • 官方 _v3 tarball 的具体编译 flag（是否含 LTO / PGO / BOLT，还是仅 -march=x86-64-v3）：未核实，本次只确认了资产名。
  • Flatpak 沙箱内 /dev/ntsync 的实测可用性：基于 manifest 含 --device=all 的推断，未实测。
  • Flatpak vs 原生 Steam 的帧率差异：无公开对照基准；"沙箱开销可忽略"为机制推断。
  • 非 CachyOS 发行版上装 v3 Proton 的实际收益：无实测数据。
