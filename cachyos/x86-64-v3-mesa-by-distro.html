CachyOS 深度调研 · 第十二轮

除 CachyOS 外，哪些发行版提供 x86-64-v3 编译的 Mesa（AMD RADV）？

openSUSE / Ubuntu 专项核查  |  2026-10-16  |  含本次直接 HTTP 探测证据

Ubuntu 有（实验性、非官方支持、默认关闭，但实测确认归档里含 v3 编译的 Mesa，含 RADV）；openSUSE 没有（Tumbleweed 基线是 x86-64-v2，镜像里没有任何 v3 仓库）。顺带扫全：Fedora 也没有（推迟到至少 F46）；真正"基线即 v3"的是 RHEL 10 系；Gentoo 有官方 v3 二进制包；Arch 官方是 v1，需靠第三方 ALHP。

一、两个问题的直接答案

Ubuntu 25.10 / 26.10
有 ✅
归档里的独立架构组件 binary-amd64v3，实测含 mesa-vulkan-drivers（RADV）/ mesa-libgallium / libgl1-mesa-dri。
实验性、非官方支持、默认不启用。
openSUSE Tumbleweed
没有 ❌
基线是 x86-64-v2（2022 年起）。download.opensuse.org/tumbleweed/repo/ 下只有 oss / non-oss / update / debug / ports / source / factory，无任何 v3 仓库（多路径探测全 404）。

Mesa 确实在里面（问题核心）

26.10 main/binary-amd64v3（该组件共 6,446 个包）：

Package: mesa-vulkan-drivers     ← RADV（AMD Vulkan 驱动）在这里

26.10 universe/binary-amd64v3：mesa-utils / mesa-va-drivers / mesa-vdpau-drivers / mesa-opencl-icd / mesa-drm-shim

25.10 main/binary-amd64v3 同样含 mesa-vulkan-drivers / mesa-libgallium / libgl1-mesa-dri。

怎么用（两条路径）

  1. 直接用 amd64v3 ISO（推荐）：Ubuntu 26.10 的 daily ISO 自 2026-09-04 起同时发布 amd64v3 镜像。
  2. 改装：先装通用 amd64 的 ISO/包，再调整 APT 指向 binary-amd64v3 组件并升级。

官方定位（Phoronix 原文）

"Canonical hasn't officially introduced a supported solution but they have offered x86_64-v3/amd64v3 package archives for testing."

"the amd64v3 archive isn't currently enabled by default on capable systems or anything along those lines"

四、openSUSE：实测无 v3

检查项结果
Tumbleweed 指令集基线x86-64-v2（2022 年起从 v1 过渡）
download.opensuse.org/tumbleweed/repo/ 实际内容oss / non-oss / update / debug / ports / source / factory —— 无 v3 仓库
探测 repo/oss-x86_64-v3/404
探测 repo/x86_64-v3/404
探测 ports/x86_64-v3/404

结论：openSUSE Tumbleweed 想要 v3 编译的 Mesa，只能自己编译（或用 OBS 自建仓库），发行版不提供。

注意区分：openSUSE 的 v2 基线已高于 Arch / Fedora / Ubuntu 官方仓库的 v1——但它不是 v3。

五、重要校准：v3 Mesa 到底值多少？（别高估）

证据结论
Phoronix《Ubuntu 25.10 amd64v3 Benchmarks》2025-10-31标题即："Some Minor & Rare Performance Advantages For Desktop Workloads" —— 收益小且零散
Phoronix《Ubuntu 26.10 amd64v3 Packages...》2026-10-14在 AMD EPYC 上有 "some additional uplift"（服务器负载更明显）
机制RADV 的着色器编译走 LLVM，面向实际 GPU、与宿主 ISA 级别基本无关；受益的是主机侧 Mesa 代码（状态设置、命令缓冲构建、描述符管理），AVX2 能帮上的幅度有限

对游戏而言：Mesa 的「版本」≫ Mesa 的「ISA 级别」。
想提升 A 卡游戏性能，优先级应是：更新的 Mesa（mesa-git / kisak PPA / 新发行版）> 内核与固件 > v3 重编译。

六、坑与反直觉

  • 把 Ubuntu amd64v3 当正式功能 —— ❌ 实验性、不受官方支持；混装 v1/v3 包有依赖风险。
  • 以为 openSUSE 有 v3 —— ❌ 它是 v2 基线。比 v1 高，但不是 v3。
  • 以为 Fedora 有 v3 —— ❌ 提案推迟到至少 Fedora 46。
  • 把 ALHP 与 CachyOS 仓库混用 —— ❌ 两套都覆盖 core/extra，混用会打架。
  • 忽略硬件门槛 —— v3 需 Intel Haswell（2013）/ AMD Excavator 及更新；v4 需 AVX-512（消费级大多没有，这也是 CachyOS 只给 Proton 发 v3 变体的原因）。
  • 期待"换 v3 白捡帧数" —— 桌面游戏负载实测是小且零散的收益；4K / GPU 受限时归零。

七、未核实 / 存疑

  • ALHP 的确切仓库 URL：常见路径探测得 404，但 alhp.dev/ 目录列表明确显示 core-x86-64-v3/、extra-x86-64-v3/、multilib-x86-64-v3/（含 v2/v4）存在且 lastupdate 为 2026-10-16 → 仓库存在，路径以官方文档为准。
  • Void Linux 是否有 v3 仓库：未找到证据，暂记"无"。
  • openMandriva 的 znver4 优化构建：未核实。
  • Amazon Linux 2027：仅知为预览状态，包覆盖未核实。
  • Ubuntu amd64v3 的实测游戏帧率增益：Phoronix 结论是"桌面负载收益小且零散"，但没有游戏专项对照数据。
