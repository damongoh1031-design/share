skills.sh 是什么

Vercel 出品的 Agent Skills 目录与排行榜，2026-01-20 上线。自称 "The Agent Skills Directory" / "The Open Agent Skills Ecosystem"。

一条命令安装：npx skills add <owner/repo>

支持 20 个 agent（页面实测）：Claude Code、Cursor、Codex、GitHub Copilot、Windsurf、Gemini、Cline、AMP、Antigravity、OpenClaw、Droid、Goose、Kilo、Kiro CLI、Nous Research、OpenCode、Roo、Trae、VS Code、Zed。CLI 本身支持更多（README 称 "75 more"）。

最重要的一个发现：榜单被少数几个组织垄断

176 条榜单里，超过一半来自 6 个组织。所谓「skills.sh 最推荐的」很大程度上是「mattpocock 和 heygen 最推荐的」。看到高排名先看 owner。

一skills.sh 平台怎么用

1.1 三个榜单的差别

榜单指标适合
All Time8W Activity + Installs（8 周活跃 + 累计安装）判断长期价值
Trending (24h)Installs（24 小时）看这周什么在起来
Hot1H / Change（1 小时 + 增量）看此刻什么在爆
实测差异很大

All Time 前 10 全是开发/设计类；Trending 前 10 里 7 个是 heygen 的视频生成类（hyperframes-cli 32.9K、hyperframes-audio 28.4K、motion-graphics 20.6K…）；Hot 榜前列则是 limrun-bazel、ponytail、clickhouse-best-practices 这类刚起步的。

结论：只看 All Time 会漏掉正在起势的；只看 Trending 会被单一厂商刷屏。

1.2 安装方式

# 基础安装（owner/repo 简写）
npx skills add vercel-labs/agent-skills

# 指定单个 skill
npx skills add https://github.com/mattpocock/skills --skill tdd

# 装到用户目录而非项目（全局）
npx skills add mattpocock/skills -g

# 只看有哪些 skill，不装
npx skills add mattpocock/skills --list

# 不安装，直接生成 prompt 喂给 agent
npx skills use vercel-labs/agent-skills@web-design-guidelines | claude
npx skills use vercel-labs/agent-skills --skill web-design-guidelines --agent claude-code

# 指定目标 agent
npx skills add mattpocock/skills -a claude-code -a codex

支持多种来源（README 实测）：GitHub 简写 / 完整 URL / 仓库内子路径 / GitLab / Azure Repos / 任意 git URL / 本地路径 / 私有仓库（复用 Git 凭证、gh CLI 或 SSH）。

1.3 单个 skill 页面有什么

抓取详情页实测，每个 skill 页显示 6 组信息：

字段作用
Installs安装量
Repository + GitHub Stars仓库与星数（用于发现「星数低但安装量高」的推广驱动 skill）
First Seen首次收录日期（用于发现新建仓库陡增）
Security AuditsGen Agent Trust HubSocketSnyk
Summary一句话摘要
SKILL.md完整原文（装前必读）
这六组数据合起来才能判断一个 skill 值不值得装

只看安装量会被刷榜误导；只看星数会漏掉好用的新 skill；不看安全审计则可能装进有问题的东西。

三分场景推荐

3.1 元技能层 —— 先装这个

find-skills（vercel-labs/skills，3.8M，全站第一）

它做什么：让 agent 自己去发现并安装 skill。

详情页原文：

Discover and install specialized agent skills from the open ecosystem
when users need extended capabilities.

- Helps identify relevant skills by domain and task when users ask
  "how do I do X" or "find a skill for X"
- Provides `npx skills find [query]` command to search interactively
  and `npx skills add ` to install from GitHub or other sources
- Recommends skills based on install count (prefer 1K+), source
  reputation (official sources like Vercel, Anthropic), and GitHub
  stars to ensure quality
- Checks the skills.sh leaderboard first for battle-tested, popular
  options before running CLI searches

解决什么：你不用再手动逛榜单——直接问 agent「有没有做 X 的 skill」，它自己去查、去比、去装。

为什么它排第一：它是入口。装了它，后面所有 skill 的发现成本归零。

skill-creator（anthropics/skills，405.1K）

原文："Create new skills, modify and improve existing skills, and measure skill performance. Use when users want to create a skill from scratch, edit, or optimize an existing skill, run evals to test..."

解决什么：找不到合适的就自己造。这是官方出的造 skill 的 skill。

另有 obra/superpowers 的 writing-skills（含测试方法论）和 mattpocock 的 writing-for-agents / writing-great-skills，都是「怎么给 agent 写文档」的元技能。

3.2 需求对齐 / 设计阶段 —— 最被低估的一类

grill-me（mattpocock/skills，1.4M，全站第二）

详情页原文：

Relentless interviewing skill that stress-tests plans and designs
through systematic questioning.

- Conducts deep-dive questioning across all aspects of a plan, walking
  through decision trees branch-by-branch until shared understanding
  is reached
- Automatically explores the codebase to answer questions where code
  context is available, reducing redundant back-and-forth
- Designed for design reviews, architecture validation, and
  pre-implementation planning where thorough vetting prevents
  downstream issues

解决什么：AI 编程最高频的失败模式是「它做的不是你要的」。 这个 skill 强制在动手前把需求问透。

作者原文（README）：

The most common failure mode in software development is misalignment.
You think the dev knows what you want. Then you see what they've built
- and you realize it didn't understand you at all. This is just the
same in the AI age. There is a communication gap between you and the
agent. The fix for this is a grilling session.

grill-with-docs（1.2M）

比 grill-me 多了构建领域模型：边问边更新 GLOSSARY.md 和 ADR。作者的例子很有说服力：

说法
BEFORE"There's a problem when a lesson inside a section of a course is made 'real' (i.e. given a spot in the file system)"
AFTER"There's a problem with the materialization cascade"

收益（作者原文）：变量/函数/文件名用统一语言命名 → 代码库更易导航 → agent 思考更省 token。

grilling（907.9K）—— 底层原语

原文："Interview the user relentlessly about a plan, decision, or idea until every branch of the design tree is resolved. The reusable interview primitive behind grill-me, grill-with-docs, triage, wayfinder and improve-codebase-architecture."

即：grill-me 是「入口」，grilling 是「引擎」。

tdd（1.1M）—— 值得单独说

详情页原文：

Test-driven development with vertical slices, behavior-focused tests,
and incremental red-green-refactor cycles.

- Emphasizes integration-style tests that verify behavior through
  public APIs, not implementation details; tests should survive
  refactors unchanged
- Requires vertical slicing (one test → one implementation → repeat)
  instead of horizontal slicing (all tests first, then all code),
  preventing brittle, behavior-insensitive test suites
- Includes planning phase to confirm interface changes, prioritize
  behaviors to test, and design for testability before writing code

SKILL.md 原文的关键概念：

A seam is the public boundary you test at: the interface where you
observe behavior without reaching inside. Tests live at seams, never
against internals.

Test only at pre-agreed seams. Before writing any test, write down the
seams under test and confirm them with the user. No test is written at
an unconfirmed seam.

解决什么：AI 写的测试往往「测实现细节」，一重构就全红。这个 skill 强制测行为、在接缝上测。

codebase-design（792.3K）+ improve-codebase-architecture（1.1M）

codebase-design 提供词汇表：module、interface、depth、seam、adapter、leverage、locality。原文要求 "Use these terms exactly in every suggestion, and don't drift into 'component,' 'service,' 'API,' or 'boundary.'"

improve-codebase-architecture 详情页原文：

Analyze codebases for architectural friction and propose
module-deepening refactors as testability improvements.

- Explores codebases organically to surface shallow modules,
  tightly-coupled components, and untested seams rather than
  following rigid heuristics
- Applies John Ousterhout's "deep module" principle: small interfaces
  hiding large implementations for better testability and AI
  navigability
- Generates multiple radically different interface designs
  (minimalist, flexible, caller-optimized, ports & adapters) via
  parallel sub-agents, then recommends the strongest approach
- Creates GitHub issue RFCs documenting the problem space, design
  trade-offs, and refactoring rationale

作者建议：每隔几天在代码库上跑一次。自我定位很克制："It is a survey, not a rescue: on a genuinely old codebase it will find real candidates, but it won't untangle the mud for you."

解决什么：作者的诊断——"agents can radically speed up coding, they also accelerate software entropy. Codebases get more complex at an unprecedented rate."

3.4 调试与排错

diagnosing-bugs（mattpocock/skills，777.5K）

Disciplined diagnosis loop for hard bugs and performance regressions:
build a feedback loop that goes red on this bug → minimise →
hypothesise → instrument → fix → regression-test.

解决什么：难 bug 靠猜是猜不出来的。强制先建一个「能稳定复现」的反馈回路，再最小化、再假设、再插桩。

systematic-debugging（superpowers，291.8K）

原文："4-phase root cause process (includes root-cause-tracing, defense-in-depth, condition-based-waiting techniques)"

verification-before-completion（superpowers，238.3K）

原文："Ensure it's actually fixed"

解决什么：AI 最常犯的错是「声称修好了但没验证」。这个 skill 强制在宣布完成前做验证。

3.5 协作与交接

handoff（mattpocock/skills，979.1K）

详情页原文：

Summarize conversations into handoff documents for seamless
agent-to-agent transitions.

- Compacts current conversation context into a structured document
  saved to the OS temp directory
- Automatically suggests relevant skills the next agent should invoke
  based on conversation content
- Avoids duplication by referencing existing artifacts (PRDs, plans,
  ADRs, issues, commits, diffs) by path or URL rather than repeating
  their content
- Redacts sensitive data including API keys, passwords, and PII
  before handoff
- Tailors handoff focus based on user-provided arguments

SKILL.md 原文（很短，说明它很聚焦）：

Write a handoff document summarising the current conversation so a
fresh agent can continue the work. Save to the temporary directory of
the user's OS ($TMPDIR, else /tmp; %TEMP% on Windows) - not the
current workspace.

Include a "suggested skills" section in the document, naming which
skills the next agent should call the Skill tool for.

Do not duplicate content already captured in other artifacts.
Reference them by path or URL instead.

Redact any sensitive information, such as API keys, passwords, or
personally identifiable information.

解决什么：上下文窗口满了 / 要换 agent / 要开会中断时，把上下文无损压缩，而不是从头讲一遍。

triage（938.7K） ⚠️ 安全审计 Warn

详情页原文：

State machine-driven issue triage with role-based workflow management
and agent brief generation.

- Two category roles (bug, enhancement) and five state roles
  (needs-triage, needs-info, ready-for-agent, ready-for-human,
  wontfix) guide issues through a standardized workflow
- Supports querying unlabeled issues, in-progress triage, and issues
  awaiting reporter feedback
- Includes reproduction testing for bugs, grilling sessions for
  incomplete issues, and templates for triage notes and agent briefs
- Respects prior triage context, codebase ADRs, and out-of-scope

一个很好的设计细节（SKILL.md 原文）：triage 期间发的每条评论都必须以这句话开头：

> *This was generated by AI during triage.*

解决什么：issue 堆积、状态混乱。而且主动标注 AI 生成，避免误导。

3.7 前端 / UI 设计

frontend-design（anthropics/skills，985.0K）—— 排名最高的非 mattpocock 开发类 skill

Distinctive, production-grade frontend interfaces that reject generic
AI aesthetics through intentional design choices.

- Guides aesthetic direction selection (brutalist, maximalist,
  retro-futuristic, luxury, organic, etc.) before implementation
- Emphasizes typography, color theming with CSS variables, motion
  design, spatial composition, and textural details as core design
  pillars
- Generates working code (HTML/CSS/JS, React, Vue) that matches
  implementation complexity to the aesthetic vision
- Explicitly avoids overused fonts, clichéd color schemes, and
  predictable layouts that characterize generic AI-generated interfaces

SKILL.md 原文的开场设定（很能说明它的思路）：

Approach this as the design lead at a design studio known for giving
every client a distinct visual identity that is not mistaken for
anyone else's. This client has already rejected proposals that felt
cliché or templated, and is paying for a distinctive point of view.

以及一条很具体的反套路规则：

a big number with a small label, supporting stats, and a gradient
accent is the default treatment, so only use it if that's truly the
best option

解决什么：AI 生成的界面千篇一律。这个 skill 强制先定美学方向，再写代码。

web-design-guidelines（vercel-labs/agent-skills，734.2K）

README 原文："Review UI code for compliance with web interface best practices. Audits your code for 100+ rules covering accessibility, performance, and UX."

覆盖：Accessibility（aria-label、语义 HTML、键盘处理）、Focus States、Forms、Animation（prefers-reduced-motion）、Typography（弯引号、省略号、tabular-nums）、Images、Performance（虚拟化、布局抖动、preconnect）、Navigation & State（URL 反映状态、深链）、Dark Mode & Theming、Touch & Interaction、Locale & i18n（Intl.DateTimeFormat）

它和 frontend-design 是互补的

前者是「创造好看的设计」，后者是「审查是否符合规范」。两个都装不冲突。
