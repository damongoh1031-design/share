〇结论速览

六个最重要的判断，后面每一节都在展开它们。

① 2026 年扩展生态已收敛为"四层结构"，彼此不是竞品

能力层 Agent Skills 管"怎么做事"，连接层 MCP 管"能碰什么"，协作层 A2A 管"Agent 之间怎么配合"，规则层 AGENTS.md 管"在本仓库要守什么规矩"。选型的第一步是判断你缺的是哪一层。

② 两个标准在 2025 年 12 月同时被"中立化"

MCP 于 2025-12-09 随 Agentic AI Foundation（AAIF） 捐给 Linux Foundation（与 Block 的 goose、OpenAI 的 AGENTS.md 同为创始项目）；Agent Skills 于 2025-12-18 作为开放标准发布到 agentskills.io。扩展标准不再由单一厂商控制——这是 2026 年最重要的结构性变化。

③ MCP 在 2026-07-28 完成问世以来最大重构

核心从"有状态双向会话"改为无状态请求/响应：移除 initialize 握手与 Mcp-Session-Id，新增 server/discover，Roots / Sampling / Logging 正式废弃。网上绝大多数 MCP 教程仍是旧模型——按新规范实现时这是头号踩坑点。

④ 安全是这个生态当前最大的短板

已确认的 MCP 组件 RCE/SSRF 漏洞至少 7 个（多个 CVSS ≥9.0）。Invariant Labs 早在 2025-04 就公开了工具投毒这一基础攻击面，至今无生态级强制签名机制。更关键的是：Skills 与 MCP 共用同一条信任链——第三方技能以 Agent 同等权限运行，恶意 SKILL.md 即等于完全接管 Agent。

⑤ "MCP 服务器破 10 万"是营销口径

该数字出自 Linux Foundation 新闻稿，指"整个生态广泛发布的服务器"，不等于官方 Registry 的收录量（官方 Registry 2026-09 约 3 万条）。第三方目录站的 13.7 万等数字互相重复计数，不可比。

⑥ 本机环境已是一个相当完整的"扩展面"实例

实测：49 个用户级 Skills、57 个已装插件、5 个插件市场、3 个 MCP Server、13 个可用连接器。其中"调研 + 抓取"类技能占了 35%，并出现了 4 个"元技能"（审计 Agent 自身）。

一SKILL.md 规范：Agent Skills 开放标准

Anthropic 2025-10 推出，2025-12-18 发布为开放标准，规范主页 agentskills.io/specification。

核心定义（官方原文）

"Skills are folders of instructions, scripts, and resources that Claude loads dynamically to improve performance on specialized tasks."

一个 Skill = 一个文件夹：SKILL.md（元数据 + 指令）+ 可选的脚本、参考资料、模板。它把"领域流程知识"从提示词里剥离，做成可组合、可移植、按需加载的模块。

frontmatter 字段（权威：agentskills.io/specification）

字段必需约束
name必需≤64 字符。仅小写字母/数字/连字符。不得以连字符开头结尾，不得连续连字符。必须与父目录名一致
description必需≤1,024 字符。必须同时说明做什么和何时用，含具体关键词
license可选许可证名称或指向随附许可证文件
compatibility可选≤500 字符。环境要求。官方称"大多数技能不需要"
metadata可选任意 string→string 键值对，用于规范外的扩展属性
allowed-tools可选空格分隔的预授权工具列表。实验性，各实现支持度不一
⚠️ 三个必须记住的规范细节
  • 规范里没有 version 和 model 顶层字段——版本类信息放进 metadata 映射。
  • description 上限是 1,024 字符（规范），不是 200 字符——Anthropic 帮助中心文章与此冲突，且列出一个规范中不存在的 dependencies 字段。以规范为准。
  • 非法 name 示例：PDF-Processing（大写）、-pdf（连字符开头）、pdf--processing（连续连字符）。

渐进式披露：三级加载模型

这是 Agent Skills 最重要的工程机制，也是它区别于"把提示词塞进系统提示"的关键。

L1元数据
name + description
启动时对所有技能全部加载。这是唯一的常驻部分，也是唯一的触发机制——写得含糊就永远触发不了。
~100 tokens
L2指令
SKILL.md 正文
技能被激活时加载。官方要求正文保持在 500 行以内；预算单位是 tokens 不是 words。
<5,000 tokens
L3资源
scripts/ · references/ · assets/
仅在需要时按需读取。不设上限，但应拆分、单文件小而聚焦。
按需

目录结构与示例

skill-name/
├── SKILL.md          # 必需：元数据 + 指令
├── scripts/          # 可选：可执行代码（Python / Bash / JS）
├── references/       # 可选：按需加载的参考文档
├── assets/           # 可选：模板、图片、查找表
└── ...               # 其他任意文件
---
name: pdf-processing
description: Extract text and tables from PDF files, fill forms, and merge
  documents. Use when working with PDF files or when the user mentions
  forms, extraction, or PDF merging.
---

四安全风险全景

本节把"已披露确认的漏洞"与"理论攻击类别"严格分开。

MCP 攻击类别

🎯 工具投毒 已确认
恶意指令藏在工具 description 中，模型读到但用户看不到，含 Unicode 不可见字符（如 U+2063）。Invariant Labs 2025-04 公开，是该领域基础攻击面。
🪤 拉地毯 Rug Pull 已确认
Server 通过审查时工具良性，批准后静默改变描述或实现。安装时静态审查无法防护。
👥 工具遮蔽/同名冲突
恶意 Server 静默覆盖良性 Server 的同名工具，Agent 以为在调 A 实际调 B。
💉 工具输出中的提示注入 已确认
工具返回的不可信内容携带指令。对应 Simon Willison 的"致命三要素"。
🎭 混淆代理 官方规范
权限高于调用方的代理被诱骗代调用方行事（如静态 client ID 被冒用）。
🔑 Token 透传 明令禁止
Server 接受客户端 token 却不校验是否签发给本 Server，破坏下游限流/审计。
🕵️ 会话劫持 官方规范
可预测 session ID。缓解：≥128 位熵、密码学安全随机、服务端用户绑定、提权后轮换。
💻 本地 Server 沦陷 官方规范
通过 npx/uvx 运行不可信本地 Server 在开发机执行任意代码；STDIO 启动命令即信任边界。

Skills 特有风险

核心风险 —— SKILL.md 内的提示注入

Skill 是"YAML 元数据 + 自然语言指令"的文件夹，而 Agent 会忠实执行其中的指令。恶意的或被入侵的 SKILL.md 可以指示 Agent 外泄密钥、执行脚本、关闭防护——这是工具投毒在"技能内容"上的对应物。

供应链风险

Docker 的 "coding agent horror stories"（2026-05）把恶意技能与插件供应链列为头号风险：第三方技能/插件以与 Agent 本身相同的权限运行，故恶意技能 = Agent 完全沦陷。

为什么"安装前先读 SKILL.md"是推荐防御：因为技能没有成熟的审查/注册机制，且以 Agent 权限执行，社区防御只能是人工检查。但这很弱——rug pull/动态更新与混淆（Unicode 隐藏）指令可绕过静态阅读。

缓解最佳实践

👤 人在环
工具调用与安装 server/技能都需人工批准
🔒 最小权限
限定工具权限；禁止读取 ~/.aws、~/.ssh、.env
📦 沙箱化
容器 + 网络出口控制，遏制被入侵的 server/技能
✅ 白名单
只信任已知 server/技能；阻止 npx/uvx 自动执行
📌 锁版本
监控 rug pull，更新时重新审查
🏭 供应链治理
把 MCP server 当作受治理的软件供应链组件，而非随手装的插件
2026 新增 —— 企业托管授权（EMA）：MCP 扩展于 2026-07-13 升为稳定。企业可通过自家 IdP（Entra、Okta）集中控制 MCP server 访问，取代逐 server 同意提示。服务端支持：Asana、Atlassian、Canva、Figma、Granola、Linear、Supabase，Slack 进行中。

skills.md—不是标准。标准化文件名是大写 SKILL.md—
关键对比：AGENTS.md/CLAUDE.md = 常驻的行为规则（"宪法"）；SKILL.md = 按需的专项能力（"技能证书"）。二手来源概括为"AGENTS.md 管路由/选择，Skill 管执行"。
Skill vs MCP（官方口径）

"MCP connects Claude to external services and data sources. Skills provide procedural knowledge—instructions for how to complete specific tasks."

即：MCP 给工具，Skills 教怎么用这些工具。常见建议是把 MCP 当作基础设施、Agent Skills 当作应用层，叠在一起用。

七选型决策树

问题 1：你要解决的是"Agent 不知道怎么做"，还是"Agent 碰不到某个系统"？ ├─ 不知道怎么做 ────────────→ Agent Skills（SKILL.md） │ 写清流程/示例/边界，确定性步骤就捆脚本 ├─ 碰不到某个系统/数据 ─────→ MCP Server │ 本地系统走 stdio，远程走 Streamable HTTP └─ 两者都要 ───────────────────→ 叠加：MCP 提供工具，Skill 教怎么用 问题 2：你的规则是"全局"还是"本仓库"？ ├─ 全局行为约束 ───────→ 系统提示 / 自定义指令 ├─ 本仓库约定 ─────────→ AGENTS.md（跨工具）/ CLAUDE.md（Claude Code） └─ 特定任务的按需流程 ─→ Skill 问题 3：多个 Agent 要互相配合？ └──────────────────────→ A2A（Agent Card + Task 生命周期） 问题 4：去哪里找现成的？ ├─ 官方技能 ───────→ github.com/anthropics/skills ├─ 官方插件 ───────→ github.com/anthropics/claude-plugins-official ├─ 官方 MCP server → registry.modelcontextprotocol.io ├─ 三方 MCP server → PulseMCP → Smithery → Glama（数量最大需甄别） ├─ 调试 MCP server → MCP Inspector（官方） ├─ 发布 MCP server → mcp-publisher（官方） └─ 创作技能 ───────→ skill-creator 元技能 问题 5：怎么降低风险？ ① 装前读一遍 SKILL.md / 查 MCP server 来源与提交历史 ② 权限最小化（本机 gog 的 --allow-tool 白名单就是好做法） ③ 能沙箱就沙箱；能锁版本就锁版本（防 rug pull） ④ 敏感操作走人在环审批 ⑤ 别用来源不明的"技能市场"站点

八数据可信度与口径问题

三个必须记住的"口径陷阱"

陷阱 ① "MCP 服务器破 10 万" ≠ 官方 Registry 收录量

前者是 LF 新闻稿的生态口径，后者 2026-09 约 3 万条。第三方站的 13.7 万等数字存在重复计数。

陷阱 ② 技能预算单位是 tokens 不是 words

官方要求 SKILL.md 正文 <5,000 tokens / <500 行。

陷阱 ③ description 长度上限是 1,024 字符（规范），不是 200 字符（帮助中心）

以 agentskills.io 规范为准。
