### 脚本能识别真封禁吗？能。

`--self-test` 验证了 `_classify_probe` 的分类正确性：

```
✓ 200 + 40KB → ok          ✓ 401 → blocked（真封禁）
✓ 200 + 0B   → soft        ✓ 403 → blocked（真封禁）
✓ 200 + 2999B → soft（边界）✓ 451 → blocked（真封禁）
✓ 200 + 3000B → ok（边界）  ✓ 200 但含挑战指纹 → blocked
✓ 404 → notfound（页码越界，与限流无关）
```

**所以真被封会明确报出来。现在没报 ⇒ 确实没被封。**

### 副作用与已做的处置

### ⚠️ 两个必须知道的"混淆"风险（不是 bug，是设计结果）

**风险 1：座机混在同一个 CSV 里**

| 号段 | 条数 | 类型 |
|---|---|---|
| `01X`（手机） | **599** | 手机 |
| `03`（吉隆坡） | 1382 | 座机 |
| `04`（槟城） | 307 | 座机 |
| `08` / `07` / `06` / `05` / `09` | 275 / 274 / 180 / 164 / 155 | 座机 |
| 其他 | 75 | 混合 |

**手机号只占 599 / 3421 = 17.5%**，其余 82.5% 是座机。
这是 `--phone-scope all`（你要的全量 dump）的**预期结果**。
→ **下游若只想群发手机号，必须自己过滤**：`phone GLOB '01[0-9]*' AND length(phone) IN (10,11)`

**风险 2：`display` 列是原始文本，`phone` 列才是归一化的**

```
display = "+60 3-2169 7440"     ← 原样保留，格式不统一
phone   = "0321697440"          ← 归一化，可直接用
```
→ 下游**用 `phone`，别用 `display`**。
