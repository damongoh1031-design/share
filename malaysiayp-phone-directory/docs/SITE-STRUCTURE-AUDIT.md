## 三、缺陷性质：源站应用层确定性缺陷（**不是页面无内容**）

### 3.1 两种缺陷形态

| 形态 | 响应头 | 表现 | 占比 |
|---|---|---|---|
| **A. 完全空** | `Transfer-Encoding: chunked`，**无 Content-Length** | HTTP 200，**0 字节** | 大多数 |
| **B. 硬截断** | `Content-Length: **32768**` | HTML 渲染到一半**被切断** | 少数 |

正常页：`Content-Length: 36510 ~ 37369`

### 3.2 决定性证据：`page/3` 的 HTML 分析

```
长度: 32758 字符
</html> 结尾?  False          ← 被硬截断
row-item 出现次数: 20         ← 但确实渲染了 20 条记录
页内分页链接: /page/2/ /page/4/ /page/5/ /page/275/
最后 120 字符: '...\"className\":\"row-name\",\"children\":[[\"$\",\"a\",null,{\"href\":\"/item/abdul-h'
```

**三个关键推论：**

1. **页面有内容** —— 20 条记录已经渲染出来了，HTML 结构正常（`row-item`、分页导航齐全）
2. **不是「页码越界」** —— 页内自带 `/page/275/` 链接，说明站点认为这页有效
3. **是输出被切断** —— 停在 `/item/abdul-h` 中间，`</html>` 都没有

### 3.3 `32768` 这个数字很说明问题

**32768 = 32 KiB = 2¹⁵** —— 一个精确的缓冲区边界。

而正常页是 36510–37369 字节（> 32 KiB）。所以：

> 源站的渲染输出**本该**是 36.5 KB 左右，但当渲染管线中途失败时，
> 输出会**恰好停在 32 KiB 的 flush 边界**（形态 B），或**完全无输出**（形态 A）。

这是**应用层流式渲染的失败特征**，不是网络层问题。

### 3.4 五种假设全部证伪

| 假设 | 实验 | 结果 |
|---|---|---|
| 限流 | `--delay` 从 8.0s 降到 3.0s（提速 2.7×） | ❌ 错误率**无变化**，健康率仍 1.0 |
| 封禁 | 检查 403 / 429 / 验证页 / 挑战指纹 | ❌ **0 条** |
| CDN 缓存坏响应 | 加随机 `?cb=6739974` / `?cb=3946021` | ❌ 仍 0 字节 |
| 强制回源 | 请求头 `Cache-Control: no-cache, no-store` + `Pragma: no-cache` | ❌ 仍 0 字节 |
| 代理 / 传输层 | `--noproxy` 直连；`Accept-Encoding: identity` | ❌ 仍 0 字节 |

**补充排除**：
- **不是负载均衡随机**：并发 3 个相同请求，结果**完全一致**（全 0 字节）
- **不是压缩问题**：`Accept-Encoding: gzip` 得到压缩后 5943 字节，**解压后仍是 32768** ⇒ 截断在源站
- **不是 RSC 路径问题**：加 `RSC: 1` / `?_rsc=<rand>` / `Next-Router-Prefetch: 1` /
  `Accept: text/x-component` **全部仍为 0 字节**

### 3.5 但缺陷**不是永久的** —— 这是最重要的发现

抽样复核 35 页时发现：

| 页 | DB 记录 | 实测 | 结论 |
|---|---|---|---|
| `page/213` | **成功，rows=20** | **0 字节** | ⚠️ **由好变坏** |
| 其余 14 个 done 页 | 成功 | 36510–37369 字节 ✔ | 一致 |
| 20 个失败页 | 0 字节 | 0 字节 ✔ | 一致 |

**`page/213` 从「成功」变成了「失败」，证明状态会随时间变化。**

⇒ 这意味着缺陷页**可能自愈**，也可能继续恶化。
⇒ **所以不能永久删除，只能延期重试。**

## 五、已执行的剔除（可逆「软剔除」）

### 5.1 为什么是「延期」而不是「删除」

| 方案 | 优点 | 缺点 | 采用 |
|---|---|---|---|
| 永久删除（标 `failed`） | 立刻收敛，拿到 rc=6 | **丢失自愈机会**（page/213 证明会变） | ❌ |
| **延期重试**（推后 `not_before`） | 保留自愈机会；可逆；不破坏任何校验语义 | 不立刻收敛 | ✅ |

### 5.2 执行结果

```
待处置（pending 且有错误）: 340 页
  agricultural                            220 页  (0B 216 / 截断 4)
  amusement-and-recreation-services        66 页  (0B 65 / 其他 1)
  apparel-textiles-clothing-accessories    42 页  (0B 42)
  apartment / accounting / advertising /
  air-conditioning-* / aluminum-*          12 页  (零散)

已延期 340 页至 2026-10-08 20:45  （+6 小时）
验证：仍在当前队列的缺陷页 = 0        ✅
验证：当前可抓取页数 = 1775           ✅
```

### 5.3 技术实现（为什么安全）

只改 `pages.not_before` 一个字段，**不动** `status` / `attempts` / `error` / `rows`：

- `_full_coverage()` 不看 `not_before` → **不影响完成判定语义**
- `_full_verify_db()` 只校验 `status='done'` 的页 → **不受影响**
- 采集脚本的选页条件 `not_before<=?` → **自然跳过**这些页

### 5.4 关键设计：只延期「已到期」的页

```sql
UPDATE pages SET not_before = :now_plus_6h
WHERE status='pending' AND error<>'' AND not_before <= :now
```

**为什么要加 `not_before <= now`**：否则定时执行会把已延期的页**重复推后**，
让它们永远回不来。加上这个条件后：
- 从未延期的、已到期的 → 延期 6 小时
- 已延期到未来的 → **不动**

已实测验证：第二次执行输出「**已延期 0 页**」✅

### 5.5 延期时长为什么是 6 小时

| 依据 | 值 |
|---|---|
| 站点 CDN 缓存期 `s-maxage` | 86400s = 24h |
| 我们的复检周期 | 6h（一天 4 次） |
| 效果 | 无效请求减少约 6 倍（脚本默认退避上限是 1h），同时保留一天 4 次自愈捕捉机会 |
| 30 次重试预算对应窗口 | 30 × 6h = **7.5 天** |

## 七、结论

| 你的问题 | 答案 |
|---|---|
| 是网站的结构问题？ | **不是。** 站点结构自洽：275 页 / 5493 条，三源互证，`274×20+13=5493` 分毫不差 |
| 是网站的页面没有内容？ | **不是。** `page/3` 渲染了 20 条完整记录、含分页导航、含指向 `/page/275/` 的链接 —— **有内容，只是输出被切断** |
| 真实原因 | **源站 Next.js 应用层的确定性渲染缺陷**：形态 A（chunked + 0 字节）或形态 B（截断在 32768 = 32 KiB 缓冲边界）。五种外部假设全部证伪 |
| 已剔除？ | ✅ **340 页已延期 6 小时**（可逆），当前可抓取页 1775 |

### 未验证 / 待观察

1. ⏳ **6 小时后这 340 页能否自愈**（`page/213` 的存在说明有可能）。守护会自动复检。
2. ⏳ **缺陷是否在扩散**（26 分钟 +80 页）。若持续扩散，需人工评估是否暂停。
3. ⏳ **根因**（我的推断，未验证）：Next.js App Router 的流式渲染在输出超过 32 KiB 时
   遇到异常/背压，导致 flush 中断或整体失败。**这属于源站代码问题，我们无法修复。**

### 若 24 小时后仍无自愈，可做的四件事

1. **接受当前交付**（全量 CSV 分片 + `DEFECT-PAGES.json` 缺口清单）
2. **硬剔除**：把 340 页标为 `failed`，任务立刻收敛到 `rc=6`（我可以用一条命令执行）
3. **更换出口 IP**（换 CDN 边缘节点）—— 但直连测试已排除网络因素，**预计无效**
4. **与站点方确认**：告知其 `/cat/<slug>/page/N/` 在输出 > 32 KiB 时被截断

**不建议**：把 `--page-attempts` 调大（退避已封顶 3600s，只是拉长空转）。
